## 1. Find the Index of the First Occurrence in a String 🟢

**출처:** [LeetCode #28](https://leetcode.com/problems/find-the-index-of-the-first-occurrence-in-a-string/)

두 문자열 `haystack`과 `needle`이 주어진다. `haystack` 안에서 `needle`이 **처음 등장하는 인덱스**를 반환하라. 등장하지 않으면 `-1`을 반환한다.

**예시:**
- `haystack = "sadbutsad"`, `needle = "sad"` → `0` (0과 6에서 등장하지만 **처음**은 0)
- `haystack = "leetcode"`, `needle = "leeto"` → `-1`

**제약:** `1 <= haystack.length, needle.length <= 10^4`, 둘 다 영소문자로만 구성.

**시그니처 (LeetCode):**
```python
class Solution:
    def strStr(self, haystack: str, needle: str) -> int: ...
```

> [!tip]- 힌트 1 (먼저 한 줄로 통과시켜라)
> `return haystack.find(needle)`. **끝이다.** 이건 편법이 아니라 파이썬에서의 정답이다.
> CPython의 `find`는 C로 구현되어 있고, 3.10부터 긴 패턴에 **Two-Way 알고리즘**을 써서 **최악에도 `O(N+M)`** 을 보장한다.
>
> **그러나 이 문제의 학습 목표는 KMP를 손으로 짜 보는 것**이다. 먼저 한 줄로 통과시켜 **정답 기준선을 확보**하고, 그다음 KMP를 구현해 **무작위 입력으로 교차 검증**하라.

> [!tip]- 힌트 2 (나이브부터 정확히 이해하라)
> ```python
> for i in range(len(haystack) - len(needle) + 1):
>     if haystack[i:i+len(needle)] == needle:
>         return i
> return -1
> ```
> `N = M = 10^4`이면 최악 `10^8` — **파이썬에서는 위험**하다. 특히 `"aaaa...a"`에서 `"aaa...ab"`를 찾는 입력이 정확히 그 최악이다.
> **왜 느린지**를 한 문장으로 말할 수 있어야 한다: **"실패할 때마다 이미 확인한 정보를 전부 버리고 처음부터 다시 센다."**

> [!tip]- 힌트 3 (KMP — `pi` 배열부터)
> ```python
> def build_pi(p):
>     pi = [0] * len(p)
>     k = 0
>     for i in range(1, len(p)):
>         while k > 0 and p[i] != p[k]:
>             k = pi[k-1]          # 실패 링크를 타고 후퇴
>         if p[i] == p[k]:
>             k += 1
>         pi[i] = k
>     return pi
> ```
> `pi[i]` = `p[0..i]`에서 **접두사이면서 접미사인 최장 진부분문자열의 길이**.
> `build_pi("ababaca")` → `[0,0,1,2,3,0,1]`을 **손으로 먼저 채워 보고** 코드와 대조하라.

> [!tip]- 힌트 4 (탐색 — 불변식 하나만 지켜라)
> ```python
> j = 0
> for i in range(len(haystack)):     # i 는 절대 되돌아가지 않는다
>     while j > 0 and haystack[i] != needle[j]:
>         j = pi[j-1]                # 패턴만 후퇴
>     if haystack[i] == needle[j]:
>         j += 1
>     if j == len(needle):
>         return i - len(needle) + 1
> return -1
> ```
> **불변식: `i`는 단조 증가한다.** 이것이 `O(N)` 보장의 전부다. `i`를 되돌리는 순간 그건 나이브다.

> [!tip]- 힌트 5 (실측해 보라)
> `haystack = "a"*100000 + "b"`, `needle = "a"*50 + "b"`로 **파이썬 KMP와 `find`의 시간을 재라.**
> 복잡도가 **둘 다 `O(N+M)`인데도 수백 배** 차이가 난다. **"복잡도가 같으면 언어 상수가 승부를 가른다"** 는 것을 몸으로 아는 것이 이 문제의 진짜 소득이다.

> [!warning]- 흔한 실수
> - **`i`를 되돌리기.** `while` 안에서 `i -= 1` 같은 걸 하면 KMP가 아니다.
> - **`j = pi[j-1]`을 `j = 0`으로 바꾸기.** 첫 매치만 찾는 이 문제에서는 티가 안 나지만, **모든 매치를 찾을 때 겹치는 매치를 놓친다.**
> - **`pi[0]`을 계산하려 들기.** `i=0`은 진부분문자열이 없으므로 항상 `0`이다. `range(1, m)`으로 시작하라.
> - **빈 패턴 처리.** 제약상 `needle.length >= 1`이라 이 문제에선 안 걸리지만, 범용 함수로 만들 거면 `m == 0 → return 0`을 넣어라.

**복잡도 목표:** KMP `O(N + M)` 시간, `O(M)` 공간.

## 2. Repeated DNA Sequences 🟢

**출처:** [LeetCode #187](https://leetcode.com/problems/repeated-dna-sequences/)

DNA 서열은 `'A'`, `'C'`, `'G'`, `'T'` 네 문자로 이루어진 문자열이다. 문자열 `s`가 주어질 때, **길이가 정확히 10인 부분 문자열 중 두 번 이상 등장하는 것**을 모두 반환하라. 순서는 상관없다.

**예시:**
- `s = "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT"` → `["AAAAACCCCC","CCCCCAAAAA"]`
- `s = "AAAAAAAAAAAAA"` → `["AAAAAAAAAA"]`

**제약:** `1 <= s.length <= 10^5`, `s[i]`는 `'A'`, `'C'`, `'G'`, `'T'` 중 하나.

**시그니처 (LeetCode):**
```python
class Solution:
    def findRepeatedDnaSequences(self, s: str) -> List[str]: ...
```

> [!tip]- 힌트 1 (가장 단순한 답이 이미 통과한다)
> 길이가 **10으로 고정**이다. 슬라이싱 비용이 상수(10글자)이므로 전체가 `O(n)`이다.
> ```python
> seen, res = set(), set()
> for i in range(len(s) - 9):
>     sub = s[i:i+10]
>     if sub in seen:
>         res.add(sub)
>     seen.add(sub)
> return list(res)
> ```
> **`n <= 10^5`에서 이걸로 통과한다.** 먼저 이걸 쓰고, 그다음 롤링 해시를 연습하라.
>
> **그렇다면 왜 롤링 해시를 배우는가:** 길이가 10이 아니라 **`10^4`이거나 가변**이면 이 방법은 즉시 `O(n·L)`로 터진다. 이 문제는 **두 방법을 나란히 구현해 비교하기 좋은 연습대**다.

> [!tip]- 힌트 2 (2비트 인코딩 — 오늘의 비트 연습)
> 문자가 **4종류뿐**이다. 각 문자를 **2비트**로 인코딩하면 길이 10짜리 부분 문자열이 **정확히 20비트 정수 하나**가 된다.
> ```
> A -> 00,  C -> 01,  G -> 10,  T -> 11
>
> "AAAAACCCCC" -> 00 00 00 00 00 01 01 01 01 01  (20비트)
> ```
> `2^20 = 1,048,576`이므로 **정수 하나가 부분 문자열을 완벽하게 대표**한다 — **충돌이 아예 없는 완전 해시**다. [[day-41-bitmask/concept|Day 41 비트마스킹]]의 직접 응용이다.

> [!tip]- 힌트 3 (롤링 갱신)
> ```python
> MASK = (1 << 20) - 1              # 하위 20비트만 남기는 마스크 (괄호 필수!)
> code = {'A':0, 'C':1, 'G':2, 'T':3}
>
> h = 0
> for i, c in enumerate(s):
>     h = ((h << 2) | code[c]) & MASK     # 2비트 밀어넣고 20비트로 자르기
>     if i >= 9:
>         # 이 시점의 h 가 s[i-9:i+1] 을 대표한다
>         ...
> ```
> **`& MASK`가 "맨 앞 글자를 빼는" 역할**을 한다 — 곱셈·나눗셈 없이 시프트와 AND만으로 롤링이 끝난다. 이것이 알파벳이 작을 때의 최적 형태다.

> [!tip]- 힌트 4 (일반 다항식 해시로도 해 보라)
> ```
> h_next = (h - s[i]·B^9) · B + s[i+10]      (mod p)
> ```
> 2비트 인코딩은 이 문제에만 통하는 특수해이고, **다항식 롤링 해시는 어떤 알파벳·어떤 길이에도 통하는 일반해**다. #1044에서 필요한 것은 후자이므로 여기서 손에 익혀 두라.
> 단, **다항식 해시는 충돌 가능성이 있으므로** `seen`에 해시만 넣지 말고 **실제 문자열도 확인**하거나 `dict[해시] = 문자열`로 검증하라.

> [!warning]- 흔한 실수
> - **윈도우 개수 계산.** 길이 10짜리 윈도우는 `n - 10 + 1`개다. `range(len(s) - 10)`으로 쓰면 **마지막 윈도우를 놓친다**. `range(len(s) - 9)`가 맞다.
> - **결과에 중복이 들어가기.** 세 번 이상 등장하는 서열이 여러 번 담기지 않도록 `res`는 `set`으로 관리하라.
> - **`& MASK`를 빼먹기.** 안 자르면 정수가 계속 커져서 서로 다른 길이의 서열이 섞인다.
> - **`(1 << 20) - 1`의 괄호.** `1 << 20 - 1`은 `1 << 19`다([[day-41-bitmask/concept|Day 41]]의 그 함정).

**복잡도 목표:** `O(n)` 시간, `O(n)` 공간.

## 3. Repeated Substring Pattern 🟡

**출처:** [LeetCode #459](https://leetcode.com/problems/repeated-substring-pattern/)

문자열 `s`가 주어진다. **`s`의 어떤 부분 문자열을 두 번 이상 이어 붙여 `s`를 만들 수 있는지** 판정하라.

**예시:**
- `s = "abab"` → `true` (`"ab"` × 2)
- `s = "aba"` → `false`
- `s = "abcabcabcabc"` → `true` (`"abc"` × 4, 또는 `"abcabc"` × 2)

**제약:** `1 <= s.length <= 10^4`, 영소문자로만 구성.

**시그니처 (LeetCode):**
```python
class Solution:
    def repeatedSubstringPattern(self, s: str) -> bool: ...
```

> [!tip]- 힌트 1 (약수만 확인하면 된다 — 가장 직관적인 해법)
> 반복 단위의 길이 `k`는 반드시 **`n`의 약수**여야 한다(딱 떨어져야 하므로). 그리고 `k < n`이어야 한다("두 번 이상").
> ```python
> n = len(s)
> for k in range(1, n // 2 + 1):
>     if n % k == 0 and s[:k] * (n // k) == s:
>         return True
> return False
> ```
> `n <= 10^4`이면 약수 개수가 많아야 수십 개이고 비교가 `O(n)`이라 **여유롭게 통과**한다. **먼저 이걸로 통과시켜 정답 기준선을 만들어라.**

> [!tip]- 힌트 2 (오늘의 핵심 — `pi` 배열 한 줄)
> **정리: 길이 `n`인 문자열의 최소 주기는 `n - pi[n-1]`이다.**
> ```
> s = "abcabcabc"  (n=9)
> pi[8] = 6        ("abcabc" 가 접두사이자 접미사)
> 최소 주기 = 9 - 6 = 3
> ```
> 왜 그런가: `pi[n-1] = L`이면 앞 `L`글자와 뒤 `L`글자가 같다는 뜻이고, **그 겹침이 `n-L`만큼의 "밀림"을 만든다** — 그것이 곧 주기다.
> ```python
> n = len(s)
> pi = build_pi(s)
> p = n - pi[n-1]
> return pi[n-1] > 0 and n % p == 0
> ```
> **`O(n)`.** 이 세 줄이 오늘 배운 것의 정수다.

> [!tip]- 힌트 3 (`n % p == 0`이 왜 필수인가)
> ```
> s = "abcabca"  (n=7)
> pi[6] = 4  ->  주기 p = 3
> 그런데 7 % 3 != 0  ->  마지막 조각이 잘린다 ("abc","abc","a")
> 따라서 "반복으로 정확히 구성"된 것이 아니다  ->  False
> ```
> **최소 주기가 존재하는 것과, 그 주기가 전체를 딱 나누는 것은 다른 이야기**다. `n % p == 0` 검사를 빼먹는 것이 **이 문제 최다 오답**이다.
>
> `pi[n-1] > 0` 조건도 필요하다. `"abcd"`는 `pi[3] = 0`이라 `p = 4 = n`이 되고, `n % n == 0`이라 이 검사만으로는 통과해 버린다 — **`p < n`(= `pi[n-1] > 0`)** 을 반드시 함께 확인하라.

> [!tip]- 힌트 4 (유명한 세 줄 트릭 — 검산용)
> ```python
> return (s + s)[1:-1].find(s) != -1
> ```
> **왜 되는가:** `s`가 `t`를 `k(≥2)`번 반복한 것이면, `s+s`는 `t`를 `2k`번 반복한 것이다. 여기서 `t` 길이만큼 밀린 위치에도 `s`가 나타난다.
> **양 끝을 한 글자씩 자르는 이유:** 자르지 않으면 위치 `0`과 위치 `n`에서 **자명한 매치**가 항상 발견되어 아무 문자열이나 `True`가 된다.
> **아름답지만 면접에서 위험하다** — 왜 되는지 설명하지 못하면 감점이다. `pi` 해법을 주력으로, 이건 **교차 검증용**으로 쓰라.

> [!warning]- 흔한 실수
> - **`n % p == 0` 검사 누락** → `"abcabca"`에서 틀린다.
> - **`p < n` 검사 누락** → `"abcd"`, `"a"` 같은 비반복 문자열에서 틀린다.
> - **`n = 1`** 이면 항상 `False`다(자기 자신 한 번은 "두 번 이상"이 아니다).
> - **약수 루프 범위.** `k`는 `n // 2`까지만 보면 된다(그보다 크면 두 번을 못 채운다).
> - **세 줄 트릭에서 `[1:-1]`을 빼먹기** → 모든 입력에 `True`가 나온다.

**복잡도 목표:** `pi` 해법 `O(n)` 시간·공간. 약수 해법도 제약 내에서는 충분.

## 4. [3차] 방금그곡 ⚫ (2018 카카오 블라인드 3차)

**출처:** [프로그래머스 #17683](https://school.programmers.co.kr/learn/courses/30/lessons/17683)

라디오에서 나온 곡을 찾는 서비스를 구현한다. 기억한 멜로디 `m`과 방송된 곡 정보 목록 `musicinfos`가 주어질 때, **조건에 맞는 곡의 제목**을 반환하라.

- 음은 **12개**: `C`, `C#`, `D`, `D#`, `E`, `F`, `F#`, `G`, `G#`, `A`, `A#`, `B`. **1분에 한 음**씩 재생된다.
- `musicinfos`의 각 원소는 `"시작시각,종료시각,곡명,악보"` 형식이다(시각은 `HH:MM`).
- 악보는 **재생 시간만큼 반복**되며, 재생 시간이 악보 길이보다 짧으면 **중간에 잘린다**.
- 조건을 만족하는 곡이 여러 개면 **재생 시간이 가장 긴 곡**, 그것도 같으면 **먼저 입력된 곡**을 반환한다.
- 없으면 `"(None)"` 을 반환한다.

**예시:**

| m | musicinfos | 답 |
|---|---|---|
| `"ABCDEFG"` | `["12:00,12:14,HELLO,CDEFGAB", "13:00,13:05,WORLD,ABCDEF"]` | `"HELLO"` |
| `"CC#BCC#BCC#BCC#B"` | `["03:00,03:30,FOO,CC#B", "04:00,04:08,BAR,CC#BCC#B"]` | `"FOO"` |
| `"ABC"` | `["12:00,12:14,HELLO,C#DEFGAB", "13:00,13:05,WORLD,ABCDEF"]` | `"WORLD"` |

**시그니처 (프로그래머스):**
```python
def solution(m, musicinfos):
    return answer
```

> [!tip]- 힌트 1 (이 문제의 진짜 함정 — 매칭이 아니라 정규화)
> **`C#`은 두 글자지만 "음 하나"다.** 문자열로 그냥 비교하면 재앙이 일어난다.
> ```
> 세 번째 예시를 보라.
>   악보 "C#DEFGAB",  멜로디 "ABC"
>
>   정규화 없이 문자열로 보면:
>     악보를 이어 붙인 "C#DEFGABC#DEFGAB..." 안에 "ABC" 가 들어 있다!
>     ("...GAB" + "C#..." 의 'C' 에 걸린다)
>     -> HELLO 를 답으로 내놓는 오답이 나온다
>
>   정답은 WORLD 다. 'C#' 의 'C' 는 'C' 가 아니다.
> ```
> **해결: `C#` 같은 샾 음을 한 글자로 치환한다.**
> ```python
> def norm(x):
>     for a, b in [('C#','c'), ('D#','d'), ('F#','f'), ('G#','g'), ('A#','a')]:
>         x = x.replace(a, b)
>     return x
> ```
> 소문자는 원래 음 이름에 없으므로 **충돌하지 않는다.** 이제 **한 글자 = 한 음 = 1분**이 되어 길이 계산도 정확해진다.
>
> **"매칭 전에 표현을 정규화하라"** — 이것이 이 기출의 교훈이다.

> [!tip]- 힌트 2 (재생 시간 계산)
> ```python
> def minutes(t):                        # "12:34" -> 754
>     h, mm = t.split(':')
>     return int(h) * 60 + int(mm)
>
> play = minutes(end) - minutes(start)
> ```
> 문제 예시상 종료가 시작보다 앞서는 경우는 다루지 않아도 된다. 그래도 방어적으로 짜고 싶다면 음수일 때 `+ 24*60`을 더하는 처리를 넣어 두라.

> [!tip]- 힌트 3 (악보를 재생 시간만큼 펼치기)
> 정규화된 악보 `sheet`(길이 `L`)를 `play`분만큼 반복·절단한다.
> ```python
> played = (sheet * (play // L + 1))[:play]
> ```
> **`+1`이 중요하다.** `play // L`만 하면 `play`가 `L`의 배수가 아닐 때 모자란다. 넉넉히 만들고 `[:play]`로 자르는 것이 안전하다.
>
> 파이썬답게 쓰면 이 한 줄로 "반복되며, 짧으면 잘린다"는 조건이 전부 해결된다.

> [!tip]- 힌트 4 (매칭과 최적 곡 선택)
> ```python
> if norm(m) in played:                  # 정규화한 멜로디로 검사
>     후보에 (play, 입력순서, 제목) 추가
> ```
> 선택 규칙은 **① 재생 시간 최대 → ② 먼저 입력된 것**이다.
> 정렬을 쓴다면 `sorted(cands, key=lambda x: (-x[0], x[1]))[0]`이고, **정렬 없이 한 번의 순회로도 된다**:
> ```python
> best_title, best_play = "(None)", -1
> for idx, info in enumerate(musicinfos):
>     if 매칭:
>         if play > best_play:           # 부등호가 > 여야 한다!
>             best_title, best_play = title, play
> ```
> **`>=`가 아니라 `>`** 를 써야 "같으면 먼저 입력된 것"이 유지된다. 이 부등호 하나가 정답을 가른다.

> [!tip]- 힌트 5 (KMP를 쓸 자리인가?)
> **아니다 — 그리고 그걸 판단하는 것도 학습이다.** 곡의 길이와 개수가 작아 `in` 연산으로 충분하다.
> 이 문제가 오늘 배치된 이유는 **"실전 문자열 매칭 문제의 난이도는 알고리즘이 아니라 전처리·경계 조건에 있다"** 는 것을 보여주기 위해서다. 카카오 기출이 특히 그렇다.

> [!warning]- 흔한 실수
> - **`C#` 정규화 누락** → `"C"` 검색이 `"C#"`의 앞 글자에 걸려 오답. **이 문제 최다 오답이다.**
> - **멜로디 `m`은 정규화하고 악보는 안 하기(또는 반대).** **양쪽 모두** 같은 규칙으로 정규화해야 한다.
> - **`play` 분 절단 누락** → 악보를 통째로 반복해 놓고 검사하면 실제로 재생되지 않은 부분까지 매칭된다.
> - **동점 처리에서 `>=` 사용** → 나중에 입력된 곡이 선택되어 틀린다.
> - **후보가 없을 때 `"(None)"` 반환 누락.** 문자열 그대로, 괄호 포함이다.
> - **곡명에 쉼표가 없다고 가정.** `split(',')` 결과가 정확히 4조각이라고 믿어도 되는지 확인하라(이 문제는 안전하다).

**복잡도 목표:** 곡 개수 `K`, 최대 재생 시간 `T`에 대해 `O(K · T)`. 제약 내에서 충분히 빠르다.

## 5. Shortest Palindrome 🔴

**출처:** [LeetCode #214](https://leetcode.com/problems/shortest-palindrome/)

문자열 `s`가 주어진다. **`s`의 앞에만 문자를 추가**해서 팰린드롬을 만들 수 있다. 이렇게 만들 수 있는 **가장 짧은 팰린드롬**을 반환하라.

**예시:**
- `s = "aacecaaa"` → `"aaacecaaa"`
- `s = "abcd"` → `"dcbabcd"`

**제약:** `0 <= s.length <= 5 * 10^4`, 영소문자로만 구성.

**시그니처 (LeetCode):**
```python
class Solution:
    def shortestPalindrome(self, s: str) -> str: ...
```

> [!tip]- 힌트 1 (문제를 다시 쓰기 — 이게 절반이다)
> "앞에 최소한의 문자를 붙여 팰린드롬 만들기"를 뒤집어 보자.
>
> 앞에 `k`글자를 붙인다는 것은, **`s`의 앞쪽 `n-k`글자가 이미 팰린드롬**이라는 뜻이다(그래야 붙인 `k`글자와 뒤쪽 `k`글자가 대칭을 이룬다).
> ```
> s = "aacecaaa"
>      [aacecaa]a        <- 앞 7글자가 팰린드롬
>      남는 것: "a"  ->  뒤집어서 앞에 붙인다
>      답: "a" + "aacecaaa" = "aaacecaaa"
> ```
> **따라서 문제는 "`s`의 가장 긴 팰린드롬 접두사(palindromic prefix)를 찾아라"로 바뀐다.** 그 길이를 `L`이라 하면 답은 `reverse(s[L:]) + s`다.

> [!tip]- 힌트 2 (나이브 해법을 먼저)
> ```python
> for L in range(len(s), 0, -1):
>     if s[:L] == s[:L][::-1]:
>         return s[L:][::-1] + s
> ```
> `O(n^2)`다. `n = 5·10^4`이면 **TLE**다. 하지만 **작은 입력에서 최적 해법을 검증하는 기준선**으로 반드시 만들어 두라.

> [!tip]- 힌트 3 (오늘의 트릭 — `s + '#' + rev(s)`)
> **핵심 관찰:**
> ```
> "s 의 가장 긴 팰린드롬 접두사"
>   = "s 의 접두사" 이면서 동시에 "reverse(s) 의 접미사" 인 최장 문자열
> ```
> 왜? 팰린드롬 접두사 `P`는 뒤집어도 자기 자신이므로, `reverse(s)`의 **끝부분**에 그대로 나타난다.
>
> 그런데 **"접두사이면서 접미사인 최장 길이"** 가 바로 `pi` 배열이 계산하는 값이다!
> ```python
> t = s + '#' + s[::-1]
> L = build_pi(t)[-1]          # 가장 긴 팰린드롬 접두사의 길이
> return s[L:][::-1] + s
> ```
> **`O(n)`.** 이 문제의 정수다.

> [!tip]- 힌트 4 (`#`을 반드시 넣어라)
> 구분자가 없으면 매치가 **두 문자열의 경계를 넘어간다**.
> ```
> s = "aaa" 일 때
>   구분자 없이:  "aaa" + "aaa" = "aaaaaa",  pi[-1] = 5
>                 -> 5 > 3 = len(s).  말이 안 되는 값이다.
>   구분자 있게:  "aaa#aaa",  pi[-1] = 3.  정확하다.
> ```
> 구분자는 **입력에 절대 나타나지 않는 문자**여야 한다. 제약이 "영소문자만"이므로 `'#'`, `'\x00'`, `'1'` 등 아무거나 괜찮다.
>
> 방어적으로 `L = min(L, len(s))`를 추가하는 코드도 있지만, **구분자를 넣는 것이 정석**이다.

> [!tip]- 힌트 5 (검증)
> - `s = "aacecaaa"` → `t = "aacecaaa#aaacecaa"` → `pi[-1] = 7` → `s[7:] = "a"` → `"a" + s` = `"aaacecaaa"`
> - `s = "abcd"` → `pi[-1] = 1` (`"a"`만 팰린드롬) → `s[1:][::-1] = "dcb"` → `"dcbabcd"`
> - `s = ""` → 빈 문자열 반환. **경계로 반드시 테스트**하라(제약이 `0 <= s.length`다).
>
> **무작위 소문자 문자열 수백 개로 나이브와 교차 검증**하면 확신이 생긴다.

> [!warning]- 흔한 실수
> - **구분자 누락** → `"aaa"`, `"aaaa"` 같은 반복 문자열에서 `L`이 `n`을 넘어 인덱스가 깨진다.
> - **빈 문자열 처리 누락** → `build_pi("")`가 빈 리스트를 반환해 `[-1]`에서 `IndexError`.
> - **붙이는 방향 혼동.** `reverse(s[L:]) + s`이지 `s + reverse(s[L:])`가 아니다. **앞에만** 붙일 수 있다.
> - **`pi` 대신 `find`로 해결하려 들기.** `rev(s)`가 `s`의 접두사로 끝나는 지점을 `find`로 찾으려면 결국 `O(n^2)`가 된다.
> - **"가장 긴 팰린드롬 부분 문자열"과 혼동.** 이 문제는 **접두사**여야 한다(반드시 인덱스 0에서 시작).

**복잡도 목표:** `O(n)` 시간, `O(n)` 공간.

## 6. Longest Duplicate Substring 🔴

**출처:** [LeetCode #1044](https://leetcode.com/problems/longest-duplicate-substring/)

문자열 `s`가 주어진다. **두 번 이상 등장하는(등장 위치는 겹쳐도 된다) 부분 문자열 중 가장 긴 것**을 반환하라. 그런 부분 문자열이 없으면 `""`를 반환한다. 답이 여러 개면 아무거나 반환해도 된다.

**예시:**
- `s = "banana"` → `"ana"`
- `s = "abcd"` → `""`

**제약:** `2 <= s.length <= 3 * 10^4`, 영소문자로만 구성.

**시그니처 (LeetCode):**
```python
class Solution:
    def longestDupSubstring(self, s: str) -> str: ...
```

> [!tip]- 힌트 1 (단조성을 발견하라 — 이분 탐색의 전제)
> **관찰: 길이 `L`짜리 중복이 존재하면, 길이 `L-1`짜리 중복도 반드시 존재한다.**
> 왜? 중복된 길이 `L` 부분 문자열의 **앞 `L-1`글자**를 보면, 그것도 같은 두 위치에서 중복이다.
>
> 따라서 **"길이 `L`짜리 중복이 존재하는가?"** 라는 술어는 `L`에 대해 **단조 감소**한다:
> ```
> L :  1    2    3    4    5   ...
> 답:  T    T    T    F    F   ...
>                     ^
>                  경계를 이분 탐색으로 찾는다
> ```
> [[day-18-binary-search/concept|Day 18]]의 **"최적화 문제를 결정 문제로 바꿔라"** 가 그대로 적용된다.

> [!tip]- 힌트 2 (판정을 `O(n)`에 — 롤링 해시)
> 이분 탐색의 각 단계에서 **"길이 `L`짜리 중복이 있는가?"** 를 `O(n)`에 답해야 한다.
> ```python
> def check(L):
>     seen = {}                          # 해시 -> 시작 위치
>     power = pow(BASE, L-1, MOD)
>     h = 0
>     for i in range(L):
>         h = (h * BASE + code[i]) % MOD
>     seen[h] = 0
>     for i in range(1, n - L + 1):
>         h = (h - code[i-1] * power) % MOD
>         h = (h * BASE + code[i+L-1]) % MOD
>         if h in seen:
>             return i                   # 중복 발견, 시작 위치 반환
>         seen[h] = i
>     return -1
> ```
> 전체 `O(n log n)`. `n = 3·10^4`이면 `log n ≈ 15` → 약 45만 연산으로 여유롭다.

> [!tip]- 힌트 3 (⚠️ 안티해시 — 이 문제의 진짜 함정)
> **LeetCode #1044에는 단일 모듈러 해시를 저격하는 테스트가 있다.** `MOD = 10^9+7` 하나만 쓰면 **충돌로 오답이 날 수 있다.**
>
> 생일 문제로 계산해 보라: 서로 다른 부분 문자열이 `3·10^4`개일 때 `p = 10^9+7`이면 충돌 확률 ≈ `(3·10^4)^2 / (2·10^9) ≈ 0.45` — **거의 반반**이다.
>
> **처방 세 가지 (하나 이상 반드시 적용):**
> 1. **이중 해시** — 서로 다른 `(BASE, MOD)` 두 쌍의 결과를 **튜플로** `seen`에 넣는다. 충돌 확률이 곱해져 사실상 0이 된다.
> 2. **`MOD = 2^61 - 1`** — 메르센 소수. 충돌 확률 `10^-11` 수준.
> 3. **해시 일치 시 실제 문자열 검증** — `seen[h]`에 시작 위치를 저장해 두고 `s[i:i+L] == s[seen[h]:seen[h]+L]`을 확인.
>
> **1번(이중 해시)이 가장 표준적이고 안전**하다.

> [!tip]- 힌트 4 (이분 탐색 골격 — 답도 함께 추적)
> ```python
> lo, hi = 1, n - 1
> best = ""
> while lo <= hi:
>     mid = (lo + hi) // 2
>     pos = check(mid)
>     if pos != -1:
>         best = s[pos:pos+mid]          # 답을 갱신
>         lo = mid + 1                   # 더 긴 것을 노린다
>     else:
>         hi = mid - 1
> return best
> ```
> **`hi`의 초기값은 `n-1`** 이다. 길이 `n`짜리 부분 문자열은 `s` 자신 하나뿐이라 중복될 수 없다.
> **판정 함수가 위치를 반환하게** 만들면 마지막에 답을 다시 찾을 필요가 없다.

> [!tip]- 힌트 5 (문자를 미리 숫자로)
> ```python
> code = [ord(c) - ord('a') + 1 for c in s]      # +1 이 중요하다!
> ```
> **`+1`을 빼먹으면** `'a'`가 `0`이 되어 `"a"`, `"aa"`, `"aaa"`의 해시가 전부 `0`이 된다 — **길이가 다른데 해시가 같아지는** 치명적 버그다.
> 또한 **루프 안에서 `ord()`를 반복 호출하지 말고** 미리 리스트로 만들어 두면 파이썬에서 체감 속도가 꽤 달라진다.

> [!tip]- 힌트 6 (다른 접근들도 알아 두라)
> - **접미사 배열(suffix array) + LCP** — `O(n log n)` 또는 `O(n)`. 해시 충돌 걱정이 없는 결정론적 해법이지만 구현이 훨씬 무겁다.
> - **접미사 자동자(suffix automaton)** — `O(n)`. 가장 강력하지만 코딩테스트에서 쓸 일은 드물다.
> - **나이브** — 통과 못 하지만 **소규모 교차 검증용으로 반드시 만들어라.**
>
> 실전에서는 **이분 탐색 + 이중 해시가 코딩 비용 대비 최선**이다.

> [!warning]- 흔한 실수
> - **단일 해시 사용** → 이 문제의 특정 테스트에서 오답. **가장 중요한 함정이다.**
> - **`ord(c) - ord('a')`(+1 없음)** → 서로 다른 길이의 `'a'` 반복이 같은 해시가 된다.
> - **`hi`를 `n`으로 잡기** → 길이 `n`은 중복이 불가능하므로 낭비이고, 인덱싱이 어긋날 수 있다.
> - **이분 탐색에서 답 갱신을 빼먹기** → 경계는 찾았는데 문자열을 못 돌려준다.
> - **`check`에서 첫 윈도우를 `seen`에 안 넣기** → 첫 번째와 두 번째 위치의 중복을 놓친다.
> - **중복이 없을 때 `""` 반환 누락.** `s = "abcd"`로 반드시 테스트하라.

**복잡도 목표:** `O(n log n)` 시간, `O(n)` 공간.

## 학습 순서 제안

1. **#28을 두 번 풀어라.** 먼저 `haystack.find(needle)` 한 줄로 통과시키고(정답 기준선 확보), 그다음 `build_pi` + `kmp_search`를 손으로 짜서 **무작위 입력으로 교차 검증**하라. `pi` 배열을 손으로 채워 보는 것이 오늘의 출발점이다.
2. **#187로 롤링의 감각을 익혀라.** `set` 슬라이싱으로 먼저 통과시키고, 그다음 **2비트 인코딩**(`(h << 2 | code) & MASK`)으로 다시 짜라. [[day-41-bitmask/concept|Day 41 비트마스킹]]이 여기서 바로 재등장한다.
3. **#459가 오늘의 핵심 정리다.** 약수 완전 탐색 → `pi` 주기 공식 → `(s+s)[1:-1]` 트릭 **세 가지를 모두** 구현하고 서로 대조하라. **`n % p == 0`을 왜 확인해야 하는지** 설명할 수 있으면 `pi` 배열을 이해한 것이다.
4. **#17683(방금그곡)이 실전 하이라이트다.** 알고리즘이 아니라 **`C#` 정규화·재생 시간 절단·동점 처리** 세 가지 경계 조건이 승부처다. **카카오 기출의 난이도는 대개 여기에 있다**는 것을 체감하라.
5. **#214로 `pi`의 응용력을 끌어올려라.** `s + '#' + rev(s)`가 왜 "가장 긴 팰린드롬 접두사"를 주는지 **말로 설명**할 수 있어야 한다. 구분자를 빼고 돌려서 실제로 깨지는 것도 한 번 확인해 보라.
6. **#1044로 조합의 힘을 배워라.** [[day-18-binary-search/concept|이분 탐색(Day 18)]] + 롤링 해시. 그리고 **단일 해시로 먼저 제출해 실패를 겪은 뒤 이중 해시로 고치는 것**을 권한다 — 해시 충돌이 이론이 아니라 실재한다는 것을 몸으로 알게 된다.

## 오늘의 판단 기준 (다시)

| 상황 | 도구 |
|---|---|
| 파이썬에서 단일 패턴을 그냥 찾기 | **`T.find(P)`** (C 구현이 가장 빠르다) |
| 최악 `O(N+M)`을 직접 보장·설명해야 함 | **KMP** |
| 문자열의 주기·반복 구조 | **`n - pi[n-1]`** (+ `n % p == 0` 확인) |
| 가장 긴 팰린드롬 **접두사** | **`pi(s + '#' + rev(s))[-1]`** |
| 고정 길이 부분 문자열의 중복 | `set` 슬라이싱 또는 **비트/롤링 해시** |
| 패턴이 여러 개 | **라빈-카프**(해시 `set`) / 아호-코라식 |
| 임의 두 구간이 같은지 여러 번 질의 | **접두사 해시** (전처리 `O(N)`, 질의 `O(1)`) |
| "가장 긴 ○○"인데 길이에 단조성이 있음 | **이분 탐색 + 롤링 해시** |
| 해시를 쓰는데 `n`이 큼 | **이중 해시 또는 `2^61-1`** (단일 `10^9+7` 금지) |
| 기출 문자열 문제 | **먼저 정규화**(`C#` → 한 글자), 그다음 매칭 |
