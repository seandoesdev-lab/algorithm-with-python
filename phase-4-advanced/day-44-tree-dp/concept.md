# Day 44 — 트리 DP (Tree DP: 서브트리 집계·리루팅)

> [!abstract] 한눈 요약 (TL;DR)
> **트리 DP(Tree DP)** 는 **"각 노드의 답을 그 자식들의 답으로 정의하는"** DP다. [[day-31-dp/concept|Day 31]]에서 배운 DP가 **1차원 배열**(`dp[i]`는 `dp[i-1]`에서) 위에서 굴러갔다면, 오늘은 그 무대가 **트리**로 바뀐다. **핵심은 놀랄 만큼 단순하다: 트리에는 사이클이 없으므로, 서로 다른 자식의 서브트리는 절대 겹치지 않는다.** 그래서 **"자식들의 답을 합치면 내 답"** 이라는 재귀식이 **순환 없이** 성립하고, **후위 순회(post-order)가 곧 DP의 계산 순서**가 된다 — [[day-38-topological-sort/concept|위상 정렬(Day 38)]]을 따로 돌릴 필요조차 없다는 뜻이다. 오늘 익혀야 할 것은 다섯 가지 형태다. **① 순수 집계형** — 서브트리 크기·합·높이를 올려보내는 가장 기본형. **② 상태 추가형 `dp[v][0/1]`** — "이 노드를 **쓰느냐 마느냐**"를 상태에 넣는다. [House Robber III(#337)](https://leetcode.com/problems/house-robber-iii/)의 **"쓰면 자식은 못 쓴다"** 가 그대로 **최대 가중 독립 집합(maximum weight independent set)** 이고, 이것이 **[[day-32-dp-knapsack/concept|배낭(Day 32)]]의 "넣는다/안 넣는다"가 트리로 옮겨온 모습**이다. **③ 경로형 — 오늘 가장 중요한 패턴** — [지름(#543)](https://leetcode.com/problems/diameter-of-binary-tree/)과 [최대 경로 합(#124)](https://leetcode.com/problems/binary-tree-maximum-path-sum/)이 여기 속하며, **"부모에게 올려보내는 값(한쪽으로만 내려가는 최선)"과 "정답에 기록하는 값(이 노드에서 좌우로 꺾이는 최선)"이 서로 다르다**는 것이 전부다. **`return`값과 `answer` 갱신을 분리하지 못하면 이 유형 전체를 틀린다.** 이것은 [[day-43-lca/concept|LCA(Day 43)]]에서 본 **"트리의 모든 경로는 어딘가에서 꺾인다"** 의 DP 버전이다 — 꺾이는 지점에서 답을 집계한다. **④ 리루팅(rerooting, 전방위 트리 DP)** — **"모든 노드를 루트로 삼았을 때의 답을 전부 구하라"** 는 요구를 **`O(N²)`가 아니라 `O(N)`** 에 해결한다([#834](https://leetcode.com/problems/sum-of-distances-in-tree/)). **1차 순회로 아래 정보를 모으고, 2차 순회로 부모의 정보를 빼서 내려보내는** 2-pass 구조이며, **"전체에서 나를 뺀다"** 는 [[day-14-prefix-sum/concept|누적 합(Day 14)]]의 사고가 트리에서 재등장한다. **⑤ 다중 상태형** — [카메라(#968)](https://leetcode.com/problems/binary-tree-cameras/)처럼 상태가 `0/1`이 아니라 **`커버 안 됨 / 커버됨 / 카메라 있음` 세 가지**인 경우. 상태를 정확히 나누는 것이 곧 문제를 푸는 것이다. 그리고 **트리라고 전부 DP는 아니다**: [양과 늑대(프로그래머스 #92343)](https://school.programmers.co.kr/learn/courses/30/lessons/92343)는 **방문 순서가 답을 바꾸고 상태가 "지금까지 방문한 집합"** 이라 **서브트리로 분해되지 않는다** — 그래서 DP가 아니라 [[day-24-brute-force/concept|완전 탐색(Day 24)]]+[[day-41-bitmask/concept|비트마스크(Day 41)]]다. **"분해되는가"를 먼저 묻는 훈련**이 오늘의 숨은 주제다. 마지막으로 파이썬 실전 경고 하나: **`N`이 10⁴만 되어도 트리 문제에서 재귀 DFS는 체인 입력에 `RecursionError`로 죽는다.** 정석은 **BFS 순서를 만들고 `reversed(order)`로 후위 순회를 대신하는 것** — [[day-43-lca/concept|Day 43]]에서 예고한 그 관용구가 오늘 주력 무기가 된다. 핵심 한 줄: **"트리 DP는 자식의 요약본을 부모가 합치는 일이다. 무엇을 올려보내고 무엇을 기록할지만 정하면 된다."**

> [!note]- 1. 정의와 직관 (Definition & Intuition)
> **정의.** **트리 DP**는 루트가 정해진 트리에서
> - **상태(state)** 를 **"노드 `v`를 루트로 하는 서브트리"**(필요하면 `+ 부가 상태`)로 잡고,
> - **전이(transition)** 를 **"`v`의 자식들의 답 → `v`의 답"** 으로 정의하며,
> - **계산 순서(order)** 를 **후위 순회(자식 먼저, 부모 나중)** 로 두는
>
> DP 기법이다. 한 문장으로 줄이면 **"서브트리의 답을 위로 올려보내며 합친다"** 이다.
>
> ---
>
> ### 왜 트리에서는 DP가 되는가 — 두 가지 이유
>
> [[day-31-dp/concept|Day 31]]에서 DP가 성립하려면 **① 최적 부분 구조**와 **② 겹치는 부분 문제**가 필요하다고 했다. 트리는 이 조건을 **구조적으로** 만족한다.
> ```
>   [이유 1] 서브트리는 서로 겹치지 않는다 (disjoint)
>
>              v
>            /   \
>           a     b
>          / \   / \
>         .. .. .. ..
>
>     a 의 서브트리와 b 의 서브트리는 공통 노드가 0개다.
>     -> "a 쪽 결정"과 "b 쪽 결정"이 서로 간섭하지 않는다
>     -> 따로 최적화한 뒤 합쳐도 된다 = 최적 부분 구조 O
>
>   [이유 2] 사이클이 없다 (acyclic)
>
>     일반 그래프에서 dp[v] = f(dp[이웃들]) 을 쓰면
>     dp[a] 가 dp[b] 에 의존하고 dp[b] 가 다시 dp[a] 에 의존한다
>     -> 순환 정의, 계산 불가
>
>     트리에서는 "부모 방향"만 빼고 보면 의존이 한 방향(자식 -> 부모)뿐이다
>     -> 후위 순회 순서로 계산하면 필요한 값이 항상 이미 준비되어 있다
> ```
> **그래서 트리 DP에는 "메모이제이션 딕셔너리"가 사실 필요 없다.** 각 상태를 **정확히 한 번씩** 계산하며, 그 순서를 **순회가 공짜로 제공**한다. [[day-38-topological-sort/concept|위상 정렬(Day 38)]]을 별도로 돌려야 하는 DAG DP와 비교하면 **"트리 = 위상 순서가 이미 주어진 DAG"** 라고 볼 수 있다.
>
> ---
>
> ### 비유 1 — 회사 조직도의 실적 집계
>
> **팀장은 자기 팀원들의 보고서를 받아 자기 보고서를 만든다.** 사원 → 대리 → 과장 → 부장 → 사장 순으로 올라가고, **아랫사람의 보고가 끝나야 내 보고를 쓸 수 있다.** 이것이 정확히 후위 순회다.
> ```
>   "우리 부서 총 인원" = 1(나) + 각 팀의 총 인원 합       <- 서브트리 크기
>   "우리 부서 총 매출" = 내 매출 + 각 팀 매출 합           <- 서브트리 합
>   "가장 말단까지의 깊이" = 1 + max(각 팀의 깊이)          <- 서브트리 높이
> ```
> **각 노드가 부모에게 "요약본 한 장"을 올려보낸다** — 이 그림이 트리 DP의 전부다. 그리고 **요약본에 무엇을 적을지 정하는 것**이 문제 풀이의 90%다.
>
> ---
>
> ### 비유 2 — 디렉터리 용량 계산 (`du`)
>
> 폴더 하나의 크기 = **자기 파일들 크기 + 하위 폴더들 크기의 합**. 하위 폴더를 다 계산해야 상위 폴더가 정해진다. **`du -sh`는 실제로 트리 DP를 돌리는 프로그램이다.** 그리고 **하위 폴더끼리 겹치지 않기 때문에** 단순 덧셈이 성립한다 — 심볼릭 링크로 사이클이 생기면 순회가 무한 루프에 빠지는 것이 **"사이클이 있으면 DP가 깨진다"** 의 실물 증거다.
>
> ---
>
> ### 오늘 배우는 다섯 가지 형태 — 한눈에
>
> ```
>   [1] 순수 집계형   dp[v] = (자식 dp 들의 단순 결합)
>       예: 서브트리 크기, 합, 높이, 잎 개수
>
>   [2] 상태 추가형   dp[v][0] / dp[v][1]   ("v 를 쓰나 안 쓰나")
>       예: House Robber III(#337), 최대 가중 독립 집합, 트리 매칭
>       핵심: 쓰면 자식은 못 쓴다 -> dp[v][1] = w[v] + sum(dp[c][0])
>             안 쓰면 자식은 자유 -> dp[v][0] = sum(max(dp[c][0], dp[c][1]))
>
>   [3] 경로형        올려보내는 값 != 정답에 기록하는 값     <- 오늘의 핵심
>       예: 지름(#543), 최대 경로 합(#124)
>       핵심: 부모에게는 "한쪽 가지로만 내려가는 최선"을 준다
>             정답에는 "여기서 좌우로 꺾이는 최선"을 기록한다
>
>   [4] 리루팅        모든 노드를 루트로 삼은 답을 전부       <- O(N) 로!
>       예: 모든 정점까지의 거리 합(#834)
>       핵심: 1차(아래 모으기) -> 2차(부모에서 내 기여분을 빼서 내려주기)
>
>   [5] 다중 상태형   상태가 3개 이상
>       예: 카메라(#968) - (커버 안 됨 / 커버됨 / 카메라 있음)
>       핵심: 상태를 정확히 나누면 전이는 기계적으로 따라온다
> ```
>
> ---
>
> ### ⚠️ 트리라고 전부 트리 DP는 아니다 — 오늘의 숨은 주제
>
> 트리 DP가 성립하려면 **"서브트리 안에서 내린 결정이 서브트리 밖에 영향을 주지 않아야"** 한다. 이 조건이 깨지면 DP가 아니라 **탐색**이다.
> ```
>   트리 DP가 되는 경우:
>     - "이 서브트리에서 최대 얼마를 얻는가"가 바깥과 무관하게 정해진다
>     - 자식들 사이에 순서/상호작용이 없다 (합치기만 하면 된다)
>
>   트리 DP가 안 되는 경우:
>     - 방문 "순서"가 답을 바꾼다
>     - 지금까지 지나온 전체 경로/집합이 앞으로의 선택을 제약한다
>     - 자식 서브트리를 넘나들며 왔다 갔다 할 수 있다
>
>   대표 예: 프로그래머스 #92343 "양과 늑대"
>     루트에서 시작해 이미 방문한 노드 어디로든 되돌아가 다른 가지로 갈 수 있다.
>     "늑대 >= 양이면 전멸"이라는 제약이 전역 상태(지금까지 모은 양/늑대)에 걸린다.
>     -> 서브트리로 분해되지 않는다 -> 완전 탐색(방문 집합을 상태로) 이 정답이다
>     -> n <= 17 이라는 제약이 "지수 시간을 허용한다"는 출제자의 신호다
> ```
> **"제약의 크기가 도구를 알려준다"** 는 감각을 여기서 다시 확인하라. `N ≤ 17`이면 **`2^N` 탐색**, `N ≤ 10^5`면 **선형 트리 DP**다.

> [!gear]- 2. 동작 원리 (How It Works)
> **(A) 골격 — 재귀 없이 후위 순회하기 (파이썬 정석)**
>
> 트리 DP의 뼈대는 **"자식이 먼저, 부모가 나중"** 이다. 재귀로 쓰면 자연스럽지만 파이썬에서는 **깊이 1000에서 죽는다.** 정석은 **BFS로 순서를 만들고 뒤집는 것**이다.
> ```
>   BFS 순서:      부모가 자식보다 항상 "앞"에 온다
>   reversed(BFS): 자식이 부모보다 항상 "앞"에 온다  = 후위 순회와 동일한 효과!
>
>              0
>            /   \
>           1     2
>          / \
>         3   4
>
>   BFS order          = [0, 1, 2, 3, 4]
>   reversed(order)    = [4, 3, 2, 1, 0]
>       4 처리 -> 3 처리 -> 2 처리 -> 1 처리(자식 3,4 는 이미 끝) -> 0 처리   O
> ```
> ```python
> from collections import deque
>
> def root_tree(adj, root=0):
>     """무향 트리에 루트를 정해 parent / depth / BFS순서를 만든다. 재귀 0줄."""
>     n = len(adj)
>     parent, depth = [-1] * n, [0] * n
>     visited = [False] * n
>     visited[root] = True
>     order = [root]
>     dq = deque([root])
>     while dq:
>         v = dq.popleft()
>         for w in adj[v]:
>             if not visited[w]:
>                 visited[w] = True
>                 parent[w] = v
>                 depth[w] = depth[v] + 1
>                 order.append(w)
>                 dq.append(w)
>     return parent, depth, order
>
> # 이후 모든 트리 DP는 이 한 줄로 시작한다
> # for v in reversed(order):   ...자식들은 이미 계산되어 있다...
> ```
> **`reversed(order)` 안에서 "자식 순회"는 `adj[v]`에서 `parent[v]`만 빼고 돌면 된다.** 별도의 `children` 리스트를 만들 필요도 없다.
>
> ---
>
> **(B) 유형 1 — 순수 집계형: 서브트리 크기·합·높이**
> ```
>   size[v]   = 1 + sum(size[c])            서브트리 노드 수
>   total[v]  = w[v] + sum(total[c])        서브트리 가중치 합
>   height[v] = 0 if 잎 else 1 + max(height[c])
> ```
> ```python
> size = [1] * n
> for v in reversed(order):
>     p = parent[v]
>     if p != -1:
>         size[p] += size[v]        # 자식이 자기 값을 부모에게 "밀어 넣는다"
> ```
> ```
>   두 가지 서술 방식이 있다 - 둘 다 알아 두라
>
>     [당기기 pull]  for v in reversed(order):  for c in children[v]:  dp[v] += dp[c]
>     [밀기  push]   for v in reversed(order):  dp[parent[v]] += dp[v]
>
>   밀기(push)가 코드가 짧다. children 리스트를 안 만들어도 되기 때문이다.
>   단, max/min 처럼 "자식 목록 전체를 봐야 하는" 전이는 당기기가 읽기 쉽다.
> ```
> **서브트리 크기는 트리 문제의 만능 재료다.** 트리를 반으로 쪼개는 문제(간선 하나를 끊었을 때 양쪽 크기), 무게 중심(centroid), 리루팅에서 모두 `size[]`가 먼저 필요하다.
>

> **(C) 유형 2 — 상태 추가형 `dp[v][0/1]`: "쓰느냐 마느냐"**
>
> [House Robber III(#337)](https://leetcode.com/problems/house-robber-iii/)의 규칙은 **"직접 연결된 두 집을 같이 털 수 없다"** 이다. 이는 그래프 이론의 **최대 가중 독립 집합(maximum weight independent set)** 과 똑같은 문제이고, **일반 그래프에서는 NP-hard지만 트리에서는 `O(N)`** 이다 — **트리 DP의 존재 이유를 보여주는 대표 사례**다.
> ```
>   상태를 하나 늘린다:
>     dp[v][0] = v 를 "안 쓰는" 조건에서 v 의 서브트리 최댓값
>     dp[v][1] = v 를 "쓰는"   조건에서 v 의 서브트리 최댓값
>
>   전이:
>     dp[v][1] = w[v] + sum( dp[c][0] )                  <- 나를 쓰면 자식은 전부 못 쓴다
>     dp[v][0] =        sum( max(dp[c][0], dp[c][1]) )   <- 나를 안 쓰면 자식은 자유
>
>   답: max(dp[root][0], dp[root][1])
> ```
> ```
>   예)          3
>              /   \
>             2     3
>              \     \
>               3     1
>
>   잎 3(왼쪽 아래): dp[0]=0, dp[1]=3
>   잎 1(오른쪽):    dp[0]=0, dp[1]=1
>   노드 2:  dp[1] = 2 + dp[자식][0] = 2 + 0 = 2
>            dp[0] = max(0, 3) = 3
>   노드 3(오른쪽): dp[1] = 3 + 0 = 3,   dp[0] = max(0, 1) = 1
>   루트 3:  dp[1] = 3 + dp[2][0] + dp[3오른][0] = 3 + 3 + 1 = 7
>            dp[0] = max(2,3) + max(3,1) = 3 + 3 = 6
>   답 = max(7, 6) = 7   O
> ```
> ```
>   +-- 이것은 배낭(Day 32)의 "넣는다/안 넣는다"가 트리로 옮겨온 것이다 --------+
>   |  선형 House Robber:  dp[i][0], dp[i][1]  <- 이전 한 칸에만 의존           |
>   |  트리 House Robber:  dp[v][0], dp[v][1]  <- 여러 자식의 합에 의존         |
>   |  "이전"이 하나에서 여럿으로 늘어난 것 외에 달라진 것이 없다                |
>   +---------------------------------------------------------------------------+
> ```
> **이 형태의 확장이 매우 넓다.** 상태를 `0/1` 대신 `0/1/2`로 늘리면 카메라 문제가 되고, `k`개의 색을 칠하는 문제면 `dp[v][색]`이 되며, "자식 중 몇 개를 고르는가"가 필요하면 **서브트리 크기를 축으로 하는 트리 배낭(tree knapsack)** 이 된다.
>

> **(D) 유형 3 — 경로형: "올려보내는 값 ≠ 정답" ★ 오늘 가장 중요한 패턴**
>
> [[day-43-lca/concept|Day 43]]에서 **"트리에서 두 점 사이 경로는 반드시 어딘가에서 꺾인다"** 를 배웠다. 그 꺾이는 지점이 LCA였다. **경로형 트리 DP는 이 관찰을 그대로 쓴다: 모든 경로는 정확히 한 노드에서 꺾이므로, 각 노드에서 "여기서 꺾이는 최선의 경로"만 계산해 전부 비교하면 답이 나온다.**
> ```
>   각 노드 v 에서 두 가지 값을 생각한다:
>
>     [올려보내는 값]  down[v] = v 에서 아래로 "한 가지"만 타고 내려가는 최선
>                      -> 부모가 이 값을 이어 붙여 자기 경로를 만든다
>                      -> 그래서 "두 갈래로 벌어진" 경로는 올려보낼 수 없다!
>
>     [정답에 기록]    v 에서 왼쪽으로도 내려가고 오른쪽으로도 내려가는,
>                      즉 v 에서 꺾이는 경로
>                      -> best = max(best, down[c1] + down[c2] + ...)
>
>   이 둘이 다르다는 것이 이 유형의 전부다.
> ```
> ```
>   트리 지름 (#543) - 가장 먼 두 노드 사이의 간선 수
>
>              a
>            /   \
>           b     c
>          / \
>         d   e
>            /
>           f
>
>     down[d]=0, down[f]=0, down[e]=1, down[b]=1+max(0,1)=2, down[c]=0
>
>     각 노드에서 "여기서 꺾이는 경로 길이" (자식 방향 깊이 상위 2개의 합):
>       d: 0        f: 0        e: 1  (자식이 f 하나뿐)
>       b: (d 쪽 1) + (e 쪽 2) = 3          <- d - b - e - f,  간선 3개
>       a: (b 쪽 3) + (c 쪽 1) = 4          <- 실제 최장 경로는 f - e - b - a - c
>     답 = 4
> ```
> ```python
> # 지름: 각 노드에서 "자식 방향 깊이 상위 2개"의 합이 그 노드에서 꺾이는 최장 경로
> best = 0
> down = [0] * n
> for v in reversed(order):
>     top1 = top2 = 0                       # 상위 2개만 있으면 충분하다
>     for w in adj[v]:
>         if w == parent[v]:
>             continue
>         d = down[w] + 1
>         if d > top1:
>             top1, top2 = d, top1
>         elif d > top2:
>             top2 = d
>     down[v] = top1                        # 부모에게는 "한 갈래"만 준다
>     best = max(best, top1 + top2)         # 정답에는 "두 갈래"를 기록한다
> ```
> ```
>   최대 경로 합 (#124) - 값이 음수일 수 있는 것이 함정
>
>     gain(node) = node.val + max( gain(left), gain(right), 0 )
>                                                          ^^^
>                                        음수 가지는 아예 안 타는 것이 이득!
>     best = max(best, node.val + max(gain(left),0) + max(gain(right),0))
>
>   왜 max(..., 0) 인가:
>     경로는 "적어도 노드 하나"면 되므로 손해 보는 가지를 붙일 이유가 없다.
>     이 0 클램프를 빼면 음수가 섞인 트리에서 틀린다.
>     반대로 best 의 초깃값을 0 으로 두면 [-3] 같은 입력에서 0 을 답한다 - -inf 로 두라.
> ```
> ```
>   +-- 왜 "한 갈래만" 올려보내야 하는가 ---------------------------------+
>   |  부모 입장에서 이 자식은 "경로의 한쪽 끝으로 이어지는 통로"다.       |
>   |  자식이 이미 두 갈래로 벌어진 경로를 주면, 부모가 거기에 자기를      |
>   |  이어 붙이는 순간 "갈래가 셋"인 도형이 되어 경로가 아니게 된다.      |
>   |  경로(path)는 일직선이어야 한다 - 이것이 제약의 정체다.              |
>   +---------------------------------------------------------------------+
> ```
> **`return`값과 `answer` 갱신을 분리하는 습관**은 트리 문제 전반에 쓰인다. 실제로 [[day-43-lca/concept|Day 43]]의 [#1123](https://leetcode.com/problems/lowest-common-ancestor-of-deepest-leaves/)에서 `(높이, LCA)` 튜플을 올려보낸 것도 같은 사고다 — **"부모가 필요로 하는 정보"와 "내가 확정할 수 있는 답"은 다르다.**
>

> **(E) 유형 4 — 리루팅(Rerooting, 전방위 트리 DP): 모든 루트에 대한 답을 `O(N)`에**
>
> 지금까지는 **루트가 하나로 고정**이었다. 그런데 **"모든 노드 `v`에 대해, `v`를 루트로 했을 때의 답"** 을 전부 요구하는 문제가 있다([#834](https://leetcode.com/problems/sum-of-distances-in-tree/)). 나이브하게는 **각 노드에서 순회를 한 번씩 = `O(N²)`** 인데, `N = 3·10^4`면 `9·10^8`로 터진다.
> ```
>   핵심 발견: 루트를 v 에서 "이웃" c 로 옮길 때, 답이 아주 조금만 변한다.
>
>   [#834] ans[v] = v 에서 다른 모든 노드까지의 거리 합
>
>            v ---- c        (간선 하나로 붙어 있다)
>
>     루트를 v 에서 c 로 옮기면:
>       c 의 서브트리 안 노드들(cnt[c] 개)  -> 거리가 1 씩 "줄어든다"
>       나머지 노드들(n - cnt[c] 개)        -> 거리가 1 씩 "늘어난다"
>
>       ans[c] = ans[v] - cnt[c] + (n - cnt[c])
>
>     이 한 줄이 리루팅의 전부다!
> ```
> ```python
> # 1차 순회 (아래 -> 위): 서브트리 크기와 "루트 기준" 거리 합을 만든다
> cnt = [1] * n
> ans = [0] * n
> for v in reversed(order):
>     p = parent[v]
>     if p != -1:
>         cnt[p] += cnt[v]
>         ans[p] += ans[v] + cnt[v]    # 자식 쪽 노드들이 간선 하나씩 더 멀어진다
>
> # 2차 순회 (위 -> 아래): 부모의 답에서 내 기여분을 조정해 내려받는다
> for v in order[1:]:                  # 루트는 이미 정답
>     p = parent[v]
>     ans[v] = ans[p] - cnt[v] + (n - cnt[v])
> ```
> ```
>   예)  n=6, edges = [[0,1],[0,2],[2,3],[2,4],[2,5]]
>
>          0
>         / \
>        1   2
>           /|\
>          3 4 5
>
>   1차: cnt = [6, 1, 4, 1, 1, 1],  ans[0] = 8
>        (0->1:1, 0->2:1, 0->3:2, 0->4:2, 0->5:2  합 8)
>   2차: ans[1] = 8 - cnt[1] + (6 - cnt[1]) = 8 - 1 + 5 = 12
>        ans[2] = 8 - 4 + 2 = 6
>        ans[3] = ans[2] - 1 + 5 = 10      (4, 5 도 동일하게 10)
>   답 = [8, 12, 6, 10, 10, 10]   O
> ```
> ```
>   리루팅의 일반형 (거리 합이 아닌 임의 집계에도 쓴다)
>
>     down[v] : v 의 서브트리에서 올라온 답      <- 1차 순회
>     up[v]   : v 를 제외한 "위쪽 전부"의 답      <- 2차 순회
>     answer[v] = merge(down[v], up[v])
>
>     2차에서 자식 c 의 up[c] 를 만들려면
>       "부모 v 의 up[v]" + "v 의 자식들 중 c 를 뺀 나머지의 down"
>     이 필요하다.  자식이 많으면 "c 를 뺀 나머지"를 매번 다시 더할 수 없으므로
>       - 합/개수처럼 뺄 수 있는 연산: 전체에서 빼면 O(1)      <- Day 14 누적 합 사고
>       - max 처럼 못 빼는 연산: "상위 2개"를 들고 다니거나
>                                 접두사/접미사 배열을 만든다  <- 못 빼면 미리 쌓는다
> ```
> **`max`는 뺄 수 없다**는 것이 리루팅 구현의 최대 난관이다. 처방은 두 가지다: **① 상위 1·2등을 함께 저장**(1등이 나 자신이면 2등을 쓴다), **② 자식 목록에 대해 접두사 최댓값·접미사 최댓값 배열을 만들어 `i`를 제외한 최댓값을 `O(1)`에 얻기.** [[day-14-prefix-sum/concept|Day 14]]의 사고가 여기서도 그대로 쓰인다.
>

> **(F) 유형 5 — 다중 상태형: 카메라 문제(#968)**
>
> 상태를 **세 가지**로 나누면 전이가 기계적으로 따라온다.
> ```
>   각 노드에 대해 세 값을 계산한다 (모두 "이 서브트리를 전부 감시하는 최소 카메라 수")
>
>     A[v] = v 에 카메라를 "설치"한다
>     B[v] = v 에 카메라는 없지만 v 는 "감시되고 있다" (자식 중 누군가에 카메라)
>     C[v] = v 에 카메라도 없고 v 는 "아직 감시되지 않는다" (부모가 책임진다)
>            단, v 의 자식들은 모두 감시되어 있어야 한다
>
>   빈 노드(None):  A = INF (카메라를 놓을 수 없다),   B = 0,   C = 0
>
>   전이 (자식 L, R):
>     A[v] = 1 + min(A[L], B[L], C[L]) + min(A[R], B[R], C[R])
>            (내가 카메라면 자식은 어떤 상태든 상관없다)
>     B[v] = min( A[L] + min(A[R], B[R]),  A[R] + min(A[L], B[L]) )
>            (적어도 한 자식에 카메라가 있어야 내가 감시된다)
>     C[v] = B[L] + B[R]
>            (자식들은 감시되어 있되 카메라는 없다)
>
>   답 = min(A[root], B[root])     <- C[root] 는 안 된다. 루트 위에는 부모가 없다!
> ```
> ```
>   잎 노드 검산:  L = R = None
>     A = 1 + min(INF,0,0) + min(INF,0,0) = 1 + 0 + 0 = 1
>     B = min(INF+0, INF+0) = INF        <- 잎은 자식이 없으니 감시받을 수 없다. 맞다
>     C = 0 + 0 = 0                      <- 부모가 책임진다면 0. 맞다
>   노드 1개짜리 트리:  min(A, B) = min(1, INF) = 1   O
> ```
> **이 문제는 [[day-21-greedy/concept|그리디(Day 21)]]로도 풀린다** — "아직 감시되지 않은 잎이 보이면 그 부모에 카메라를 놓는다"를 아래에서 위로 반복하면 된다. **DP가 안전하고, 그리디가 짧다.** 두 해법을 모두 짜서 **교차 검증**하는 것이 오늘의 좋은 훈련이다. 그리디가 왜 최적인지 설명할 수 없다면 **DP로 가라** — 그것이 실전에서 안전한 판단이다.

> **(G) ⚠️ 파이썬 실전 — 재귀 깊이와 반복 후위 순회**
> ```
>   기본 재귀 한도: sys.getrecursionlimit() == 1000
>
>   LeetCode #543, #337, #124 는 노드 수가 각각 10^4, 10^4, 3·10^4 이고
>   "한쪽으로 늘어진 트리" 테스트가 실제로 존재한다.  재귀는 죽는다.
>
>   처방 3가지:
>     1) sys.setrecursionlimit(10**6)   -> 파이썬 한도는 늘어나지만
>                                          C 스택이 터져 프로세스가 죽을 수 있다(임시방편)
>     2) BFS 순서 + reversed(order)     -> 인접 리스트 트리에서는 이게 정석
>     3) 명시적 스택 후위 순회          -> 이진 트리 객체(TreeNode)에서는 이게 정석
> ```
> ```python
> # 이진 트리 객체에서의 반복 후위 순회 - (노드, 처리했는가) 쌍을 쌓는다
> def postorder(root):
>     out, stack = [], [(root, False)]
>     while stack:
>         node, done = stack.pop()
>         if node is None:
>             continue
>         if done:
>             out.append(node)            # 자식이 모두 끝난 뒤 도달한다
>         else:
>             stack.append((node, True))  # 나를 "나중에" 처리하도록 다시 넣고
>             stack.append((node.right, False))
>             stack.append((node.left, False))
>     return out                          # 이 순서대로 dp 를 채우면 안전하다
> ```
> **또는 "부모 맵을 만들고 BFS 순서를 뒤집는" 방식**도 똑같이 동작한다. **어느 쪽이든 재귀 0줄**이라는 점이 중요하다.
>

> | 경로형 (#543, #124) | **O(N)** | O(N) | 자식 중 상위 2개만 보면 됨 |
> | 다중 상태 (#968) | **O(N·S)** = O(N) | O(N) | `S = 3` |
> | **리루팅** (#834) | **O(N)** ✅ | O(N) | 2-pass. 나이브는 **O(N²)** ❌ |
> | 트리 배낭 (자식별 용량 분배) | **O(N·K)** ~ O(N²) | O(N·K) | 크기 축을 상태에 넣을 때 |
> | 트리 위 완전 탐색 (#92343) | **O(2^N · N)** | O(2^N) | `N ≤ 17`이라는 제약이 신호 |
>
> > **왜 "모든 노드·간선을 한 번씩"이 `O(N)`인가.**
> >
> > 트리의 간선 수는 정확히 `N-1`이다. `for v: for c in children[v]` 이중 루프는 **겉보기에 이중이지만 실제로는 각 간선을 딱 한 번 훑는다** — 모든 `children[v]` 길이의 합이 `N-1`이기 때문이다. **"이중 루프 = `O(N²)`"이 아니라는 대표적인 예**이고, 인접 리스트 순회의 복잡도가 `O(V+E)`인 것과 같은 논리다([[day-28-graph/concept|Day 28]]).
>
> > **리루팅이 없으면 얼마나 손해인가 (#834 기준, `N ≤ 3·10⁴`).**
> >
> > | 방법 | 연산량 | 파이썬 판정 |
> > |---|---|---|
> > | 각 노드마다 BFS/DFS (`O(N²)`) | 9×10⁸ | ❌ 불가능 (수백 초) |
> > | 리루팅 2-pass (`O(N)`) | 6×10⁴ | ✅ 즉시 |
> >
> > **10⁴ 배 차이**다. **"모든 노드에 대해 답을 구하라"는 문구를 보면 즉시 리루팅을 의심하라** — 그것이 이 유형의 신호탄이다.
>
> > **재귀 vs 반복 — 복잡도는 같고 "생존 여부"가 다르다.**
> >
> > | 트리 모양 (N = 10⁵) | 재귀 DFS | 반복(BFS 뒤집기) |
> > |---|---|---|
> > | 완전 이진 트리 (h≈17) | 동작 | 동작 |
> > | 랜덤 트리 (h≈수십~수백) | 동작 | 동작 |
> > | **체인(일자, h=10⁵)** | **RecursionError** ❌ | ✅ 정상 |
> >
> > 둘 다 `O(N)`이다. **차이는 복잡도가 아니라 "죽느냐 사느냐"** 다. 그리고 반복 버전은 **함수 호출 오버헤드가 없어 실제로 더 빠르다**(파이썬 함수 호출은 비싸다). **깊이 걱정이 없는 작은 트리에서도 반복이 손해가 아니다.**
>
> > **상태 수를 늘릴 때의 비용 감각.**
> >
> > | 상태 수 `S` | 예시 | 시간 |
> > |---|---|---|
> > | 1 | 서브트리 크기 | O(N) |
> > | 2 | 쓴다/안 쓴다 (#337) | O(2N) |
> > | 3 | 카메라 (#968) | O(3N) |
> > | `K` | `K`색 칠하기 | O(N·K) 또는 O(N·K²) |
> > | 서브트리 크기 축 | 트리 배낭 | **O(N²)** (교묘하게도 `N²`가 된다) |
> >
> > **트리 배낭이 `O(N²)`인 것은 유명한 결과다.** "자식 서브트리 크기끼리의 곱의 총합 = 노드 쌍의 수 = `O(N²)`"이라는 조합적 논증에서 나온다. 상태에 **"몇 개를 골랐는가"** 를 넣는 순간 이 비용이 발생한다는 것을 기억하라.
>
> **공간의 실전 감각:** 트리 DP의 공간은 대개 `O(N)`으로 안전하지만, **재귀 스택이 `O(h)`** 라는 것을 잊지 마라. 체인 트리에서 `h = N`이면 재귀 스택만으로 메모리가 커진다. 반복 버전은 **명시적 스택도 `O(h)`** 지만 파이썬 프레임보다 훨씬 가볍다.

> [!tip]- 💡 이해를 돕는 팁 (Tips)
> - **암기 문장 셋.** **"자식의 요약본을 부모가 합친다."** / **"올려보내는 값과 정답은 다르다."** / **"모든 노드가 루트라면 리루팅."** 이 세 줄이 오늘의 90%다.
> - **트리 DP 설계는 세 질문으로 끝난다.** **① 상태를 무엇으로 잡을까**(서브트리 + 부가 상태), **② 자식의 무엇을 알면 내 답이 정해지나**(= 올려보낼 요약본), **③ 정답은 어디서 확정되나**(루트에서? 모든 노드에서?). **③을 먼저 정하면 경로형에서 헤매지 않는다.**
> - **"루트에서 답이 나오는가, 모든 노드에서 나오는가"를 구분하라.** #337은 **루트에서** 확정된다(`max(dp[root][0], dp[root][1])`). #543·#124는 **모든 노드에서 후보를 만들어 최댓값을 취한다.** 이 차이가 `return`과 `best` 갱신을 분리해야 하는 이유다.
> - **지름은 두 가지 방법을 다 알아 두라.** ① **트리 DP**(각 노드에서 자식 깊이 상위 2개의 합), ② **BFS 두 번**(아무 노드에서 가장 먼 노드 `u`를 찾고, `u`에서 가장 먼 노드까지가 지름). ②는 **가중치가 모두 음이 아닐 때만** 성립하며 증명이 필요하다. **음수 가중치가 섞이면 ①만 옳다.** 두 방법을 서로 **교차 검증**하는 데 쓰면 좋다.
> - **#124에서 `max(gain, 0)`을 빼먹지 마라.** 음수 가지를 붙이는 것은 언제나 손해다. 그리고 **`best`의 초깃값은 `0`이 아니라 `-inf`** 다 — `root = [-3]`이면 답이 `-3`이지 `0`이 아니다. **이 두 개가 #124 오답의 대부분**이다.
> - **자식이 여럿일 때는 "상위 2개"만 유지하라.** 경로형에서 정렬(`sorted(...)[-2:]`)을 쓰면 자식이 많은 노드에서 `O(C log C)`가 되지만, `top1`/`top2`를 갱신하면 `O(C)`다. 코드도 짧다.
> - **리루팅의 신호는 문구다.** **"모든 노드에 대해", "각 정점을 루트로 했을 때", "각 노드를 제거했을 때"** 라는 표현이 보이면 리루팅(또는 서브트리 크기 트릭)을 의심하라. `O(N²)`이 통과하지 못하는 제약이 함께 있으면 확정이다.
> - **리루팅에서 "뺄 수 있는 연산인가"를 먼저 확인하라.** 합·개수는 **전체에서 빼면 끝**(`O(1)`)이다. `max`·`min`·`gcd`는 **뺄 수 없다** → **상위 2개 유지** 또는 **접두사·접미사 배열**로 우회한다. [[day-14-prefix-sum/concept|Day 14]]의 "빼기가 되는 연산에만 누적 합이 통한다"가 똑같이 적용된다.
> - **`children` 리스트를 만들지 않아도 된다.** 무향 인접 리스트에서 `for w in adj[v]: if w == parent[v]: continue`면 충분하다. 다만 **다중 간선이나 자기 루프가 있는 입력**(트리라면 없어야 정상)에서는 이 방식이 깨지므로 문제의 보장을 확인하라.
> - **`reversed(order)` 관용구를 손에 익혀라.** [[day-43-lca/concept|Day 43]]에서 예고한 그것이다. **BFS로 만든 순서를 뒤집으면 후위 순회**이며, 재귀 없이 트리 DP 전체를 굴릴 수 있다. **파이썬 트리 문제의 표준 시작점**으로 삼아라.
> - **DP인지 탐색인지 먼저 판별하라.** **"서브트리 안의 결정이 밖과 무관한가"** 를 물어라. [양과 늑대(#92343)](https://school.programmers.co.kr/learn/courses/30/lessons/92343)처럼 **방문 순서와 전역 상태가 얽히면 DP가 아니다.** 그리고 그 신호는 대개 **작은 제약**(`n ≤ 17`)으로 나타난다. ([트리 패턴 정리 — LeetCode 토론](https://leetcode.com/discuss/post/5020529/master-tree-patterns/))
> - **#968은 그리디로도 풀리지만 DP가 안전하다.** 그리디("아직 감시 안 된 잎이 보이면 그 부모에 카메라")는 짧지만 **왜 최적인지 논증이 필요**하다. 면접에서는 **3-state DP로 설명하고 그리디를 최적화로 덧붙이는** 순서가 좋다.
> - **작은 트리로 손으로 검산하는 습관.** 노드 3~5개짜리 트리에서 `dp` 표를 손으로 채워 보라. **잎(leaf)의 초기값이 맞는지**가 대부분의 버그를 잡는다. 특히 **`None`/빈 서브트리의 값**을 `0`으로 둘지 `INF`/`-inf`로 둘지가 문제마다 다르다.
> - **무작위 트리 교차 검증.** `parent[i] = randint(0, i-1)`로 만들면 **항상 유효한 트리**가 나온다([[day-43-lca/concept|Day 43]]와 동일한 트릭). 그 위에서 **나이브(각 노드에서 BFS) vs 트리 DP** 결과를 대조하라 — 리루팅 구현 확신은 이렇게만 얻어진다. ([트리 문제 모음 — LeetCode 토론](https://leetcode.com/discuss/post/5072269/All-Trees-Questions/))
> - **트리 DP는 "그래프 DP의 가장 쉬운 경우"다.** 일반 DAG에서는 [[day-38-topological-sort/concept|위상 정렬(Day 38)]]로 순서를 먼저 만들어야 하고, 사이클이 있는 그래프에서는 DP 자체가 성립하지 않아 [[day-34-dijkstra/concept|다익스트라]]·[[day-35-bellman-floyd/concept|벨만-포드]] 같은 다른 도구가 필요하다. **오늘 배운 것은 "순서가 공짜인 DP"** 라는 위치를 기억하라.

> [!warning]- ⚠️ 개발자 필수 상식 (Must-Know)
> 1. **경로형에서 `return`값과 정답 갱신을 반드시 분리하라.** 부모에게는 **"한 갈래로만 내려가는 최선"**(`node.val + max(left, right)`)을 주고, 정답에는 **"여기서 꺾이는 최선"**(`node.val + left + right`)을 기록한다. **이 둘을 같게 쓰면 #543·#124 전부 틀린다.** 이 주제 최다 오답이다.
> 2. **#124에서 음수 가지는 `max(gain, 0)`으로 잘라라.** 그리고 **답의 초깃값은 `-inf`** 다. `0`으로 두면 모든 값이 음수인 트리에서 `0`을 답한다.
> 3. **#543의 답은 "간선 수"** 다. 노드 수가 아니다. `down[c] + 1`로 간선을 세고, 두 갈래를 더한 값이 그대로 답이다. **`+1`을 어디에 붙이는지**로 1씩 틀리는 것이 이 문제 단골 실수다.
> 4. **`dp[v][1]`(쓰는 경우)에는 자식의 `dp[c][0]`만 더한다.** `max`를 쓰면 인접한 두 노드를 같이 고르는 오답이 된다. 반대로 `dp[v][0]`에는 **반드시 `max(dp[c][0], dp[c][1])`** 이다 — `dp[c][1]`만 쓰면 자식을 강제로 고르게 된다.
> 5. **잎(leaf)과 빈 노드(None)의 초기값을 정확히 정하라.** 문제마다 다르다: 높이는 `None → 0` 또는 `-1`, 카메라는 `None → (INF, 0, 0)`, 경로 합은 `None → 0`. **`INF`를 써야 할 자리에 `0`을 쓰면 "불가능한 상태"가 최적으로 선택되어 조용히 틀린다.**
> 6. **`C[root]`(부모가 책임지는 상태)를 답에 넣으면 안 된다.** #968에서 루트 위에는 부모가 없다. **경계 상태를 답에서 제외**하는 처리는 다중 상태 DP의 공통 함정이다.
> 7. **트리 DP의 이중 루프는 `O(N²)`가 아니다.** `sum(len(children[v])) = N-1`이므로 전체가 `O(N)`이다. **이것을 몰라서 "너무 느릴 것 같다"고 다른 알고리즘을 찾는 것**이 흔한 시간 낭비다.
> 8. **"모든 노드에 대한 답"을 나이브하게 구하면 `O(N²)`다.** `N = 3·10⁴`면 이미 불가능하다. **리루팅 2-pass를 쓰라.** 1차는 `reversed(order)`, 2차는 `order`(위에서 아래로) — **순서가 정반대**라는 점이 핵심이다.
> 9. **리루팅에서 `max` 같은 "뺄 수 없는" 연산을 전체합처럼 다루지 마라.** `total - mine`은 합에서만 옳다. `max`는 **상위 2개**를 들고 다니거나 **접두사·접미사 배열**을 만들어야 한다. 이걸 틀리면 **특정 트리 모양에서만 실패**해 디버깅이 매우 어렵다.
> 10. **파이썬 재귀 한도 1000은 트리 DP에서 반드시 문제가 된다.** `N ≤ 10⁴`만 되어도 체인 입력이면 죽는다. **`sys.setrecursionlimit`은 임시방편**(C 스택 오버플로로 프로세스가 죽을 수 있다). **정석은 반복 후위 순회**다.
> 11. **무향 트리에서 "자식"을 구할 때 부모를 제외하는 것을 잊지 마라.** `for w in adj[v]`를 그대로 돌면 **부모로 되돌아가 무한 루프**에 빠진다. `if w == parent[v]: continue`가 필수다. **DFS의 `visited` 대신 `parent` 비교로 충분한 것이 트리의 특권**이다(사이클이 없으므로).
> 12. **루트를 무엇으로 잡을지 문제가 정해 주는지 확인하라.** [#834](https://leetcode.com/problems/sum-of-distances-in-tree/)처럼 **무향 트리**만 주어지면 아무 노드나(보통 `0`) 루트로 삼아도 되지만, **답이 루트 선택에 의존하는 문제**라면 리루팅이 필요하다는 신호다.
> 13. **1-based / 0-based를 섞지 마라.** 프로그래머스는 노드 번호가 `1`부터인 경우가 많고 LeetCode는 `0`부터가 흔하다. **입력을 읽는 즉시 통일**하라.
> 14. **"트리 DP인가 탐색인가"를 반드시 먼저 판단하라.** 서브트리로 분해되지 않는 문제(방문 순서 의존, 전역 상태 제약)에 트리 DP를 억지로 적용하면 **그럴듯하지만 틀린 답**이 나온다. **작은 제약(`n ≤ 20` 등)은 "지수 탐색을 허용한다"는 출제자의 신호**다.
> 15. **실무에서의 트리 DP.** **파일 시스템 용량 집계(`du`)**, **패키지 의존성 트리의 총 설치 크기**, **조직도 기반 예산·인원 롤업(roll-up)**, **DOM 트리의 레이아웃 계산**(자식 크기를 모아 부모 크기를 정한다), **컴파일러의 구문 트리(AST) 위 상수 폴딩·타입 추론**, **의사결정 트리(decision tree)의 가지치기(pruning)**, **HTML/PDF 렌더링 엔진의 박스 모델 계산**. **"계층 구조에서 아래를 모아 위를 정하는 모든 계산이 트리 DP"** 다.
> 16. **트리 DP는 상위 기법의 기반이다.** **트리 배낭**, **오일러 투어 + [[day-40-segment-tree/concept|세그먼트 트리(Day 40)]]로 서브트리 구간 질의**, **DSU on tree(small-to-large)**, **센트로이드 분할(centroid decomposition)**, **HLD(Heavy-Light Decomposition)** 가 모두 "서브트리 집계"를 전제로 한다. **오늘의 `reversed(order)` 한 줄이 그 전부의 입구**다.
> 17. **중복 계산이 없다는 것을 이해하라.** 트리 DP는 각 노드를 **정확히 한 번** 계산하므로 메모이제이션이 불필요하다. 만약 **같은 서브트리를 여러 번 계산하고 있다면 설계가 틀린 것**이다 — 대개 "자식을 구할 때 부모를 제외하지 않아 왕복"하거나 "각 노드에서 다시 전체 순회를 도는" 실수다.

> [!example]- 예제 코드 (Examples)
> ```python
> from collections import deque
>
> # ---- (0) 공통: 무향 트리에 루트를 정해 parent/depth/BFS순서 만들기 (재귀 0줄) ----
> def root_tree(adj, root=0):
>     n = len(adj)
>     parent, depth = [-1] * n, [0] * n
>     visited = [False] * n
>     visited[root] = True
>     order = [root]                      # BFS 순서: 부모가 항상 자식보다 앞
>     dq = deque([root])
>     while dq:
>         v = dq.popleft()
>         for w in adj[v]:
>             if not visited[w]:
>                 visited[w] = True
>                 parent[w] = v
>                 depth[w] = depth[v] + 1
>                 order.append(w)
>                 dq.append(w)
>     return parent, depth, order
>
>
> # ---- (1) 순수 집계형: 서브트리 크기와 가중치 합 ----
> def subtree_size_and_sum(adj, weight, root=0):
>     n = len(adj)
>     parent, _, order = root_tree(adj, root)
>     size = [1] * n
>     total = weight[:]
>     for v in reversed(order):           # 자식이 부모보다 먼저 처리된다
>         p = parent[v]
>         if p != -1:
>             size[p] += size[v]          # "밀기(push)" 스타일
>             total[p] += total[v]
>     return size, total
>
>
> # ---- (2) 경로형: 트리 지름 - 올려보내는 값 != 정답 ----
> def tree_diameter(adj, root=0):
>     n = len(adj)
>     parent, _, order = root_tree(adj, root)
>     down = [0] * n                      # v 에서 아래로 "한 갈래"만 내려가는 최장(간선 수)
>     best = 0
>     for v in reversed(order):
>         top1 = top2 = 0                 # 자식 방향 깊이 상위 2개
>         for w in adj[v]:
>             if w == parent[v]:
>                 continue
>             d = down[w] + 1
>             if d > top1:
>                 top1, top2 = d, top1
>             elif d > top2:
>                 top2 = d
>         down[v] = top1                  # 부모에게는 한 갈래만
>         if top1 + top2 > best:
>             best = top1 + top2          # 정답에는 두 갈래(= 여기서 꺾이는 경로)
>     return best
>
>
> # ---- (3) 상태 추가형: 최대 가중 독립 집합 (House Robber III 의 일반형) ----
> def max_weight_independent_set(adj, weight, root=0):
>     n = len(adj)
>     parent, _, order = root_tree(adj, root)
>     skip = [0] * n                      # v 를 안 쓴다
>     take = weight[:]                    # v 를 쓴다
>     for v in reversed(order):
>         p = parent[v]
>         if p != -1:
>             skip[p] += max(skip[v], take[v])   # 부모가 안 쓰면 자식은 자유
>             take[p] += skip[v]                 # 부모가 쓰면 자식은 못 쓴다
>     return max(skip[root], take[root])
>
>
> # ---- (4) 리루팅: 모든 노드에서 다른 모든 노드까지의 거리 합 (LeetCode #834) ----
> def sum_of_distances(n, edges):
>     adj = [[] for _ in range(n)]
>     for a, b in edges:
>         adj[a].append(b)
>         adj[b].append(a)
>     parent, _, order = root_tree(adj, 0)
>     cnt = [1] * n                       # 서브트리 노드 수
>     ans = [0] * n
>     for v in reversed(order):           # 1차: 아래에서 위로 모은다
>         p = parent[v]
>         if p != -1:
>             cnt[p] += cnt[v]
>             ans[p] += ans[v] + cnt[v]   # 자식 쪽 노드들이 간선 하나씩 더 멀어진다
>     for v in order[1:]:                 # 2차: 위에서 아래로 재루팅 (순서가 정반대!)
>         p = parent[v]
>         ans[v] = ans[p] - cnt[v] + (n - cnt[v])
>     return ans
> ```
>
> 전체 실행 파일(3-state 카메라 DP·재귀 실패 시연·나이브 교차 검증 포함) → [examples.py](examples.py)
