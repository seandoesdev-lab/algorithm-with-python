## 1. Lowest Common Ancestor of a BST 🟢

**출처:** [LeetCode #235](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-search-tree/)

**이진 탐색 트리(BST)** 의 루트와 두 노드 `p`, `q`가 주어진다. 두 노드의 **최소 공통 조상(LCA)** 을 반환하라.

문제의 LCA 정의는 이렇다: **`p`와 `q`를 모두 자손으로 갖는 노드 중 가장 깊은 것**. 그리고 **"노드는 자기 자신의 자손으로 간주한다"**(a node can be a descendant of itself).

**예시:**
```
         6
       /   \
      2     8
     / \   / \
    0   4 7   9
       / \
      3   5
```
- `p = 2`, `q = 8` → `6` (루트에서 갈라진다)
- `p = 2`, `q = 4` → **`2`** (2가 4의 조상. **자기 자신도 조상으로 센다**)

**제약:** 노드 수 `[2, 10^5]`, `-10^9 <= Node.val <= 10^9`, 모든 값은 **서로 다르다**, `p != q`, `p`와 `q`는 **반드시 트리에 존재**한다.

**시그니처 (LeetCode):**
```python
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode': ...
```

> [!tip]- 힌트 1 (BST의 정렬 성질을 쓰지 않으면 절반만 푼 것이다)
> BST에서는 **모든 왼쪽 서브트리 값 < 노드 값 < 모든 오른쪽 서브트리 값**이다. 이 성질만으로 **탐색 방향이 결정된다.**
> ```
>   현재 노드 c 에서
>     p.val < c.val  이고  q.val < c.val   ->  둘 다 왼쪽    ->  c = c.left
>     p.val > c.val  이고  q.val > c.val   ->  둘 다 오른쪽  ->  c = c.right
>     그 외                                ->  c 가 LCA다!
> ```
> "그 외"에 해당하는 경우는 정확히 둘이다: **① 값이 `c`를 사이에 두고 갈라진다**, **② `c`가 `p`나 `q` 자신이다.** 두 경우 모두 **더 내려가면 한쪽을 잃으므로** 여기가 답이다.

> [!tip]- 힌트 2 (반복문으로 쓰면 공간 `O(1)`)
> ```python
> cur = root
> while cur:
>     if p.val < cur.val and q.val < cur.val:
>         cur = cur.left
>     elif p.val > cur.val and q.val > cur.val:
>         cur = cur.right
>     else:
>         return cur
> ```
> **재귀 스택조차 필요 없다.** 노드가 `10^5`이고 **한쪽으로 치우친 BST**(정렬된 값을 순서대로 삽입한 경우)라면 `h = 10^5`가 되어 **재귀는 `RecursionError`로 죽는다.** 반복문이 정답이다.

> [!tip]- 힌트 3 (부등호를 `<=`로 쓰지 마라)
> 값이 모두 서로 다르고 `p != q`이므로 `<`와 `>`로 충분하다. `<=`를 쓰면 **`c`가 `p`나 `q`일 때 잘못 내려가** 답을 지나친다.
> `p = 2, q = 4`에서 `c = 2`일 때: `2 < 2`는 거짓이므로 첫 조건 실패, `2 > 2`가 거짓이므로 둘째 조건도 실패 → **`return 2`**. 정확하다.

> [!tip]- 힌트 4 (p, q의 대소를 미리 정리하면 조건이 짧아진다)
> ```python
> lo, hi = min(p.val, q.val), max(p.val, q.val)
> cur = root
> while not (lo <= cur.val <= hi):        # 구간 [lo, hi] 를 벗어나 있으면 계속 내려간다
>     cur = cur.left if cur.val > hi else cur.right
> return cur
> ```
> **"두 값이 만드는 구간 `[lo, hi]`에 처음으로 들어오는 노드가 LCA"** 라는 관점이다. 같은 알고리즘의 더 예쁜 표현이고, **면접에서 설명하기 좋다.**

> [!warning]- 흔한 실수
> - **#236의 범용 해법을 그대로 쓰기.** 통과는 하지만 **`O(N)` vs `O(h)`** 로 손해다. BST 문제에서 정렬 성질을 안 쓰는 것은 감점 포인트다.
> - **`<=` / `>=` 사용** → `c`가 `p`나 `q` 자신일 때 지나친다.
> - **"자기 자신도 조상"을 놓치기** → `p=2, q=4`에서 `6`을 반환하는 오답. **이 주제 최다 오답이다.**
> - **깊은 BST에서 재귀** → 치우친 트리(`h = 10^5`)에서 `RecursionError`. 반복문으로 짜라.
> - **값 대신 노드 객체만 비교하기.** `p is cur`도 맞지만, 이 문제는 **값 비교가 알고리즘의 핵심**이다. 값을 써라.

**복잡도 목표:** `O(h)` 시간, `O(1)` 공간(반복문).

## 2. Lowest Common Ancestor of a Binary Tree 🟡

**출처:** [LeetCode #236](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree/)

**일반 이진 트리**(BST가 아니다!)의 루트와 두 노드 `p`, `q`가 주어진다. 두 노드의 LCA를 반환하라. 자기 자신도 자손으로 간주한다.

**예시:**
```
         3
       /   \
      5     1
     / \   / \
    6   2 0   8
       / \
      7   4
```
- `p = 5`, `q = 1` → `3`
- `p = 5`, `q = 4` → **`5`** (5가 4의 조상)

**제약:** 노드 수 `[2, 10^5]`, `-10^9 < Node.val < 10^9`, 모든 값은 서로 다르다, `p != q`, **`p`와 `q`는 반드시 트리에 존재한다.**

**시그니처 (LeetCode):**
```python
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode': ...
```

> [!tip]- 힌트 1 ("각 노드가 부모에게 보내는 보고서"로 생각하라)
> BST가 아니므로 **값으로는 방향을 알 수 없다.** 트리 전체를 봐야 한다. 그러나 **"각 노드가 무엇을 부모에게 보고하는가"** 로 재정의하면 놀랍게 짧아진다.
> ```
>   보고 규칙:
>     내 서브트리에서 p 나 q 를 찾았다  ->  찾은 노드(또는 이미 정해진 LCA)를 올려보낸다
>     아무것도 못 찾았다               ->  None 을 올려보낸다
>
>   판정:
>     왼쪽 O, 오른쪽 O  ->  p 와 q 가 서로 다른 가지에 있다  ->  내가 LCA!
>     한쪽만 O          ->  그 보고를 그대로 위로 전달
>     둘 다 X           ->  None 전달
> ```
> **후위 순회(post-order)** 여야 한다: 자식의 답을 먼저 알아야 내 답이 정해진다.

> [!tip]- 힌트 2 (코드는 6줄이다)
> ```python
> def lowestCommonAncestor(self, root, p, q):
>     if root is None or root is p or root is q:
>         return root
>     L = self.lowestCommonAncestor(root.left, p, q)
>     R = self.lowestCommonAncestor(root.right, p, q)
>     if L and R:
>         return root
>     return L or R
> ```
> **첫 줄이 "자기 자신도 조상"을 처리한다.** `root is p`면 즉시 `p`를 올려보내고 더 내려가지 않는다 — `q`가 그 아래에 있으면 `p`가 조상이므로 `p`가 정답이고, 아래에 없으면 다른 가지에서 발견되어 상위에서 갈라짐이 잡힌다.
>
> **`L or R`을 쓰는 이유:** 둘 중 하나만 `None`이 아니면 그것을 반환하고, 둘 다 `None`이면 `None`을 반환한다. `if L: return L; return R`과 같다.

> [!tip]- 힌트 3 (⚠️ 이 코드의 숨은 가정을 알고 있어라)
> 이 6줄은 **`p`와 `q`가 둘 다 트리에 존재한다**고 가정한다. 하나만 있으면 **있는 쪽 하나를 반환**해 버린다.
> ```
>   트리에 p 만 있고 q 는 없다면?
>     -> 이 코드는 p 를 반환한다. 하지만 정답은 "LCA 없음(None)" 이어야 한다.
>
>   존재가 보장되지 않는 변형(LCA II)에서는:
>     찾은 개수를 세거나, 미리 두 노드가 다 있는지 확인한 뒤 이 함수를 호출한다
> ```
> **#236은 제약이 존재를 보장하므로 통과한다.** 그러나 **면접에서 "만약 없을 수도 있다면?"** 을 반드시 묻는다. 답을 준비해 두라.

> [!tip]- 힌트 4 (재귀 없는 버전 — 파이썬에서는 이게 더 안전하다)
> 노드가 `10^5`이고 **한쪽으로 늘어진 트리**면 재귀는 `RecursionError`로 죽는다. 반복문 버전:
> ```
>   1) BFS/스택 DFS 로 parent 맵을 만든다  (각 노드 -> 부모)
>   2) p 에서 루트까지 올라가며 조상을 set 에 담는다
>   3) q 에서 루트까지 올라가며 set 에 처음 있는 노드가 LCA다
>
>   시간 O(N), 공간 O(N).  재귀 0줄.
> ```
> **`p`와 `q`를 둘 다 발견하면 순회를 중단**하는 최적화도 가능하다.

> [!tip]- 힌트 5 (교차 검증하라)
> 두 방식(재귀 / `parent` 맵)을 모두 구현해 **무작위 이진 트리 + 모든 노드 쌍**으로 대조하라.
> 특히 **① `p`가 `q`의 조상**, **② `p`와 `q`가 완전히 다른 가지**, **③ 루트가 답** 세 케이스가 다 나오는지 확인하라.

> [!warning]- 흔한 실수
> - **`root.val == p.val` 대신 `root is p`를 안 쓰기.** 값이 유일하므로 이 문제에서는 둘 다 되지만, **값이 중복될 수 있는 변형에서는 객체 비교(`is`)가 맞다.**
> - **`if L and R: return root`를 빼먹기** → 갈라지는 지점을 못 찾고 한쪽만 계속 올라간다.
> - **전위 순회로 짜려 하기.** 자식의 결과가 필요하므로 **반드시 후위**다.
> - **`p`나 `q`를 만나도 계속 내려가기.** 첫 줄에서 즉시 반환해야 "자기 자신도 조상"이 성립한다.
> - **깊은 트리에서 재귀** → `RecursionError`. `N ≤ 10^5`이므로 실제 위험하다.

**복잡도 목표:** `O(N)` 시간, `O(h)`(재귀) 또는 `O(N)`(`parent` 맵) 공간.

## 3. Lowest Common Ancestor of Deepest Leaves 🟡

**출처:** [LeetCode #1123](https://leetcode.com/problems/lowest-common-ancestor-of-deepest-leaves/)

이진 트리의 루트가 주어진다. **가장 깊은 잎(deepest leaves)들의 LCA**를 반환하라.

- 루트의 깊이는 `0`이고, 깊이 `d`인 노드의 자식은 깊이 `d+1`이다.
- 여러 노드의 LCA는 **모든 노드가 그 서브트리 안에 들어가는 노드 중 가장 깊은 것**이다.

**예시:**
```
         3
       /   \
      5     1
     / \   / \
    6   2 0   8
       / \
      7   4
```
- 최대 깊이는 `3`이고 그 깊이의 잎은 `7`, `4`다. → 답은 **`2`** (서브트리 `[2,7,4]`)
- `root = [1]` → `1` (잎이 하나면 자기 자신)
- `root = [0,1,3,null,2]` → `2` (최심 잎이 `2` 하나뿐)

**제약:** 노드 수 `[1, 1000]`, `0 <= Node.val <= 1000`, 값은 서로 다르다.

**시그니처 (LeetCode):**
```python
class Solution:
    def lcaDeepestLeaves(self, root: 'TreeNode') -> 'TreeNode': ...
```

> [!tip]- 힌트 1 (문제를 다시 쓰면 절반이 풀린다)
> "가장 깊은 잎들의 LCA"는 다르게 말하면 **"왼쪽 서브트리와 오른쪽 서브트리의 높이가 같아지는, 가장 깊은 노드"** 다.
> ```
>   어떤 노드 v 에서
>     왼쪽 높이 > 오른쪽 높이  ->  최심 잎이 전부 왼쪽에 있다   ->  답은 왼쪽 아래
>     왼쪽 높이 < 오른쪽 높이  ->  전부 오른쪽                 ->  답은 오른쪽 아래
>     왼쪽 높이 == 오른쪽 높이 ->  양쪽에 최심 잎이 있다        ->  v 가 답!
> ```
> **양쪽 높이가 같은 순간이 곧 "갈라지는 지점"** 이고, 그것이 LCA의 정의다.

> [!tip]- 힌트 2 (한 번의 DFS로 두 값을 동시에 올려보낸다 — 오늘의 트리 DP 패턴)
> 각 노드가 **`(내 서브트리의 높이, 내 서브트리 안 최심 잎들의 LCA)`** 튜플을 반환하게 하라.
> ```python
> def dfs(node):
>     if not node:
>         return 0, None                     # (높이, LCA)
>     hl, al = dfs(node.left)
>     hr, ar = dfs(node.right)
>     if hl == hr:
>         return hl + 1, node                # 양쪽이 같다 -> 내가 답
>     if hl > hr:
>         return hl + 1, al                  # 왼쪽이 깊다 -> 왼쪽 답을 그대로 올린다
>     return hr + 1, ar
>
> return dfs(root)[1]
> ```
> **`O(N)` 한 번의 순회로 끝난다.** #236과 골격이 똑같다는 것을 보라 — **"자식의 보고를 합쳐 내 보고를 만든다"**.
>
> `hl == hr == 0`(잎)일 때 `(1, node)`를 반환하는 것이 **잎 자기 자신이 답인 경우**를 자연스럽게 처리한다.

> [!tip]- 힌트 3 (2-pass 해법도 알아 두라)
> 더 직관적이지만 두 번 순회한다:
> ```
>   1) 먼저 전체 최대 깊이 D 를 구한다
>   2) 다시 DFS 하면서 "이 서브트리에 깊이 D 의 노드가 있는가" 를 판정하고,
>      양쪽 다 있으면 자신이 답, 한쪽만 있으면 그쪽으로 내려간다
> ```
> **1-pass가 더 우아하지만, 2-pass가 더 설명하기 쉽다.** 면접에서는 2-pass로 먼저 말하고 1-pass로 최적화하는 흐름이 좋다. 그리고 **두 구현을 교차 검증**하면 확신이 생긴다.

> [!tip]- 힌트 4 (같은 문제가 두 번 출제되어 있다)
> [Smallest Subtree with all the Deepest Nodes (#865)](https://leetcode.com/problems/smallest-subtree-with-all-the-deepest-nodes/)가 **#1123과 완전히 같은 문제**다(제목만 다르다). 한쪽을 풀면 다른 쪽도 같은 코드로 통과한다. **"가장 깊은 노드들을 모두 담는 최소 서브트리" = "가장 깊은 잎들의 LCA"** 라는 두 표현이 같다는 것을 이해하면 좋다.

> [!warning]- 흔한 실수
> - **"높이"와 "깊이"를 섞기.** 여기서 반환하는 것은 **서브트리의 높이**(아래로 몇 칸)다. 깊이(위에서 몇 칸)와 혼동하면 비교 방향이 뒤집힌다.
> - **빈 노드에 `0`이 아니라 `-1`을 반환하기.** 무엇을 쓰든 **일관되게** 쓰면 되지만, `hl == hr` 비교가 성립해야 한다. `None → 0`, 잎 → `1`이 가장 헷갈리지 않는다.
> - **`hl == hr`일 때 자식을 올려보내기** → 갈라지는 지점을 지나쳐 버린다. **자신을 올려보내야** 한다.
> - **노드가 1개일 때** 자기 자신을 반환해야 한다. 위 코드는 자연스럽게 처리하지만 반드시 테스트하라.
> - **최심 잎이 하나뿐인 경우.** 그 잎 자신이 답이다(`[0,1,3,null,2]` → `2`). 높이가 한쪽만 깊은 경로를 계속 따라 내려가면 자동으로 잎에 도달한다.

**복잡도 목표:** `O(N)` 시간, `O(h)` 공간.

## 4. 합승 택시 요금 ⚫ (2021 카카오 블라인드 채용)

**출처:** [프로그래머스 #72413](https://school.programmers.co.kr/learn/courses/30/lessons/72413)

A와 B가 **같은 지점 `s`에서 출발**해 각각 `a`, `b`로 가려 한다. 처음 얼마간은 **합승**해서 요금을 나눠 내고, 어느 지점에서 **갈라져** 각자 이동한다.

지점 수 `n`, 출발 지점 `s`, A의 도착지 `a`, B의 도착지 `b`, 그리고 지점 사이 택시 요금 `fares`가 주어질 때 **최저 예상 택시요금**을 반환하라.

- `fares[i] = [c, d, f]`는 `c`와 `d` 사이를 이동하는 요금이 `f`라는 뜻이다(**양방향**).
- **합승을 아예 하지 않는 것이 더 싸다면 합승하지 않아도 된다.**

**예시:**

| n | s | a | b | fares | 답 |
|---|---|---|---|---|---|
| 6 | 4 | 6 | 2 | `[[4,1,10],[3,5,24],[5,6,2],[3,1,41],[5,1,24],[4,6,50],[2,4,66],[2,3,22],[1,6,25]]` | `82` |
| 7 | 3 | 4 | 1 | `[[5,7,9],[4,6,4],[3,6,1],[3,2,3],[2,1,6]]` | `14` |
| 6 | 4 | 5 | 6 | `[[2,6,6],[6,3,7],[4,6,7],[6,5,11],[2,5,12],[5,3,20],[2,4,8]]` | `18` |

**제약:** `3 <= n <= 200`, `1 <= s, a, b <= n`, `2 <= fares.length <= n(n-1)/2`, `1 <= f <= 100,000`.

**시그니처 (프로그래머스):**
```python
def solution(n, s, a, b, fares):
    return answer
```

> [!tip]- 힌트 1 (이것이 왜 오늘 배치되었는가 — "분기점"이라는 사고)
> 이 문제의 구조는 **LCA와 정확히 같은 모양**이다.
> ```
>   s 에서 함께 가다가 지점 c 에서 갈라져 각각 a, b 로 간다
>
>          s
>          |         <- 합승 구간 (s ~ c)
>          c         <- 갈라지는 지점 = "분기점"
>         / \
>        a   b
>
>   총 요금 = dist(s, c) + dist(c, a) + dist(c, b)
> ```
> **트리라면 `c = LCA(a, b)`로 즉시 정해진다.** 그런데 이 문제는 **일반 그래프**(사이클이 있고 경로가 여럿)라서 `c`가 유일하게 정해지지 않는다.
>
> **그래서 `c`를 모든 지점에 대해 전수 조사한다.** `n <= 200`이므로 200번 시도해도 무료다.
> ```python
> answer = min(d[s][c] + d[c][a] + d[c][b] for c in range(1, n+1))
> ```
> **"트리면 LCA, 일반 그래프면 분기점 완전 탐색 + 전체 최단 거리"** — 이 대응 관계가 오늘의 교훈이다.

> [!tip]- 힌트 2 (합승을 안 하는 경우도 자동으로 포함된다)
> 문제는 "합승을 안 해도 된다"고 하는데, **별도 처리가 필요 없다.**
> ```
>   c = s 로 두면:  d[s][s] + d[s][a] + d[s][b] = 0 + d[s][a] + d[s][b]
>                   = 각자 따로 가는 요금!
> ```
> **`c`의 전수 조사에 `c = s`가 이미 포함**되어 있으므로 자동으로 커버된다. **"특수 케이스가 일반 케이스의 한 인스턴스인지 확인하라"** 는 좋은 습관이다.

> [!tip]- 힌트 3 (모든 쌍 최단 거리 → 플로이드-워셜)
> `d[i][j]`(모든 쌍 최단 거리)가 필요하므로 [[day-35-bellman-floyd/concept|플로이드-워셜(Day 35)]]이 딱 맞다.
> ```python
> INF = float('inf')
> d = [[INF] * (n+1) for _ in range(n+1)]
> for i in range(1, n+1):
>     d[i][i] = 0
> for c, e, f in fares:
>     d[c][e] = min(d[c][e], f)        # 중복 간선 대비 min
>     d[e][c] = min(d[e][c], f)        # 양방향!
>
> for k in range(1, n+1):              # 경유지 k 가 가장 바깥 루프!
>     for i in range(1, n+1):
>         for j in range(1, n+1):
>             if d[i][k] + d[k][j] < d[i][j]:
>                 d[i][j] = d[i][k] + d[k][j]
> ```
> `n = 200`이면 `200³ = 8×10^6` — **파이썬에서도 충분하다.** 다만 내부 루프를 리스트 지역 변수로 빼면 훨씬 빨라진다(`solutions.py` 참고).
>
> **`k`가 가장 바깥이어야 한다.** 이 순서를 틀리는 것이 플로이드 최다 버그다.

> [!tip]- 힌트 4 (다익스트라 3회로도 된다 — 사실 이게 더 빠르다)
> 필요한 것은 `d[s][*]`, `d[a][*]`, `d[b][*]` **세 줄뿐**이다. 모든 쌍이 필요한 게 아니다!
> ```
>   dijkstra(s), dijkstra(a), dijkstra(b)  ->  3회
>   answer = min(ds[c] + da[c] + db[c] for c in 1..n)
>
>   왜 da[c] 가 d[c][a] 와 같은가:  무향 그래프이므로 대칭이다
> ```
> **`O(3 · E log V)`** 로 플로이드의 `O(n³)`보다 훨씬 빠르다. 이 문제는 `n`이 작아 둘 다 통과하지만, **`n`이 크게 늘어나면 다익스트라만 살아남는다.** [[day-34-dijkstra/concept|Day 34]]와 [[day-35-bellman-floyd/concept|Day 35]]의 역할 분담을 여기서 체감하라.

> [!tip]- 힌트 5 (1-based 인덱스에 주의하라)
> 지점 번호가 **1부터 `n`까지**다. 배열을 `n+1` 크기로 잡고 인덱스 `0`을 버리는 것이 가장 안전하다. **프로그래머스 문제에서 1-based는 매우 흔하다.**

> [!warning]- 흔한 실수
> - **플로이드에서 `k` 루프를 안쪽에 두기** → 조용히 틀린 답. **`k`가 가장 바깥이다.**
> - **간선을 한 방향만 넣기** → `fares`는 양방향이다. 둘 다 넣어라.
> - **중복 간선을 `min` 없이 덮어쓰기** → 더 비싼 간선이 남을 수 있다. `d[c][e] = min(d[c][e], f)`로 방어하라.
> - **`d[i][i] = 0` 초기화 누락** → `c = s`, `c = a`, `c = b` 케이스가 `INF`가 되어 최솟값을 놓친다.
> - **`c`의 범위를 `a`, `b`, `s`로만 제한하기** → **모든 지점**이 분기점 후보다. 세 번째 예시(답 `18`)가 정확히 "중간 지점에서 갈라지는" 케이스다.
> - **0-based로 착각** → 인덱스 에러 또는 조용한 오답.

**복잡도 목표:** 플로이드 `O(n³)` 또는 다익스트라 `O(3 · E log V)`. 둘 다 제약 내에서 충분하다.

## 5. Step-By-Step Directions From a Binary Tree Node to Another 🔴

**출처:** [LeetCode #2096](https://leetcode.com/problems/step-by-step-directions-from-a-binary-tree-node-to-another/)

`n`개 노드의 이진 트리가 주어지고, 각 노드에는 `1`부터 `n`까지의 **서로 다른 값**이 할당되어 있다. `startValue`인 노드에서 `destValue`인 노드까지의 **최단 경로**를 나타내는 문자열을 반환하라.

문자열은 `'L'`, `'R'`, `'U'` 로만 구성된다:
- `'L'` — 왼쪽 자식으로 이동
- `'R'` — 오른쪽 자식으로 이동
- `'U'` — 부모로 이동

**예시:**
```
       5
     /   \
    1     2
   /     / \
  3     6   4
```
- `startValue = 3`, `destValue = 6` → `"UURL"`
  (3 → 1 → 5 → 2 → 6: 위, 위, 오른쪽, 왼쪽)
- `root = [2,1]`, `startValue = 2`, `destValue = 1` → `"L"`

**제약:** 노드 수 `[2, 10^5]`, `1 <= Node.val <= n`, 모든 값은 서로 다르다, `startValue != destValue`, 둘 다 트리에 존재한다.

**시그니처 (LeetCode):**
```python
class Solution:
    def getDirections(self, root: 'TreeNode', startValue: int, destValue: int) -> str: ...
```

> [!tip]- 힌트 1 (트리의 최단 경로는 하나뿐이다 — LCA에서 꺾인다)
> "최단 경로"라는 말에 속지 마라. **트리에서 두 노드를 잇는 경로는 애초에 하나뿐**이고, 그것이 최단이다. 그리고 그 경로는 **LCA에서 꺾인다.**
> ```
>   start ---(위로)---> LCA ---(아래로)---> dest
>
>   위로 가는 부분은 전부 'U' 다 (몇 칸인지만 중요)
>   아래로 가는 부분은 LCA 에서 dest 까지의 'L'/'R' 문자열이다
> ```
> 따라서 답은 **`'U' × (start에서 LCA까지 거리) + (LCA에서 dest까지의 방향 문자열)`** 이다.

> [!tip]- 힌트 2 (오늘의 예쁜 통찰 — LCA를 명시적으로 구하지 않아도 된다)
> **루트에서 각 노드까지의 경로 문자열**을 구해 보라.
> ```
>   root -> start 경로 문자열:  ps
>   root -> dest  경로 문자열:  pd
>
>   두 문자열의 "공통 접두사"는 곧 "루트에서 LCA 까지의 경로"다!
>
>   예)  root=5, start=3, dest=6
>        ps = "LL"    (5 -> 1 -> 3)
>        pd = "RL"    (5 -> 2 -> 6)
>        공통 접두사 = ""  ->  LCA = 루트 5
>        남은 ps = "LL" (2글자)  ->  'U' 2개
>        남은 pd = "RL"
>        답 = "UU" + "RL" = "UURL"   O
> ```
> ```python
> i = 0
> while i < len(ps) and i < len(pd) and ps[i] == pd[i]:
>     i += 1                                   # 공통 접두사를 건너뛴다
> return 'U' * (len(ps) - i) + pd[i:]
> ```
> **"공통 접두사를 자르는 것이 곧 LCA를 지나치는 것"** — [[day-42-string-matching/concept|Day 42]]의 접두사 사고가 트리에서 재등장한다.

> [!tip]- 힌트 3 (경로 문자열 찾기 — 재귀 없이, 그리고 `O(N²)`를 피해서)
> `N ≤ 10^5`이고 **한쪽으로 늘어진 트리**면 재귀 DFS가 죽는다. 스택 DFS로 바꾸는 것이 첫걸음이다:
> ```python
> def find_path(root, target):
>     stack = [(root, "")]                     # (노드, 여기까지의 경로 문자열)
>     while stack:
>         node, path = stack.pop()
>         if node.val == target:
>             return path
>         if node.left:
>             stack.append((node.left, path + 'L'))
>         if node.right:
>             stack.append((node.right, path + 'R'))
>     return ""
> ```
> ⚠️ 그런데 **문자열 `+`가 `O(길이)`** 이므로 깊은 트리에서 이 자체가 `O(N²)`가 된다([[day-04-strings/concept|Day 04]]).
> **정석은 `parent` 맵 + `dir` 맵을 만들고, 대상에서 루트로 거슬러 올라가 뒤집는 것**이다 — 각 노드를 정확히 한 번만 방문하므로 `O(N)`이 보장된다. `solutions.py`가 이 방식을 쓴다.

> [!tip]- 힌트 4 (명시적 LCA 해법도 구현해 보라)
> 접두사 트릭은 우아하지만, **LCA를 직접 구하는 정석 해법**도 손에 익혀 두라.
> ```
>   1) #236 방식으로 LCA 노드를 찾는다
>   2) LCA 에서 start 까지의 거리를 구해 'U' 를 그만큼
>   3) LCA 에서 dest 까지의 경로 문자열을 구해 이어 붙인다
> ```
> 두 해법을 **무작위 트리로 교차 검증**하면 확신이 생긴다. 그리고 **"어느 쪽이 더 짧고 왜인가"** 를 말할 수 있으면 좋다.

> [!tip]- 힌트 5 (답의 길이를 미리 계산해 검산하라)
> 답의 길이는 반드시 **`dist(start, dest) = depth[start] + depth[dest] - 2·depth[LCA]`** 와 같아야 한다. 구현이 끝나면 이 등식으로 **자체 검증**을 넣어 두라 — 오프바이원 버그를 즉시 잡는다.

> [!warning]- 흔한 실수
> - **`'U'`와 `'L'/'R'`의 순서를 뒤집기.** 반드시 **먼저 올라가고(`U`) 그다음 내려간다**. 트리 경로는 U자 모양이다.
> - **`'U'`의 개수를 잘못 세기.** `len(ps) - i`다. 공통 접두사 길이 `i`를 뺀 나머지가 "LCA까지 올라갈 칸 수"다.
> - **`pd`에서 접두사를 안 자르기** → `pd[i:]`가 맞다. `pd` 전체를 붙이면 루트부터 다시 내려가는 엉뚱한 경로가 된다.
> - **문자열 `+=` 누적으로 `O(N²)`** → `N = 10^5`에서 TLE. 리스트 + `join`을 쓰거나 `parent` 맵 방식으로 가라.
> - **깊은 트리에서 재귀** → `RecursionError`. 스택 DFS나 BFS를 쓰라.
> - **`startValue != destValue`를 잊고 빈 문자열 케이스를 처리하려 하기.** 제약상 다르므로 답은 항상 길이 1 이상이다.

**복잡도 목표:** `O(N)` 시간, `O(N)` 공간.

## 6. Kth Ancestor of a Tree Node 🔴

**출처:** [LeetCode #1483](https://leetcode.com/problems/kth-ancestor-of-a-tree-node/)

노드의 **`k`번째 조상**은 그 노드에서 루트까지의 경로에서 `k`번째 노드다. `n`개 노드(`0` ~ `n-1`)의 트리가 `parent` 배열로 주어지고(`parent[i]`는 `i`의 부모, 루트는 노드 `0`), `TreeAncestor` 클래스를 구현하라.

- `TreeAncestor(int n, int[] parent)` — 초기화
- `int getKthAncestor(int node, int k)` — `node`의 `k`번째 조상. **없으면 `-1`**

**예시:**
```
     0
    / \
   1   2
  /
 3
 |
 4
parent = [-1, 0, 0, 1, 3]

getKthAncestor(3, 1) -> 1      (3 의 부모)
getKthAncestor(5, 2) -> ...    (제약 내 노드에 대해)
getKthAncestor(0, 1) -> -1     (루트의 조상은 없다)
```

**제약:** `1 <= k <= n <= 5 * 10^4`, `parent.length == n`, `parent[0] == -1`, `0 <= parent[i] < n`(`i != 0`), `0 <= node < n`, **`getKthAncestor`는 최대 `5 * 10^4`번 호출**된다.

**시그니처 (LeetCode):**
```python
class TreeAncestor:
    def __init__(self, n: int, parent: List[int]): ...
    def getKthAncestor(self, node: int, k: int) -> int: ...
```

> [!tip]- 힌트 1 (제약을 읽으면 답이 나온다)
> **`n ≤ 5·10^4`이고 질의도 `5·10^4`번**이다. 그리고 **트리가 체인일 수 있다**(`parent[i] = i-1`).
> ```
>   나이브(한 칸씩 k 번):  질의당 O(k) -> 최악 O(n)
>                          전체 O(질의 수 x n) = 5·10^4 x 5·10^4 = 2.5·10^9  ->  불가능
>
>   -> "질의가 많고 트리가 깊을 수 있다" = 전처리형으로 가라는 신호다
> ```
> **이 문제는 이진 상승을 쓰라고 만들어진 문제다.** 제약을 보고 도구를 정하는 훈련의 좋은 예다.

> [!tip]- 힌트 2 (표를 만든다 — `up[j][v] = up[j-1][up[j-1][v]]`)
> ```python
> LOG = max(1, n.bit_length())              # 2^LOG > n
> up = [[-1] * n for _ in range(LOG)]
> up[0] = parent[:]                          # 기저: 1칸 위 = 직접 부모
> for j in range(1, LOG):
>     prev, cur = up[j-1], up[j]
>     for v in range(n):
>         mid = prev[v]
>         cur[v] = prev[mid] if mid != -1 else -1
> ```
> **"`2^j`칸 = `2^(j-1)`칸 뛰고 또 `2^(j-1)`칸 뛰기"** — 이 한 줄이 전부다. `-1`(루트 위)에 도달하면 그 이후는 계속 `-1`이다.
>
> 전처리 `O(n log n)` = `5·10^4 × 16 = 8×10^5`. 여유롭다.

> [!tip]- 힌트 3 (질의 — `k`를 이진수로 분해해 점프)
> ```python
> def getKthAncestor(self, node, k):
>     j = 0
>     while k and node != -1:
>         if k & 1:
>             node = self.up[j][node]        # 이 비트가 켜졌으면 2^j 점프
>         k >>= 1
>         j += 1
>     return node
> ```
> **`node != -1` 검사가 루프 조건에 있어야 한다.** 중간에 루트를 넘어가면 즉시 `-1`을 들고 나와야 하고, `-1`을 인덱스로 쓰면 파이썬에서는 **에러 없이 마지막 원소를 읽어** 조용히 틀린 답이 나온다. **이것이 이 문제 최다 버그다.**
>
> 질의당 `O(log k)` = 최대 16번 점프. 전체 `5·10^4 × 16 = 8×10^5`. 여유롭다.

> [!tip]- 힌트 4 (⚠️ `-1` 인덱싱 함정을 정확히 이해하라)
> ```python
> up = [10, 20, 30]
> up[-1]        # 30 이 나온다! 에러가 아니다.
> ```
> **파이썬의 음수 인덱스가 조용한 버그를 만든다.** C++/Java라면 즉시 크래시하지만 파이썬은 그냥 잘못된 값을 준다.
>
> **두 가지 처방:**
> 1. **`node != -1`을 매번 검사**(위 코드). 명시적이고 안전하다.
> 2. **가상 노드 `n`을 만들어** 루트의 부모로 삼고 `up[j][n] = n`(자기 루프)로 둔다. 검사가 사라져 코드가 깔끔해지고, 마지막에 `return -1 if node == n else node`만 하면 된다.
>
> 실전에서는 **2번이 버그가 덜 난다.** `solutions.py`에 두 버전을 모두 넣었다.

> [!tip]- 힌트 5 (다른 접근들)
> - **오일러 투어 + 이분 탐색** — 각 깊이별로 진입 시각(tin)을 정렬해 두고, `node`의 조상 중 깊이가 `depth[node]-k`인 것을 이분 탐색으로 찾는다. `O(log n)` 질의, `O(n)` 공간. **공간이 빡빡할 때의 대안**이다.
> - **LCA와의 관계** — `up` 표를 만들어 두면 **LCA도 공짜로 얻는다**(깊이 맞추기 → 함께 올라가기). 이 문제를 풀면 **LCA 구현이 이미 손에 들어온 것**이다.
> - **나이브를 검증용으로 반드시 만들어라.** 작은 `n`에서 `while k: node = parent[node]`와 대조하면 이진 분해 버그가 즉시 잡힌다.

> [!warning]- 흔한 실수
> - **`node == -1` 검사 누락** → 파이썬 음수 인덱싱으로 **조용히 틀린 값**이 나온다. **가장 중요한 함정이다.**
> - **`LOG`를 너무 작게 잡기** → `n = 5·10^4`이면 `LOG = 16`이 필요하다. `10`으로 잡으면 큰 `k`에서 틀린다. `n.bit_length()`를 쓰라.
> - **`up[0] = parent`(복사 없이)** → 나중에 `up[0]`를 수정하면 원본 `parent`가 오염된다. `parent[:]`로 복사하라.
> - **질의 루프에서 `j`를 증가시키지 않기** → 무한 루프 또는 잘못된 점프.
> - **`k > depth[node]`를 미리 걸러내려 하기.** `depth`를 계산하면 되지만, `node != -1` 검사만으로도 자연히 처리된다. 굳이 둘 다 할 필요는 없다.
> - **전처리를 `getKthAncestor` 안에서 하기** → 질의마다 표를 다시 만들면 전처리의 의미가 없다. **`__init__`에서 딱 한 번**이다.

**복잡도 목표:** 전처리 `O(n log n)` 시간·공간, 질의 `O(log k)`.

## 학습 순서 제안

1. **#235를 반복문으로 짜라.** BST의 정렬 성질로 **한 방향만 내려가는** `O(h)`·`O(1)` 해법이 목표다. "자기 자신도 조상"을 `p=2, q=4`로 반드시 확인하라. **이 문제에서 재귀를 쓰지 않는 습관**을 들이는 것이 오늘의 첫 소득이다.
2. **#236의 6줄을 "보고서 비유"로 이해하라.** 코드를 외우지 말고 **"양쪽에서 신호가 오면 내가 답"** 을 외워라. 그리고 **`p`나 `q`가 없을 수도 있다면 어떻게 바뀌는지**를 스스로 답해 보라 — 면접 단골 후속 질문이다. 재귀 없는 `parent` 맵 버전도 함께 짜서 대조하라.
3. **#1123으로 트리 DP의 기본형을 익혀라.** **`(높이, LCA)` 튜플을 동시에 올려보내는** 1-pass 해법이 핵심이다. 2-pass(최대 깊이 선계산)로 먼저 짜고 1-pass로 줄이는 순서가 이해에 좋다. **#865가 같은 문제**라는 것도 확인해 보라.
4. **#72413(합승 택시 요금)이 실전 하이라이트다.** **"분기점 `c`를 모든 지점에 대해 전수 조사"** 가 곧 **일반 그래프에서의 LCA 사고**다. `c = s`가 "합승 안 함"을 자동으로 커버한다는 것을 확인하라. 플로이드와 다익스트라 두 버전을 모두 짜고 **왜 다익스트라가 더 빠른지** 말할 수 있게 하라.
5. **#2096으로 "공통 접두사 = LCA" 통찰을 얻어라.** 경로 문자열 두 개의 접두사를 자르는 것만으로 LCA를 우회한다. **답의 길이가 `dist` 공식과 일치하는지** 자체 검증을 넣어라. 문자열 `+=` 누적으로 `O(N²)`가 되지 않게 주의하라.
6. **#1483으로 이진 상승을 완성하라.** 오늘의 정수다. **`node != -1` 검사**(또는 가상 노드)를 반드시 넣고, **나이브와 소규모 교차 검증**하라. 이 표를 손에 익히면 **LCA·`k`번째 조상·경로 집계가 모두 같은 도구로 풀린다.**
