## 1. Subsets 🟢

**출처:** [LeetCode #78](https://leetcode.com/problems/subsets/)

서로 다른 정수로 이루어진 배열 `nums`가 주어진다. **가능한 모든 부분집합(멱집합, power set)** 을 반환하라. 중복된 부분집합은 포함하지 않아야 하며, 순서는 상관없다.

**예시:** `nums = [1,2,3]` → `[[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]` (8개)

**제약:** `1 <= nums.length <= 10`, `-10 <= nums[i] <= 10`, `nums`의 원소는 모두 서로 다르다.

**시그니처 (LeetCode):**
```python
class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]: ...
```

> [!tip]- 힌트 1 (제약을 먼저 읽어라)
> `nums.length <= 10`이다. `2¹⁰ = 1024`. **출제자가 "부분집합을 전부 만들어도 된다"고 말해주고 있다.**
> 부분집합의 개수 자체가 `2ⁿ`이므로 **어떤 알고리즘을 써도 O(2ⁿ)보다 빠를 수 없다**(답을 출력하는 것만으로도 그만큼 걸린다).

> [!tip]- 힌트 2 (비트마스크 열거)
> `0`부터 `2ⁿ-1`까지의 정수가 곧 모든 부분집합이다.
> ```python
> for mask in range(1 << n):
>     subset = [nums[i] for i in range(n) if mask >> i & 1]
> ```
> **재귀도, `itertools` 중첩도 필요 없다.** `mask >> i & 1`이 "i번 원소를 포함하는가"다.

> [!tip]- 힌트 3 (다른 두 접근도 꼭 구현해 보라)
> - **백트래킹**: `dfs(start, path)`에서 `i >= start`인 원소를 하나 고르고 재귀. `path`를 매번 `list(path)`로 복사해 담는 것을 잊지 마라.
> - **누적 확장(cascading)**: `res = [[]]`로 시작해 원소 `x`마다 `res += [sub + [x] for sub in res]`. **세 줄이면 끝난다.** 반복 중에 `res`가 커지므로 스냅샷을 떠서 순회해야 한다.
>
> 세 방법의 결과를 **정렬해서 서로 비교**하면 구현 검증이 된다.

> [!warning]- 흔한 실수
> - `(1 << n)`의 괄호. `range(1 << n)`은 맞지만 `full = 1 << n - 1`이라고 쓰면 **절반만 돈다**.
> - 백트래킹에서 `path`를 복사하지 않고 `res.append(path)`를 하면 **모든 원소가 같은 리스트를 참조**해 마지막 상태로 다 덮인다.
> - `mask & (1 << i) == 1`로 비교하지 마라. 그 값은 `2^i`다.

**복잡도 목표:** O(2ⁿ · n) 시간, O(2ⁿ · n) 공간(출력 자체가 그 크기).

## 2. Sum of All Subset XOR Totals 🟢

**출처:** [LeetCode #1863](https://leetcode.com/problems/sum-of-all-subset-xor-totals/)

배열의 **XOR 총합(XOR total)** 은 그 배열 원소를 전부 XOR한 값이다(빈 배열은 0). 배열 `nums`가 주어질 때, **`nums`의 모든 부분집합에 대한 XOR 총합의 합**을 반환하라. 같은 값이 여러 개 있어도 인덱스가 다르면 다른 부분집합으로 센다.

**예시:**
- `nums = [1,3]` → `6`
  부분집합 `[]`→0, `[1]`→1, `[3]`→3, `[1,3]`→`1^3=2`. 합 = `0+1+3+2 = 6`
- `nums = [5,1,6]` → `28`
- `nums = [3,4,5,6,7,8]` → `480`

**제약:** `1 <= nums.length <= 12`, `1 <= nums[i] <= 20`.

**시그니처 (LeetCode):**
```python
class Solution:
    def subsetXORSum(self, nums: List[int]) -> int: ...
```

> [!tip]- 힌트 1 (브루트포스로 먼저 통과시켜라)
> `n <= 12`이므로 `2¹² = 4096`. **부분집합을 전부 만들어 XOR을 더해도 통과한다.**
> 문제 1의 열거 골격을 그대로 쓴다. **먼저 확실한 정답을 만들어 두는 것**이 다음 단계의 검증 기준이 된다.

> [!tip]- 힌트 2 (핵심 관찰 — 비트 자리를 하나씩 떼어 생각하라)
> 전체를 한꺼번에 보지 말고 **비트 `b` 하나만** 보자. 답에 `2^b`가 몇 번 더해지는가?
> = **"부분집합의 XOR 결과에서 비트 `b`가 1인 부분집합의 개수"**
> = **"비트 `b`를 가진 원소를 홀수 개 고른 부분집합의 개수"**

> [!tip]- 힌트 3 (절반이 되는 이유)
> 비트 `b`를 가진 원소가 `k`개(`k >= 1`), 안 가진 원소가 `n-k`개라고 하자.
> - `k`개 중에서 **홀수 개** 고르는 방법: `2^(k-1)`가지 (`k >= 1`이면 홀수 부분집합과 짝수 부분집합의 개수가 정확히 같다)
> - 나머지 `n-k`개는 자유: `2^(n-k)`가지
> - 곱하면 `2^(k-1) · 2^(n-k) = 2^(n-1)`
>
> **`k`가 사라진다!** 즉 **"하나라도 그 비트를 가진 원소가 있으면 무조건 `2^(n-1)`번"** 이고, 하나도 없으면 0번이다.
> ```
> 답 = sum over b (그 비트가 존재하면) 2^b · 2^(n-1)
>    = (nums 전체를 OR 한 값) << (n - 1)
> ```
> 세 줄, **O(n)** 이다.

> [!tip]- 힌트 4 (검증)
> 예시로 확인: `nums=[1,3]` → `1|3 = 3`, `n-1 = 1` → `3 << 1 = 6`. 맞다.
> `nums=[5,1,6]` → `5|1|6 = 7`, `7 << 2 = 28`. 맞다.
> **무작위 입력으로 힌트 1의 브루트포스와 교차 검증**하면 확신이 생긴다.

> [!warning]- 흔한 실수
> - `n = 1`일 때 `n-1 = 0`이므로 `<< 0`이다. 정상 동작하지만 **경계로 반드시 테스트**하라(답은 `nums[0]`).
> - "홀수 개 고르기 = 절반"이 성립하는 것은 **`k >= 1`일 때만**이다. `k = 0`(그 비트를 가진 원소가 없음)이면 0번이고, 이 경우가 바로 OR로 걸러진다.

**복잡도 목표:** 브루트포스 O(2ⁿ·n) → 최적 **O(n)** 시간, O(1) 공간.

## 3. Counting Bits 🟡

**출처:** [LeetCode #338](https://leetcode.com/problems/counting-bits/)

정수 `n`이 주어진다. 길이 `n+1`인 배열 `ans`를 반환하라. 각 `i`(`0 <= i <= n`)에 대해 `ans[i]`는 **`i`의 이진 표현에서 1의 개수**다.

**예시:**
- `n = 2` → `[0,1,1]` (0→`0`, 1→`1`, 2→`10`)
- `n = 5` → `[0,1,1,2,1,2]` (3→`11`, 4→`100`, 5→`101`)

**제약:** `0 <= n <= 10^5`.

**시그니처 (LeetCode):**
```python
class Solution:
    def countBits(self, n: int) -> List[int]: ...
```

> [!tip]- 힌트 1 (쉬운 답과 진짜 학습 목표)
> `[i.bit_count() for i in range(n+1)]` 또는 `[bin(i).count('1') for i in range(n+1)]`로 **바로 통과**한다.
> 그러나 이 문제의 학습 목표는 **"O(1) 추가 연산으로 각 값을 구하는 DP 점화식"** 을 찾는 것이다. LeetCode의 follow-up이 정확히 그것을 요구한다.

> [!tip]- 힌트 2 (첫 번째 분해 — 마지막 비트를 뗀다)
> `i`를 오른쪽으로 한 칸 밀면(`i >> 1`) 마지막 비트만 잃는다.
> ```
> dp[i] = dp[i >> 1] + (i & 1)
>
>   i=5 = 101  ->  i>>1 = 10 (=2, dp=1),  i&1 = 1   ->  dp[5] = 2
>   i=6 = 110  ->  i>>1 = 11 (=3, dp=2),  i&1 = 0   ->  dp[6] = 2
> ```
> `i >> 1 < i`이므로 `i`를 오름차순으로 돌면 항상 이미 계산되어 있다.

> [!tip]- 힌트 3 (두 번째 분해 — 최하위 1비트를 뗀다)
> `i & (i-1)`은 **최하위 1비트를 지운 값**이다. 1의 개수가 정확히 하나 줄어든다.
> ```
> dp[i] = dp[i & (i-1)] + 1
>
>   i=12 = 1100  ->  i&(i-1) = 1000 (=8, dp=1)  ->  dp[12] = 2
>   i=7  = 0111  ->  i&(i-1) = 0110 (=6, dp=2)  ->  dp[7]  = 3
> ```
> 이쪽이 **"popcount는 1비트를 하나씩 지우는 것"** 이라는 Brian Kernighan의 관점과 직결된다.

> [!tip]- 힌트 4 (세 번째 관점 — 2의 거듭제곱 블록)
> `dp[i] = dp[i - 2^k] + 1` (`2^k`는 `i` 이하의 가장 큰 2의 거듭제곱). `2^k <= i < 2^(k+1)` 구간의 값들은 앞 블록 `[0, 2^k)`의 값에 1을 더한 것과 같다. **`[0]` → `[1]` → `[1,2]` → `[1,2,2,3]` → …** 로 블록이 배로 늘어나는 패턴이 보인다.

> [!tip]- 힌트 5 (세 구현을 다 만들고 성능을 재라)
> `n = 10⁵`에서 `bin(i).count('1')` 방식과 DP 방식의 실측 차이를 확인하라.
> 파이썬에서는 `bit_count()`(C 구현)가 가장 빠르고, DP가 그다음, `bin()` 문자열 변환이 가장 느린 경우가 많다. **"이론상 O(1) 전이"가 파이썬 상수를 이기지 못할 수도 있다**는 것을 몸으로 아는 것도 학습이다.

> [!warning]- 흔한 실수
> - `n = 0`이면 `[0]`을 반환해야 한다. 배열 길이는 `n+1`이다.
> - `dp[i & (i-1)] + 1`을 `i = 0`에 적용하면 `dp[0] + 1 = 1`이 되어 틀린다. **`i`는 1부터 시작**해야 한다.

**복잡도 목표:** O(n) 시간, O(n) 공간(출력 포함).

## 4. 불량 사용자 ⚫ (2019 카카오 개발자 겨울 인턴십)

**출처:** [프로그래머스 #64064](https://school.programmers.co.kr/learn/courses/30/lessons/64064)

이벤트에 응모한 전체 사용자 아이디 목록 `user_id`와, 불량 사용자 아이디를 **일부 문자가 `*`로 가려진 형태**로 담은 목록 `banned_id`가 주어진다. `*` 하나는 **문자 하나**를 가린 것이며, 각 `banned_id`에는 `*`가 최소 하나 있다.

`banned_id`의 각 항목에 **서로 다른** `user_id`를 하나씩 대응시켜 만들 수 있는 **"제재 아이디 목록"** 의 경우의 수를 반환하라. 단, **제재 아이디 목록은 순서를 구분하지 않는 집합**이다 — 같은 아이디들로 이루어진 목록은 하나로 센다.

**예시:**

| user_id | banned_id | 답 |
|---|---|---|
| `["frodo","fradi","crodo","abc123","frodoc"]` | `["*rodo","*rodo","******"]` | `2` |
| `["frodo","fradi","crodo","abc123","frodoc"]` | `["fr*d*","abc1**"]` | `2` |
| `["frodo","fradi","crodo","abc123","frodoc"]` | `["fr*d*","*rodo","******","******"]` | `3` |

**제약:** `1 <= len(user_id) <= 8`, 각 아이디 길이 `4~10`, `1 <= len(banned_id) <= len(user_id)`.

**시그니처 (프로그래머스):**
```python
def solution(user_id, banned_id):
    return answer
```

> [!tip]- 힌트 1 (제약이 알려주는 것)
> **`len(user_id) <= 8`** 이다. `2⁸ = 256`. **완전 탐색을 하라는 신호**이고, 선택한 사용자 집합을 **8비트 마스크 하나**로 표현할 수 있다는 뜻이다.

> [!tip]- 힌트 2 (1단계: 패턴 매칭 후보 구하기)
> 각 `banned_id`에 대해 **매칭되는 `user_id` 인덱스 목록**을 먼저 구한다.
> ```python
> def match(uid, pattern):
>     if len(uid) != len(pattern):        # 길이가 같아야 한다 ('*' 하나 = 문자 하나)
>         return False
>     return all(p == '*' or p == c for c, p in zip(uid, pattern))
> ```
> **길이 비교를 빼먹는 것이 이 문제 최다 오답**이다. `*`는 "한 글자"이므로 `"*rodo"`는 5글자 아이디에만 매칭된다(`"frodoc"`은 6글자라 매칭되지 않는다).
>
> `re`나 `fnmatch`를 쓸 수도 있지만, `*`가 "0개 이상"이 아니라 **정확히 1개**라는 차이 때문에 직접 비교하는 편이 안전하다.

> [!tip]- 힌트 3 (2단계: 백트래킹 + 마스크로 중복 제거 — 오늘의 핵심)
> `banned_id`를 순서대로 처리하며, 각 단계에서 **아직 쓰지 않은** 후보를 하나 고른다.
> ```python
> results = set()                       # 서로 다른 "집합"들만 모인다
>
> def dfs(idx, used_mask):
>     if idx == len(banned_id):
>         results.add(used_mask)        # 마스크 정수 하나 = 집합 하나
>         return
>     for u in candidates[idx]:
>         if used_mask >> u & 1:        # 이미 이 사용자를 썼다
>             continue
>         dfs(idx + 1, used_mask | (1 << u))
>
> dfs(0, 0)
> return len(results)
> ```
> **왜 이게 중복 제거가 되는가:** `banned_id = ["*rodo","*rodo"]`처럼 같은 패턴이 두 개면 `(frodo, crodo)`와 `(crodo, frodo)`가 별개의 재귀 경로로 도달한다. 그러나 **둘 다 마스크가 같으므로** `set`에 넣으면 자동으로 하나가 된다. **"순서를 구분하지 않는다"는 문제 조건이 마스크 한 줄로 해결된다.**

> [!tip]- 힌트 4 (frozenset 대신 마스크를 쓰는 이유)
> `results.add(frozenset(chosen))`도 정답이지만, 마스크 쪽이
> - **해싱이 싸다** (정수 해시 = 자기 자신)
> - **상태 전달이 O(1)** (`used_mask | (1 << u)`는 새 정수 하나. 리스트/세트는 복사 비용이 있다)
> - **코드가 짧다** (`used` 배열의 되돌리기(`used[u] = False`)가 필요 없다 — 새 정수를 넘기므로 원본이 변하지 않는다)
>
> `n <= 8`이라 성능 차이는 무의미하지만, **"집합을 정수로"** 라는 오늘의 사고방식을 연습하는 데 딱 맞는 문제다.

> [!tip]- 힌트 5 (대안: 부분집합 전체 열거)
> `2⁸ = 256`뿐이므로 **크기가 `len(banned_id)`인 모든 부분집합을 만들고, 그 집합이 유효한 대응을 가지는지 판정**하는 방법도 된다. 판정은 각 원소를 각 패턴에 배정하는 **작은 순열 탐색 또는 이분 매칭**이다. 백트래킹 쪽이 훨씬 짧지만, **"열거 후 판정"과 "탐색 중 구성"의 두 사고방식**을 비교해 볼 가치가 있다.

> [!warning]- 흔한 실수
> - **길이 비교 누락.** `*`는 정확히 한 글자다. 길이가 다르면 매칭 불가.
> - **같은 사용자를 두 번 쓰기.** `banned_id` 항목마다 **서로 다른** 사용자여야 한다. `used_mask` 체크 필수.
> - **순서 중복을 그대로 세기.** 마스크나 `frozenset` 없이 리스트를 세면 예제 1에서 2가 아니라 4가 나온다.
> - **후보가 없는 패턴.** 어떤 `banned_id`에 매칭되는 사용자가 없으면 답은 0이다(재귀가 자연히 0을 반환한다).

**복잡도 목표:** 매칭 O(B·U·L), 탐색 최악 O(U!/(U-B)!)이지만 `U <= 8`이라 즉시 끝난다.

## 5. Shortest Path Visiting All Nodes 🔴

**출처:** [LeetCode #847](https://leetcode.com/problems/shortest-path-visiting-all-nodes/)

`n`개 노드(`0..n-1`)의 **연결된 무방향 그래프**가 인접 리스트 `graph`로 주어진다(`graph[i]`는 `i`와 인접한 노드들). **모든 노드를 방문하는 가장 짧은 경로의 길이**를 반환하라. **아무 노드에서 시작해도 되고, 노드와 간선을 여러 번 재방문해도 된다.**

**예시:**
- `graph = [[1,2,3],[0],[0],[0]]` → `4` (예: `1 → 0 → 2 → 0 → 3`)
- `graph = [[1],[0,2,4],[1,3,4],[2],[1,2]]` → `4` (예: `0 → 1 → 4 → 2 → 3`)

**제약:** `n == graph.length`, `1 <= n <= 12`, `0 <= graph[i].length < n`, 그래프는 항상 연결되어 있다.

**시그니처 (LeetCode):**
```python
class Solution:
    def shortestPathLength(self, graph: List[List[int]]) -> int: ...
```

> [!tip]- 힌트 1 (제약 = 지시문)
> `n <= 12`. `2¹² = 4096`, `12 · 4096 = 49,152`. **"방문 집합을 상태에 넣어라"** 는 뜻이다.

> [!tip]- 힌트 2 (왜 평범한 BFS가 안 되는가)
> 일반 BFS는 `visited[node]`로 재방문을 막는다. 그런데 이 문제는 **재방문이 필수**다(예시 1에서 노드 0을 세 번 지난다). `visited[node]`를 쓰면 답에 도달할 수 없고, 아예 안 쓰면 무한 루프다.
>
> **해결: "무엇을 방문했는가"를 상태에 포함시킨다.** 상태 = `(현재 노드, 지금까지 방문한 노드 집합)`. 같은 노드를 다시 밟아도 **방문 집합이 달라졌으면 다른 상태**이므로 진행이 가능하고, 상태 수가 `n · 2ⁿ`으로 유한하므로 종료도 보장된다.

> [!tip]- 힌트 3 (다중 소스 BFS)
> 시작점이 자유롭다 → **모든 노드를 동시에 시작점으로** 큐에 넣는다.
> ```python
> dq   = deque((i, 1 << i) for i in range(n))
> seen = {(i, 1 << i) for i in range(n)}
> ```
> **왜 정당한가:** BFS는 큐에 있는 모든 출발 상태로부터 거리 순으로 확장한다. 여러 소스를 동시에 넣으면 "어떤 소스에서든 도달하는 최단 거리"를 얻고, 이것이 정확히 "가장 좋은 시작점을 골랐을 때의 답"이다. 시작점마다 BFS를 따로 돌릴 필요가 없다(그래도 `n`배라 통과하긴 한다).

> [!tip]- 힌트 4 (전이와 종료)
> ```python
> goal = (1 << n) - 1
> # (u, mask) -> (v, mask | (1 << v))  for v in graph[u]
> # mask == goal 인 상태에 처음 도달했을 때의 거리가 답
> ```
> **`goal`을 처음 만나는 순간이 최단**이다(BFS의 성질). 레벨 단위로 돌리면 `steps`를 따로 저장하지 않아도 되고, `(거리, 노드, 마스크)`를 큐에 함께 넣어도 된다.

> [!tip]- 힌트 5 (경계 케이스)
> `n = 1`이면 이미 모든 노드를 방문한 상태이므로 답은 **0**이다. 시작 상태에서 `mask == goal`이 이미 성립하므로, **큐에서 꺼낼 때 goal 검사를 하면** 자연히 0이 나온다. 반대로 "꺼낸 뒤 이웃으로 확장할 때만" 검사하면 `n=1`(이웃 없음)에서 -1이 나온다 — **검사 위치가 중요하다.**

> [!warning]- 흔한 실수
> - `seen`을 `(노드)`만으로 관리 → 재방문이 막혀 답을 못 찾는다. **반드시 `(노드, 마스크)` 쌍**이어야 한다.
> - `n = 1` 처리 누락.
> - 큐에 넣을 때가 아니라 꺼낼 때 `seen`에 추가 → 같은 상태가 큐에 여러 번 들어가 느려진다(정답은 나온다).
> - `seen`을 `2ⁿ × n` 리스트로 잡으면 더 빠르다. `set`도 `n <= 12`에서는 충분하다.

**복잡도 목표:** O(2ⁿ · n²) 시간, O(2ⁿ · n) 공간.

## 6. Partition to K Equal Sum Subsets 🔴

**출처:** [LeetCode #698](https://leetcode.com/problems/partition-to-k-equal-sum-subsets/)

정수 배열 `nums`와 정수 `k`가 주어진다. 이 배열을 **합이 모두 같은 `k`개의 비어 있지 않은 부분집합으로 나눌 수 있는지** 판정하라(모든 원소를 정확히 한 번씩 사용해야 한다).

**예시:**
- `nums = [4,3,2,3,5,2,1]`, `k = 4` → `true` (`(5), (1,4), (2,3), (2,3)` — 각 합 5)
- `nums = [1,2,3,4]`, `k = 3` → `false`

**제약:** `1 <= k <= nums.length <= 16`, `1 <= nums[i] <= 10^4`, `nums` 원소들의 합 `<= 2^31 - 1`.

**시그니처 (LeetCode):**
```python
class Solution:
    def canPartitionKSubsets(self, nums: List[int], k: int) -> bool: ...
```

> [!tip]- 힌트 1 (먼저 즉시 걸러낼 조건들)
> ```
> total = sum(nums)
> 1) total % k != 0      -> False   (같은 합으로 나눌 수 없다)
> 2) target = total // k
> 3) max(nums) > target  -> False   (한 원소가 이미 목표를 넘는다)
> ```
> 이 세 줄만으로 상당수 케이스가 걸러진다. **`nums[i] >= 1`이므로 빈 부분집합 걱정은 없다**(합이 `target >= 1`이면 원소가 최소 하나).

> [!tip]- 힌트 2 (핵심 발상 전환 — "k개 바구니"가 아니라 "하나씩 채우기")
> `k`개 바구니를 동시에 관리하려 하면 상태가 폭발한다. 대신 **"바구니를 하나씩 순서대로 꽉 채운다"** 고 보자.
>
> 그러면 필요한 정보는 **"지금까지 어떤 원소를 썼는가"** 하나뿐이다. 왜? **쓴 원소들의 합을 `target`으로 나눈 나머지가 곧 "현재 채우고 있는 바구니에 들어 있는 양"** 이기 때문이다.
> ```
> used_sum[mask] = mask 에 속한 원소들의 합
> 현재 바구니에 담긴 양 = used_sum[mask] % target
> ```
> **`k`가 상태에서 사라진다** — 이 관찰이 이 문제의 전부다.

> [!tip]- 힌트 3 (비트 DP 구현)
> ```python
> nums.sort()                              # 오름차순 (가지치기용)
> n = len(nums)
> dp = [False] * (1 << n); dp[0] = True
> used = [0] * (1 << n)                    # used[mask] = 그 마스크의 원소 합
>
> for mask in range(1 << n):
>     if not dp[mask]:
>         continue
>     for j in range(n):
>         if mask >> j & 1:
>             continue
>         if used[mask] % target + nums[j] > target:
>             break                        # 정렬했으므로 뒤는 다 더 크다 -> break
>         nxt = mask | (1 << j)
>         if not dp[nxt]:
>             dp[nxt] = True
>             used[nxt] = used[mask] + nums[j]
> return dp[(1 << n) - 1]
> ```
> **`break`가 `continue`가 아닌 이유:** 오름차순 정렬이므로 `nums[j]`가 안 들어가면 `nums[j+1]` 이후도 절대 안 들어간다. 이 한 글자가 성능을 크게 바꾼다.
>
> **왜 `if not dp[nxt]`로 감싸는가:** `used[nxt]`는 어떤 경로로 도달했든 항상 같다(마스크가 원소 집합을 정하므로). 그래서 처음 도달했을 때만 채워도 충분하고, 중복 갱신을 피할 수 있다.

> [!tip]- 힌트 4 (두 번째 정석: 가지치기 백트래킹)
> **내림차순 정렬** 후 원소를 하나씩 바구니에 넣어 본다.
> ```
> 가지치기 4가지
>   1) 내림차순 정렬 -> 큰 원소를 먼저 배치하면 실패를 빨리 발견한다
>   2) 같은 담긴 양을 가진 바구니는 하나만 시도 (바구니는 서로 구별되지 않는다)
>   3) 첫 번째 빈 바구니에 넣어 실패하면 즉시 False (대칭성 제거)
>   4) 원소가 딱 맞아떨어져 바구니가 완성되면 다음 원소를 새 바구니에
> ```
> 특히 **2)** 가 극적으로 빠르다 — 같은 상태에 여러 번 도달할 이유가 없다.

> [!tip]- 힌트 5 (실측해 보라 — 오늘의 마지막 교훈)
> 비트 DP는 `O(2ⁿ · n)`으로 **최악 복잡도가 보장**되고, 백트래킹은 최악에 지수지만 **가지치기가 먹히면 훨씬 빠르다**. `n = 16` 근처의 어려운 케이스(예: 모든 원소가 비슷한 크기, `k`가 중간값)를 만들어 **두 구현의 실측 시간을 비교**하라.
>
> **"지수 복잡도끼리는 상수와 가지치기가 승부를 가른다"** — 최악 복잡도만 보고 판단하지 말라는 것이 이 문제의 교훈이다.

> [!warning]- 흔한 실수
> - `total % k != 0` 체크 누락.
> - `max(nums) > target` 체크 누락 → 답은 맞지만 느려진다.
> - `used[mask] % target`을 쓰지 않고 "몇 번째 바구니인지"를 따로 상태에 두기 → 불필요하게 상태가 늘어난다.
> - 정렬 방향 혼동: **비트 DP는 오름차순**(`break` 가지치기용), **백트래킹은 내림차순**(큰 것 먼저 배치)이다.
> - `k = 1`이면 항상 `true`, `k = len(nums)`이면 모든 원소가 같아야 한다. **경계로 테스트**하라.

**복잡도 목표:** 비트 DP O(2ⁿ · n) 시간, O(2ⁿ) 공간. 백트래킹은 최악 지수이나 실전에서 빠르다.

## 학습 순서 제안

1. **#78로 열거 골격을 손에 새겨라.** `for mask in range(1 << n)` + `mask >> i & 1`. 백트래킹·누적 확장까지 세 가지를 다 써보고 결과를 서로 대조하라. 이 골격이 나머지 다섯 문제의 기반이다.
2. **#1863은 두 단계로 풀어라.** 먼저 브루트포스로 통과시키고, 그다음 **"비트 자리별로 세면 지수가 사라진다"** 를 유도해 O(n)으로 압축하라. 두 결과를 무작위 입력으로 교차 검증하는 습관이 여기서 생긴다.
3. **#338로 "비트로 값을 쪼개는" 두 관점을 익혀라.** `i >> 1`(마지막 비트)과 `i & (i-1)`(최하위 1비트). 후자가 popcount·펜윅 트리([[day-40-segment-tree/concept|Day 40]])와 이어진다.
4. **#64064(불량 사용자)가 오늘의 실전 하이라이트다.** 패턴 매칭에서 **길이 비교**를 빠뜨리지 말고, **선택 인덱스 집합을 마스크로 만들어 `set`에 넣는 것**으로 "순서 무관 중복 제거"를 공짜로 얻는 감각을 익혀라.
5. **#847로 "상태 공간 확장"을 배워라.** `visited[node]` → `visited[(node, mask)]`. 이 한 번의 확장이 [[day-26-bfs/concept|BFS(Day 26)]]의 적용 범위를 크게 넓힌다. `n=1` 경계를 반드시 확인하라.
6. **#698로 상태 압축의 정수를 맛보라.** "k개 바구니" 대신 "쓴 원소 집합 하나"로 상태를 줄이는 발상(`used_sum % target`)이 핵심이다. 그리고 **비트 DP vs 가지치기 백트래킹을 실측 비교**해 "최악 복잡도가 전부는 아니다"를 확인하라.

## 오늘의 판단 기준 (다시)

| 상황 | 도구 |
|---|---|
| 부분집합을 전부 봐야 함, n ≤ 20 | `for mask in range(1 << n)` |
| 부분집합인데 답이 자리별로 분해됨 | **비트 자리별 계산** (O(n)로 붕괴, #1863) |
| 순열을 다 돌아야 할 것 같지만 "집합"만 중요 | **비트 DP** `dp[mask][last]` (#698, TSP) |
| 재방문 허용 최단 경로 | **비트마스크 + BFS** `(node, mask)` (#847) |
| "순서 무관한 조합의 개수" | **마스크를 `set`에 넣어 중복 제거** (#64064) |
| 강한 가지치기가 가능한 조합 탐색 | **백트래킹** (비트 DP보다 빠를 수 있음) |
| 값을 비트로 쪼개는 DP | `dp[i>>1] + (i&1)` 또는 `dp[i&(i-1)] + 1` (#338) |
| n > 25 | **비트마스킹 포기** — 다른 알고리즘을 찾아라 |
