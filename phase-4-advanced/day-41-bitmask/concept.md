# Day 41 — 비트마스킹 (Bitmasking & Bitmask DP)

> [!abstract] 한눈 요약 (TL;DR)
> **비트마스킹(bitmasking)** 은 **정수 하나의 이진 비트들을 "집합" 또는 "상태(state)"로 읽는 기법**이다. `n`개의 원소가 있을 때 `i`번 비트가 1이면 "i번 원소를 포함", 0이면 "미포함" — 그러면 **`0`부터 `2ⁿ-1`까지의 정수가 곧 모든 부분집합(power set)** 이 된다. 집합 연산도 전부 CPU 명령 한 방으로 끝난다: **합집합 `|`, 교집합 `&`, 차집합 `a & ~b`, 대칭차 `^`, 포함 판정 `(a & b) == a`**. `set` 객체를 만들어 순회하는 것보다 **수십 배 빠르고**, 무엇보다 **정수 하나이므로 배열의 인덱스나 dict의 키로 쓸 수 있다** — 이것이 비트마스킹의 진짜 가치다. 이 성질이 열어주는 문이 두 개다. 첫째 **부분집합 완전 탐색**: `for mask in range(1 << n)` 한 줄로 [[day-24-brute-force/concept|완전 탐색(Day 24)]]의 재귀를 없앤다. 둘째, 그리고 훨씬 중요한 **비트 DP(bitmask DP) = 상태 압축(state compression)**: "지금까지 어떤 원소들을 썼는가"라는 **집합 자체를 DP 테이블의 첨자로** 삼는 것이다. 순열 완전 탐색이 `O(n!)`인 문제 — 외판원 순회(TSP), 작업 배정(assignment), 집합 분할 — 가 **`O(2ⁿ · n²)`** 로 내려앉는다. `n=15`면 `15! ≈ 1.3×10¹²` vs `2¹⁵·15² ≈ 7×10⁶`, **약 18만 배**다. 대신 값은 비싸다: **`2ⁿ`은 `n=20`에서 100만, `n=25`에서 3355만, `n=30`이면 10억** — 그래서 **"제약에 `n ≤ 20` 근처의 수상하게 작은 수가 보이면 비트마스킹을 의심하라"** 가 실전 신호다. 파이썬에서는 정수가 **무한 정밀도(arbitrary precision)** 라 오버플로가 없는 대신 `~x = -x-1`처럼 음수가 튀어나오는 함정이 있고, `int.bit_count()`(3.10+)·`int.bit_length()`·`x & -x`·`x & (x-1)` 같은 관용구를 손에 익혀야 한다. 핵심 한 줄: **"집합을 정수로 바꾸면, 집합이 배열의 첨자가 된다."**

> [!note]- 1. 정의와 직관 (Definition & Intuition)
> **정의.** 원소가 `n`개인 전체집합 `U = {0, 1, ..., n-1}`에 대해, 부분집합 `S ⊆ U`를 **정수 `mask`** 로 인코딩한다.
> $$ \text{mask} = \sum_{i \in S} 2^i \qquad\Longleftrightarrow\qquad i \in S \iff (\text{mask} \gg i) \,\&\, 1 = 1 $$
> 이 대응은 **일대일(bijection)** 이다. 부분집합은 `2ⁿ`개이고 `0..2ⁿ-1` 정수도 `2ⁿ`개이며, 서로 정확히 하나씩 짝지어진다. **비트마스킹의 모든 것이 이 한 줄에서 나온다.**
>
> ```
> n = 5,  U = {0,1,2,3,4}
>
>   mask = 22 = 0b10110
>                 │││││
>                 ││││└─ bit0 = 0  ->  0 ∉ S
>                 │││└── bit1 = 1  ->  1 ∈ S
>                 ││└─── bit2 = 1  ->  2 ∈ S
>                 │└──── bit3 = 0  ->  3 ∉ S
>                 └───── bit4 = 1  ->  4 ∈ S
>
>   S = {1, 2, 4}
>
>   주의: 비트는 "오른쪽에서 왼쪽"으로 0번부터 센다.
>        bin(22) = '0b10110' 문자열은 왼쪽이 상위 비트다 (읽는 방향이 반대!)
> ```
>
> **왜 굳이 정수로 바꾸는가 — 이유는 셋이다.**
>
> 1. **집합 연산이 상수 시간 한 방이다.** `set` 두 개의 합집합은 원소 수에 비례하는 시간이 들지만, 정수 `a | b`는 **기계어 한 명령**이다. `n ≤ 64`면 사실상 O(1)이다.
> 2. **정수는 인덱스가 된다.** `dp[frozenset({1,2,4})]`처럼 집합을 dict 키로 쓸 수도 있지만 해싱 비용이 크다. `dp[22]`는 **배열의 직접 접근**이다. **DP 테이블의 첨자로 집합을 쓸 수 있다는 것** — 이것이 비트 DP의 존재 이유 전부다.
> 3. **열거가 반복문 한 줄이다.** 모든 부분집합을 방문하는 데 재귀도, `itertools.combinations` 중첩도 필요 없다. `for mask in range(1 << n)`.
>
> **일상 비유 — 전등 스위치 패널.** 방에 전등 5개와 스위치 5개가 있다. 각 스위치는 켜짐(1)/꺼짐(0)이다. **패널 전체의 상태는 "어느 전등이 켜져 있는가"라는 집합**이고, 이걸 `10110`처럼 한 줄로 적으면 **32가지 상태에 0~31 번호를 붙일 수 있다**. "3번 전등이 켜져 있나?"는 그 자리 숫자를 보면 되고(`&`), "3번을 켜라"는 그 자리를 1로 만들면 된다(`|`). **집합을 다루는 대신 번호표를 다루게 되는 것** — 그래서 "이 상태에서의 최적값"을 배열 한 칸에 적어둘 수 있다.
>
> **또 다른 비유 — 출석부 도장.** 30명 반의 출석을 이름 목록으로 관리하면 "오늘 온 사람들"과 "어제 온 사람들"의 교집합을 구하려면 일일이 대조해야 한다. 그런데 출석을 **30자리 O/X 한 줄**로 적으면, 두 줄을 **위아래로 겹쳐 보기만 해도** 교집합·합집합·차집합이 즉시 읽힌다. 비트 연산이 바로 이 "겹쳐 보기"다.
>
> **비트 DP의 직관 — "무엇을 했는지"를 번호로.** [[day-31-dp/concept|DP(Day 31)]]의 본질은 "같은 상태를 두 번 계산하지 않는 것"이다. 그런데 외판원 순회처럼 **"어떤 도시들을 이미 방문했는가"** 가 상태의 일부인 문제는, 상태를 표현할 방법이 없어 보인다 — 방문 집합의 가짓수가 너무 많으니까. 여기서 **집합을 정수로** 바꾸면 상태는 `(방문 집합, 현재 위치) = (mask, last)`라는 **두 개의 정수 쌍**이 되고, `dp[mask][last]`라는 **평범한 2차원 배열**이 된다. 순열을 다 만들어보던 `O(n!)`이, **같은 방문 집합에 도달하는 서로 다른 순서들을 하나로 합쳐** `O(2ⁿ·n)`개의 상태로 줄어든다. **"순서는 다르지만 상태는 같다"는 관찰이 팩토리얼을 지수로 낮춘다** — 이것이 상태 압축의 정체다.
>
> ```
> 도시 4개 TSP, 0에서 출발
>
>   순열 완전 탐색:  0->1->2->3,  0->2->1->3,  0->3->1->2, ...   (3! = 6가지)
>
>   비트 DP 의 관찰:
>     "0,1,2 를 방문했고 지금 2 에 있다" 로 도달하는 경로  =  0->1->2
>     "0,1,2 를 방문했고 지금 1 에 있다" 로 도달하는 경로  =  0->2->1
>     n 이 커지면 같은 (집합, 위치) 로 모이는 경로가 폭발적으로 많아진다.
>       예) n=10 에서 "5개 방문 + 현재 위치 고정" 에 도달하는 순서는 4! = 24 가지
>       -> 그것들 중 "최선 하나"만 남기고 합치는 것이 비트 DP
>
>   상태 수:  2^n (방문 집합) x n (현재 위치)  =  n·2^n
>   전이 비용: 각 상태에서 다음 도시 n 개 시도  ->  O(n^2 · 2^n)
> ```
>
> **경쟁 기법과의 역할 분담.**
>
> | 상황 | 도구 | 복잡도 | 비고 |
> |---|---|---|---|
> | 부분집합 전부 확인, n ≤ 20 | **비트마스크 열거** | O(2ⁿ·n) | `for mask in range(1<<n)` |
> | 부분집합 전부 확인, 가지치기 가능 | [[day-27-backtracking/concept\|백트래킹(Day 27)]] | 최악 O(2ⁿ) | **가지치기가 먹히면 훨씬 빠름** |
> | 순열 전부 확인, n ≤ 10 | `itertools.permutations` | O(n!) | n=10이 한계(360만) |
> | 순열이지만 "방문 집합"만 중요, n ≤ 16 | **비트 DP** ✅ | O(2ⁿ·n²) | **n=15에서 18만 배 빠름** |
> | 원소 선택 + 용량 제약, 값이 작음 | [[day-32-dp-knapsack/concept\|배낭 DP(Day 32)]] | O(n·W) | **n이 크면 이쪽** |
> | 방문 체크만 필요 (집합 연산 없음) | `visited` 배열 / `set` | O(1) | 비트마스크 불필요 |
> | n > 25 | **비트마스킹 불가** ❌ | — | 다른 접근(그리디·DP·플로우)을 찾아라 |
>
> **결정적 신호는 제약조건이다.** `n ≤ 20`, `len(nums) <= 16`, `1 <= n <= 12` 같은 **부자연스럽게 작은 상한**은 출제자가 남긴 힌트다. `2²⁰ = 1,048,576`은 파이썬에서도 여유롭고, `2¹² · 12² = 589,824`는 순식간이다. 반대로 `n ≤ 10⁵`인데 부분집합을 떠올렸다면 **접근 자체가 틀린 것**이다.
>
> **비트마스킹은 "자료구조"가 아니라 "표현 방식"이다.** [[day-40-segment-tree/concept|세그먼트 트리(Day 40)]]나 [[day-12-heap/concept|힙]]처럼 별도의 구조를 만드는 게 아니라, **이미 있는 정수를 다르게 읽는 것**이다. 그래서 다른 모든 기법과 자유롭게 결합된다 — 비트마스크 + [[day-26-bfs/concept|BFS(Day 26)]](최단 경로), 비트마스크 + DP(TSP), 비트마스크 + [[day-18-binary-search/concept|이분 탐색]](meet in the middle), 비트마스크 + 백트래킹(가지치기).

> [!gear]- 2. 동작 원리 (How It Works)
> **(A) 6가지 기본 비트 연산 — 이것이 알파벳이다.**
> ```
>   a = 0b1100 = 12
>   b = 0b1010 = 10
>
>   a & b  = 0b1000 =  8    AND  : 둘 다 1인 자리만 1   -> 교집합
>   a | b  = 0b1110 = 14    OR   : 하나라도 1이면 1     -> 합집합
>   a ^ b  = 0b0110 =  6    XOR  : 서로 다르면 1        -> 대칭차
>   ~a     = -13            NOT  : 모든 비트 반전       -> 여집합 (파이썬은 음수!)
>   a << 2 = 0b110000 = 48  왼쪽 시프트  : x * 2^k
>   a >> 2 = 0b11    =  3   오른쪽 시프트: x // 2^k (음수는 바닥 나눗셈)
> ```
> ```
>   XOR 의 3대 성질 (문제 풀이에서 계속 나온다)
>     x ^ x = 0          같은 값 두 번이면 사라진다  -> "짝 없는 하나 찾기"
>     x ^ 0 = x          0 이 항등원
>     교환·결합법칙 성립  -> 순서에 상관없이 다 XOR 해도 된다
>
>   AND 의 성질:  x & 0 = 0,   x & x = x,   x & (모든비트1) = x
>   OR  의 성질:  x | 0 = x,   x | x = x
>   덧셈과의 관계: a + b = (a ^ b) + ((a & b) << 1)
>                 XOR = "받아올림 없는 덧셈",  AND = "받아올림이 생기는 자리"
> ```
>
> **(B) 원소 하나를 다루는 5가지 관용구 — 통째로 외운다.**
> ```
>   i 번 비트 읽기(test)     :  (mask >> i) & 1        또는  mask & (1 << i)
>   i 번 비트 켜기(set)      :  mask |  (1 << i)
>   i 번 비트 끄기(clear)    :  mask & ~(1 << i)
>   i 번 비트 뒤집기(toggle) :  mask ^  (1 << i)
>   i 번 비트가 켜져 있나?   :  if mask & (1 << i):     <- 0 이 아니면 참
>
>   흔한 실수:  mask & (1 << i) 의 값은 0 또는 2^i 이지 0/1 이 아니다.
>              "== 1" 로 비교하면 i=0 일 때만 맞는다.
>              -> bool 로만 쓰거나, (mask >> i) & 1 로 0/1 을 뽑아라.
> ```
>
> **(C) 집합 연산 대응표 — `set`을 정수로 옮기는 사전.**
> ```
>   파이썬 set              비트마스크            의미
>   ---------------------------------------------------------------
>   A | B                   a | b                 합집합
>   A & B                   a & b                 교집합
>   A - B                   a & ~b                차집합
>   A ^ B                   a ^ b                 대칭차
>   A <= B (부분집합)        (a & b) == a          A ⊆ B
>   A == B                  a == b                같은 집합
>   len(A)                  popcount(a)           원소 개수
>   not A (공집합?)          a == 0                공집합
>   전체집합                 (1 << n) - 1          n 비트 전부 1
>   A.add(i)                a |  (1 << i)
>   A.discard(i)            a & ~(1 << i)
>   i in A                  a &  (1 << i)
> ```
> **`(a & b) == a`가 "a ⊆ b"인 이유:** a의 모든 비트가 b에도 있어야 교집합이 a와 같아진다. **면접에서 자주 묻는 한 줄**이다.
>
> **(D) 부분집합 전체 열거 — 반복문 한 줄, O(2ⁿ·n).**
> ```
>   n = 3, items = ['a','b','c']
>
>   for mask in range(1 << n):          # 0 ~ 7
>       subset = [items[i] for i in range(n) if mask >> i & 1]
>
>   mask=0 = 000 -> []           mask=4 = 100 -> ['c']
>   mask=1 = 001 -> ['a']        mask=5 = 101 -> ['a','c']
>   mask=2 = 010 -> ['b']        mask=6 = 110 -> ['b','c']
>   mask=3 = 011 -> ['a','b']    mask=7 = 111 -> ['a','b','c']
>
>   총 2^3 = 8 개.  재귀도, itertools 중첩도 필요 없다.
>   비용: 마스크 2^n 개 x 원소 확인 n 번 = O(2^n · n)
> ```
> **원소가 아니라 "집계값"만 필요하면 `n`을 떼어낼 수 있다.** 예를 들어 부분집합 합을 미리 만들려면 `s[m] = s[m ^ lowbit] + nums[lowbit_index]`처럼 **이전 마스크를 재활용**해 O(2ⁿ)에 끝낸다. 파이썬에서 이 최적화가 TLE와 통과를 가른다.
>
> **(E) 두 개의 마법 관용구 — `x & -x`와 `x & (x-1)`.**
> ```
>   x & -x   : 최하위 1비트만 남긴다 (lowest set bit, LSB)
>   x & (x-1): 최하위 1비트를 지운다 (clear lowest set bit)
>
>   x     = 0b101100 = 44
>   -x    = ...10100 (2의 보수)      x & -x   = 0b100    = 4   <- LSB 추출
>   x-1   = 0b101011                 x & (x-1)= 0b101000 = 40  <- LSB 제거
>
>   왜?  -x = ~x + 1 이다. ~x 는 모든 비트를 뒤집고, +1 은 최하위 0들을
>        타고 올라가다가 "최하위 1비트" 자리에서 멈춘다.
>        결과적으로 x 와 -x 는 그 비트에서만 함께 1이다.
>        (Day 40 펜윅 트리의 i & -i 와 완전히 같은 원리)
>
>   x-1 은 최하위 1비트를 0으로 만들고 그 아래를 전부 1로 만든다.
>        AND 하면 최하위 1비트와 그 아래가 통째로 사라진다.
>
>   LSB 의 "위치"가 필요하면:  (x & -x).bit_length() - 1
> ```
> ```
>   Brian Kernighan 의 popcount:  1비트를 하나씩 지우며 센다
>
>       cnt = 0
>       while x:
>           x &= x - 1        # 최하위 1비트 제거
>           cnt += 1
>
>   반복 횟수 = 켜진 비트 수 (0 인 자리는 건너뛴다)
>   -> 희소한(1이 적은) 수에서 32번 도는 방식보다 훨씬 빠르다
>
>   파이썬 3.10+ 에서는 그냥 x.bit_count() 를 써라 (C 구현, 가장 빠름)
>   3.10 미만이면 bin(x).count('1')
> ```
>
> **(F) 서브마스크 열거 (submask enumeration) — 어려운 관용구 하나.**
> "어떤 마스크 `m`의 **모든 부분집합**"만 돌고 싶을 때가 있다(집합 분할 DP의 핵심).
> ```
>   sub = m
>   while True:
>       ...  sub 사용 (m 의 부분집합)  ...
>       if sub == 0: break
>       sub = (sub - 1) & m
>
>   m = 0b1011 일 때 나오는 순서:
>       1011 -> 1010 -> 1001 -> 1000 -> 0011 -> 0010 -> 0001 -> 0000
>       (m 의 부분집합 2^3 = 8 개가 내림차순으로 정확히 한 번씩)
>
>   원리: sub - 1 은 m 밖의 비트도 건드리지만 & m 이 즉시 잘라낸다.
>        "m 의 비트들만 모아 만든 이진수에서 1을 뺀 것" 과 같아진다.
>
>   주의: while sub: 로 쓰면 공집합(0)을 빼먹는다. 위처럼 break 를 쓰거나
>        do-while 형태로 명시하라. 이게 서브마스크 열거 최다 버그다.
> ```
> ```
>   "모든 마스크의 모든 서브마스크" 총 비용은 O(3^n) 이다 (O(4^n) 이 아니다!)
>
>     각 비트는 (서브마스크에 포함, m 에만 포함, 둘 다 없음) 3가지 경우
>     -> sum over m of 2^popcount(m) = (1+2)^n = 3^n     (이항정리)
>
>     n=15:  3^15 = 1400만  (2^15 x 2^15 = 10억 과 비교하면 70배 절약)
>     n=18:  3^18 = 3.9억   -> 파이썬에서는 이미 위험
> ```
>
> **(G) 비트 DP 1 — 외판원 순회(TSP), 상태 압축의 교과서.**
> ```
>   문제: 0번 도시에서 출발해 모든 도시를 정확히 한 번씩 방문하고
>        0으로 돌아오는 최소 비용 (dist[i][j] 주어짐)
>
>   상태: dp[mask][last] = "mask 에 속한 도시들을 방문했고, 지금 last 에 있다"
>                          는 상태까지의 최소 비용
>
>   초기: dp[1<<0][0] = 0                      (0번만 방문, 0에 있음)
>
>   전이: for mask, for last (mask 에 포함), for nxt (mask 에 미포함):
>             dp[mask | 1<<nxt][nxt]
>                 = min(그 값, dp[mask][last] + dist[last][nxt])
>
>   답:   min over last of ( dp[전체마스크][last] + dist[last][0] )
>
>   상태 수 2^n · n,  전이 n  ->  O(2^n · n^2)
>     n=15 :  2^15 · 225 = 737만        (15! = 1.3조 와 비교!)
>     n=20 :  2^20 · 400 = 4.2억        -> 파이썬은 이미 버겁다
> ```
> ```
>   마스크를 작은 것부터 순회하면 자연스럽게 위상 순서가 지켜진다:
>     mask | (1<<nxt) 는 항상 mask 보다 크다 (없던 비트가 켜지므로)
>     -> for mask in range(1 << n): 한 줄이 곧 올바른 계산 순서
>   이 성질 덕분에 TSP 비트 DP 는 재귀 없이 반복문으로 깔끔하게 써진다.
> ```
>
> **(H) 비트 DP 2 — 비트마스크 + BFS (LeetCode #847 골격).**
> ```
>   문제: 모든 노드를 방문하는 최단 보행(walk). 노드 재방문 허용, 시작점 자유.
>
>   관찰: "재방문 허용"이라 평범한 visited BFS 로는 종료 조건을 못 만든다.
>        -> 상태에 "지금까지 방문한 집합"을 넣는다: state = (node, mask)
>
>   시작: 모든 i 에 대해 (i, 1<<i) 를 큐에 넣는다 (시작점이 자유이므로)
>   전이: (u, mask) -> (v, mask | 1<<v)  for v in adj[u]
>   종료: mask == (1<<n) - 1 인 상태에 처음 도달한 거리
>
>   상태 수 = n · 2^n,  간선당 1회 방문 -> O(n^2 · 2^n)
>   n <= 12 이므로 12 · 4096 = 49152 상태. 아주 여유롭다.
>
>   핵심: BFS 는 "가중치 1 그래프의 최단 거리"이고, 여기서 정점은
>        "노드"가 아니라 "(노드, 방문집합)" 이다. 그래프를 상태 공간으로
>        확장하는 것 — Day 26 BFS 의 가장 강력한 확장형.
> ```
>
> **(I) 파이썬 정수의 특수성 — 무한 정밀도가 만드는 함정.**
> ```
>   C/Java: int 는 32비트 고정.  ~x 는 비트 반전 결과가 그대로 나온다.
>   Python: 정수는 무한 비트.   음수는 "왼쪽으로 1이 무한히 이어지는" 것으로 취급.
>
>     ~5  = -6          ( ~x == -x - 1 )
>     ~0  = -1          ( -1 은 모든 비트가 1 )
>     -1 & 0xFF = 255   ( 마스킹하면 원하는 폭만 볼 수 있다 )
>     bin(-6) = '-0b110'  <- 부호를 앞에 붙인 표기. 2의 보수 표기가 아니다!
>
>   여집합을 구할 때:
>     틀림:  comp = ~mask                    # 음수가 되어 인덱스로 못 쓴다
>     맞음:  comp = ~mask & ((1 << n) - 1)   # n 비트로 잘라낸다
>     또는:  comp = ((1 << n) - 1) ^ mask    # XOR 로 뒤집기 (더 안전)
>
>   시프트:
>     1 << 1000 도 정상 동작한다 (오버플로 없음, 메모리만 씀)
>     x >> k 는 음수에서 바닥 나눗셈: -5 >> 1 == -3 (== -5 // 2)
> ```
> ```
>   연산자 우선순위 함정 (파이썬 vs C 가 반대!)
>
>     Python:  &, |, ^ 가 비교연산자(==, <)보다 우선순위가 "높다"
>              a & 1 == 0   ->  (a & 1) == 0     의도대로 동작 O
>     C/Java:  & 가 == 보다 "낮다"
>              a & 1 == 0   ->  a & (1 == 0)     버그! 괄호 필수
>
>     하지만 파이썬에도 함정이 있다: 산술이 시프트보다 우선순위가 높다
>       1 << n - 1   ->  1 << (n-1)     (의도가 (1<<n)-1 이었다면 버그!)
>       x << 1 + 2   ->  x << 3
>     -> "전체집합"을 쓸 때 (1 << n) - 1 처럼 괄호를 반드시 쳐라.
> ```
>
> **(J) 알아두면 좋은 추가 기법.**
> ```
>   - Gosper's hack : "정확히 k개의 원소를 가진 부분집합"만 순서대로 열거
>       c = x & -x;  r = x + c;  x = (((r ^ x) >> 2) // c) | r
>       -> combinations 보다 빠르고 마스크를 바로 얻는다
>
>   - Meet in the middle : n=40 처럼 2^n 이 불가능할 때 절반씩 나눠
>       2^20 + 2^20 으로 만들고 정렬/이분 탐색으로 결합. O(2^(n/2) · n)
>
>   - SOS DP (Sum over Subsets) : 모든 마스크에 대해 "그 서브마스크들의 합"을
>       O(2^n · n) 에 구한다 (단순히 하면 O(3^n))
>       for i in range(n):
>           for m in range(1 << n):
>               if m >> i & 1: f[m] += f[m ^ (1 << i)]
>
>   - 비트를 "상태"가 아니라 "자릿수"로 쓰기 : 각 비트 자리를 독립적으로
>       세는 문제(예: 모든 부분집합 XOR 합, 배열의 AND/OR 쌍 세기)
>
>   - 비트셋 대용 : 파이썬 큰 정수 자체가 비트셋이다. "만들 수 있는 합" 갱신이
>       dp |= dp << w 한 줄 (부분집합 합 문제에서 수십 배 빨라진다)
> ```
>

> [!chart]- 3. 복잡도 (Time / Space Complexity)
> [[day-16-big-o/concept|Big-O(Day 16)]] 기준. **n** = 원소(비트) 수.
>
> | 연산 / 기법 | 시간복잡도 | 공간 | 설명 |
> |---|---|---|---|
> | 비트 하나 읽기/켜기/끄기/뒤집기 | **O(1)** | O(1) | `& \| ^ ~ << >>` 각각 기계어 수준 |
> | 집합 연산(합·교·차·대칭차) | **O(1)** ＊ | O(1) | `set` 연산 O(len)보다 압도적 |
> | popcount (`x.bit_count()`) | **O(1)** ＊ | O(1) | 3.10+. `bin(x).count('1')`은 O(비트수) |
> | popcount (Brian Kernighan) | O(켜진 비트 수) | O(1) | `x &= x-1` 반복 |
> | **부분집합 전체 열거** | **O(2ⁿ · n)** | O(1)~O(n) | 마스크마다 원소 n개 확인 |
> | 부분집합 합 사전계산 (재활용) | **O(2ⁿ)** | O(2ⁿ) | `s[m] = s[m ^ lowbit] + a[i]` |
> | **모든 마스크의 모든 서브마스크** | **O(3ⁿ)** | O(2ⁿ) | 4ⁿ 아님. 각 비트가 3가지 상태 |
> | SOS DP (Sum over Subsets) | **O(2ⁿ · n)** | O(2ⁿ) | 3ⁿ을 2ⁿ·n으로 낮추는 기법 |
> | **비트 DP (TSP형)** | **O(2ⁿ · n²)** | O(2ⁿ · n) | 상태 2ⁿ·n, 전이 n |
> | 비트마스크 + BFS (#847) | O(2ⁿ · n²) | O(2ⁿ · n) | 상태 공간 확장 BFS |
> | 집합 분할 DP (서브마스크) | O(3ⁿ) | O(2ⁿ) | "부분집합을 그룹으로 쪼개기" |
> | Gosper's hack (k-부분집합) | O(C(n,k)) | O(1) | 마스크를 직접 생성 |
> | Meet in the middle | O(2^(n/2) · n) | O(2^(n/2)) | n=40까지 커버 |
> | 순열 완전 탐색(비교용) | **O(n!)** | O(n) | n=11에서 이미 4천만 |
>
> ＊파이썬 정수는 무한 정밀도라 비트 수가 커지면 O(비트수/64)다. `n ≤ 64`에서는 사실상 O(1)로 봐도 된다.
>
> > **`2ⁿ`이 실제로 얼마나 큰가 — 이 표를 외워라.** 비트마스킹을 쓸지 말지는 오직 이 숫자로 결정된다.
> >
> > | n | 2ⁿ | 2ⁿ·n² (비트 DP) | 3ⁿ | n! | 파이썬 판정 |
> > |---|---|---|---|---|---|
> > | 10 | 1,024 | 102,400 | 59,049 | 3.6×10⁶ | 전부 여유 |
> > | 12 | 4,096 | 589,824 | 531,441 | 4.8×10⁸ | 비트 DP 여유 / n! 위험 |
> > | 15 | 32,768 | 7.4×10⁶ | 1.4×10⁷ | 1.3×10¹² | **비트 DP 안전지대** |
> > | 16 | 65,536 | 1.7×10⁷ | 4.3×10⁷ | 2.1×10¹³ | 열거 O(2ⁿ·n) 여유 |
> > | 18 | 262,144 | 8.5×10⁷ | 3.9×10⁸ | — | 3ⁿ은 위험 |
> > | **20** | **1,048,576** | 4.2×10⁸ | 3.5×10⁹ | — | **열거는 OK, 비트 DP는 아슬** |
> > | 22 | 4.2×10⁶ | 2.0×10⁹ | — | — | 파이썬은 사실상 한계 |
> > | 25 | 3.4×10⁷ | — | — | — | **메모리부터 터진다** |
> > | 30 | 1.07×10⁹ | — | — | — | ❌ 불가능 |
> >
> > **파이썬 기준 실전 감각: 단순 열거 `n ≤ 20~22`, 비트 DP `n ≤ 16~18`, 서브마스크(3ⁿ) `n ≤ 15`.** C++라면 각각 +3 정도 여유가 있다. 문제의 제약이 `n ≤ 20`이면 "단순 열거를 하라", `n ≤ 15`면 "비트 DP를 하라"는 뜻으로 읽어라.
> >
> > **공간이 먼저 터진다는 것을 잊지 마라.** 파이썬 리스트는 원소당 8바이트 포인터 + 정수 객체다. `dp = [0] * (1 << 20)`는 약 8MB(리스트만)이고 작은 정수는 캐시되어 있어 그럭저럭 버틴다. 그러나 `dp = [[0]*n for _ in range(1<<20)]`처럼 2차원이면 **수백 MB**로 즉시 MLE다. **비트 DP에서 `n·2ⁿ` 배열이 필요하면 `n ≤ 16` 정도가 파이썬 현실선**이고, 그 이상은 1차원으로 펴서 `dp[mask*n + last]`로 쓰거나 `array` 모듈을 쓴다.
> >
> > **`O(n!)` → `O(2ⁿ·n²)`의 이득을 숫자로 확인하라.** n=15: `15! = 1.31×10¹²` vs `2¹⁵·15² = 7.37×10⁶` → **약 17만 8천 배**. n=12: `4.79×10⁸` vs `5.9×10⁵` → 812배. **n이 클수록 이득이 폭발**하고, 이것이 "순열 문제를 보면 집합만 상태로 남길 수 있는지 묻는" 이유다.
> >
> > **3ⁿ이 4ⁿ이 아닌 이유(면접 단골).** 모든 마스크 `m`(2ⁿ개)에 대해 그 서브마스크(2^popcount(m)개)를 도는 총 비용은 $\sum_{m} 2^{|m|} = \sum_{k} \binom{n}{k} 2^k = (1+2)^n = 3^n$이다(이항정리). 각 비트를 "서브마스크에 있음 / m에만 있음 / 둘 다 없음" 세 갈래로 세는 조합론적 해석이 더 직관적이다.
> >
> > **비트 연산의 상수는 매우 작지만 파이썬에서는 "매우 작지 않다".** 파이썬의 `&`도 결국 객체 연산이라 C의 수백 배다. `2²⁰`짜리 루프에서 마스크당 비트 20개를 확인하면 `2×10⁷` 연산 — 파이썬에서 **10초 이상**이다. 그래서 **부분집합 합처럼 이전 마스크를 재활용해 `n`을 떼어내는 최적화(`s[m] = s[m ^ lowbit] + a[i]`)** 가 실전에서 중요하다.
>
> **재귀 깊이는 문제되지 않는다.** 비트 DP는 보통 반복문으로 쓰고, 서브마스크 재귀도 깊이가 n(≤20)이라 `sys.setrecursionlimit`이 필요 없다. 깊은 재귀가 걱정되는 것은 DFS 계열이다([[day-25-dfs/concept|Day 25]]).

> [!tip]- 💡 이해를 돕는 팁 (Tips)
> - **암기 문장.** **"집합을 정수로 바꾸면, 집합이 배열의 첨자가 된다."** 비트마스킹의 가치는 "빠른 집합 연산"이 아니라 **"DP 테이블의 인덱스가 될 수 있다"** 는 것이다. 이 한 줄을 붙잡으면 `dp[mask][last]`가 왜 나오는지 매번 다시 유도할 필요가 없다.
> - **제약조건을 먼저 읽어라 — `n ≤ 20`은 출제자의 자백이다.** `nums.length <= 16`([Partition to K Equal Sum Subsets #698](https://leetcode.com/problems/partition-to-k-equal-sum-subsets/)), `1 <= n <= 12`([Shortest Path Visiting All Nodes #847](https://leetcode.com/problems/shortest-path-visiting-all-nodes/)) 같은 숫자를 보면 **다른 걸 고민하기 전에 `2ⁿ`부터 계산**하라. ([제약으로 알고리즘 방향 잡기 — LeetCode 토론](https://leetcode.com/discuss/post/8414445/))
> - **`(1 << n) - 1`의 괄호를 절대 빼지 마라.** 파이썬에서 `-`가 `<<`보다 우선순위가 높아 `1 << n - 1`은 `1 << (n-1)`이다. **전체집합이 절반이 되는** 조용한 버그이고, 작은 테스트에서는 잘 안 걸린다.
> - **`mask & (1 << i)`는 0 또는 `2^i`다.** `== 1`과 비교하면 `i=0`에서만 맞는다. **`if mask & (1 << i):`처럼 진릿값으로 쓰거나, 값이 필요하면 `mask >> i & 1`** 로 뽑아라. 후자가 읽기도 쉬워 실전 표준이다.
> - **`~mask`는 음수다 — 여집합은 XOR로.** 파이썬 정수는 무한 비트라 `~mask`가 `-mask-1`이 된다. `full = (1 << n) - 1`을 만들어 두고 **`comp = full ^ mask`** 를 쓰는 습관을 들여라. `~mask & full`도 맞지만 XOR 쪽이 실수가 적다.
> - **서브마스크 열거는 `do-while`이다.** `sub = (sub-1) & m`을 `while sub:`로 감싸면 **공집합을 빼먹는다**. `while True: ... if sub == 0: break; sub = (sub-1) & m` 형태를 통째로 외워라. 공집합이 답인 경계 케이스에서만 틀려서 디버깅이 오래 걸린다.
> - **`x & -x`와 `x & (x-1)`은 [[day-40-segment-tree/concept|Day 40 펜윅 트리]]와 같은 도구다.** BIT의 `i & -i`가 여기서 재등장한다. **"최하위 1비트 추출/제거"** 한 쌍만 알면 popcount, 비트 순회, LSB 인덱스가 전부 따라온다. `(x & -x).bit_length() - 1`이 최하위 1비트의 **위치**다.
> - **popcount는 `x.bit_count()`(Python 3.10+)를 쓰라.** C로 구현되어 가장 빠르다. 구버전 호환이 필요하면 `bin(x).count('1')`이 그다음이고, 루프로 세는 것은 마지막 선택이다. ([int.bit_count() 공식 문서](https://docs.python.org/3/library/stdtypes.html#int.bit_count))
> - **"모든 부분집합의 XOR 합" 같은 문제는 비트 자리별로 분해하라.** [Sum of All Subset XOR Totals #1863](https://leetcode.com/problems/sum-of-all-subset-xor-totals/)의 O(n) 해법은 **"어떤 비트가 하나라도 켜져 있으면, 그 비트는 정확히 부분집합의 절반(2^(n-1))에서 1이 된다"** 는 관찰이다 → 답 = `(nums 전체 OR) << (n-1)`. **비트마스킹 문제의 상당수가 "자리별 독립 계산"으로 지수를 없앤다.**
> - **DP 점화식을 "비트로 쪼개는" 것도 비트마스킹이다.** [Counting Bits #338](https://leetcode.com/problems/counting-bits/)의 `dp[i] = dp[i >> 1] + (i & 1)`(마지막 비트를 뗀다)과 `dp[i] = dp[i & (i-1)] + 1`(최하위 1비트를 뗀다)은 **같은 답에 이르는 다른 분해**다. 두 점화식을 나란히 보면 비트 연산이 "값을 쪼개는 방법"임이 보인다.
> - **비트 DP의 순회 순서는 저절로 맞는다.** `mask | (1 << i) > mask`이므로 `for mask in range(1 << n)`이 곧 위상 순서다. **정렬이나 재귀 없이 반복문 하나로 끝난다** — 이것이 비트 DP가 예쁘게 써지는 이유다.
> - **비트마스크 + BFS는 "그래프를 상태 공간으로 확장"하는 것.** 정점을 `노드`가 아니라 `(노드, 방문집합)`으로 두면 [[day-26-bfs/concept|BFS(Day 26)]]가 그대로 최단 거리를 준다. **"재방문이 허용되는 최단 경로"** 문제의 표준 해법이다. ([부분집합 DP 정리 — LeetCode 토론](https://leetcode.com/discuss/post/1125779/dynamic-programming-on-subsets-with-examples-explained/))
> - **기출에서는 "집합의 중복 제거"로 비트마스크가 쓰인다.** [불량 사용자(프로그래머스 #64064)](https://school.programmers.co.kr/learn/courses/30/lessons/64064)는 "서로 다른 제재 아이디 **집합**의 개수"를 묻는다 — 순서만 다른 같은 조합을 하나로 세야 하므로, 선택한 인덱스들을 **마스크 정수 하나로 만들어 `set`에 넣으면** 중복 제거가 공짜다. `frozenset`보다 해싱이 싸고 코드도 짧다.
> - **비트 트릭을 남용하지 마라.** `x ^= y ^= x ^= y`(스왑) 같은 것은 파이썬에서 `a, b = b, a`보다 느리고 위험하다. **가독성을 잃으면서까지 쓸 가치가 있는 비트 트릭은 `x & -x`, `x & (x-1)`, popcount 정도**다. 나머지는 알아만 두라. ([비트 조작 패턴 모음 — LeetCode 토론](https://leetcode.com/discuss/post/3695233/))
> - **큰 정수 자체를 비트셋으로 쓰는 반칙 기술.** "만들 수 있는 부분집합 합"을 구할 때 `dp |= dp << w` 한 줄이면 된다(`dp`는 정수). 파이썬 큰 정수 연산이 C 레벨에서 돌아 **리스트 DP보다 10배 이상 빠른** 경우가 흔하다. 부분집합 합 계열에서 기억해 둘 무기다.

> [!warning]- ⚠️ 개발자 필수 상식 (Must-Know)
> 1. **`1 << n - 1`은 `(1 << n) - 1`이 아니다.** 파이썬 우선순위상 산술(`-`)이 시프트(`<<`)보다 높다. **전체집합 마스크를 만들 때 괄호는 필수**다: `full = (1 << n) - 1`. 이 괄호 하나로 마스크가 절반이 되고, `n`이 작은 예제에서는 우연히 통과하기도 한다.
> 2. **파이썬의 `&`는 `==`보다 우선순위가 높다 — C/Java와 반대다.** 파이썬에서 `mask & 1 == 0`은 `(mask & 1) == 0`으로 **의도대로** 동작한다. 그러나 **C/Java에서는 `mask & (1 == 0)`** 이 되어 버그다. 언어를 오가며 코딩테스트를 본다면 **양쪽 다 괄호를 치는 습관**이 안전하다.
> 3. **`~x`는 파이썬에서 음수다.** `~x == -x - 1`. 여집합을 구하려면 반드시 **`full ^ mask`** 또는 `~mask & full`로 폭을 잘라라. 자르지 않은 음수 마스크를 배열 인덱스로 쓰면 **파이썬은 에러 없이 리스트 뒤에서부터 접근**한다 — 최악의 조용한 버그다.
> 4. **`mask & (1 << i)`의 값은 0/1이 아니다.** `2^i`다. `if ... == 1`로 비교하지 마라. 진릿값으로 쓰거나 `mask >> i & 1`로 정규화하라.
> 5. **`2ⁿ`의 벽을 항상 먼저 계산하라.** `n = 30`이면 `2³⁰ ≈ 10억` — **파이썬에서는 시간도 메모리도 불가능**하다. 비트마스킹은 `n ≤ 20`(단순 열거), `n ≤ 16~18`(비트 DP)에서만 성립하는 기법이다. **제약이 크면 비트마스킹은 애초에 오답 방향**이고, 그리디·DP·플로우를 찾아야 한다.
> 6. **`n · 2ⁿ` 2차원 배열은 파이썬에서 쉽게 MLE다.** `n=20`이면 `20 × 1,048,576 = 2천만 칸`이고 중첩 리스트로 만들면 수백 MB다. **1차원으로 펴서 `dp[mask * n + last]`** 로 쓰거나, `array('i', ...)`를 쓰거나, `n`을 줄일 방법을 찾아라.
> 7. **서브마스크 열거에서 공집합을 빼먹지 마라.** `while sub:` 형태는 `sub == 0`(공집합)을 처리하지 않는다. 집합 분할 DP에서 "한쪽이 빈 그룹"이 유효한 답인 경우 조용히 틀린다. **`if sub == 0: break`를 루프 끝에** 두는 형태를 표준으로 삼아라.
> 8. **비트 DP의 초기값과 "도달 불가" 상태를 구분하라.** `dp`를 `0`으로 초기화하고 최솟값을 구하면 "아직 계산 안 된 칸"과 "비용 0인 칸"이 구별되지 않는다. **`INF`로 채우고, 전이할 때 `dp[mask][last] == INF`면 건너뛰어라.** 최댓값 문제라면 `-INF`(또는 `-1`)를 쓴다. 비트 DP 오답의 큰 축이 여기다.
> 9. **`popcount`를 루프 안에서 반복 계산하지 마라.** `2²⁰`개 마스크마다 `bin(m).count('1')`을 부르면 그 자체가 수천만 연산이다. **필요하면 `pc[m] = pc[m >> 1] + (m & 1)`로 O(2ⁿ)에 전부 전처리**해 두라. 이 한 줄이 TLE와 통과를 가른다.
> 10. **"부분집합"과 "순열"을 혼동하지 마라.** 비트마스크는 **집합(순서 없음)** 을 표현한다. 순서가 답에 영향을 준다면 마스크만으로는 부족하고 `(mask, last)`처럼 **"현재 위치"를 상태에 추가**해야 한다(TSP가 정확히 그 이유로 `last`를 둔다). 반대로 **순서가 결과에 영향을 주지 않는데 순열을 다 돌고 있다면** 그게 바로 비트 DP로 줄일 자리다.
> 11. **XOR의 성질을 정확히 외워라.** `x ^ x = 0`, `x ^ 0 = x`, 교환·결합법칙 성립. 이 셋으로 "배열에서 짝 없는 하나 찾기"가 O(N) 시간·O(1) 공간에 풀린다(면접 단골). 그리고 **XOR은 "받아올림 없는 덧셈"** 이라는 관점도 알아두라 — `a + b = (a ^ b) + ((a & b) << 1)`.
> 12. **비트 자리별 독립 계산이 지수를 없앤다.** "모든 부분집합의 XOR 총합"처럼 보이는 `O(2ⁿ)` 문제가 **"각 비트가 몇 번 1이 되는가"** 로 분해하면 `O(n)`이 된다(#1863). **"부분집합 전체를 돌아야만 하는가, 아니면 자리별로 셀 수 있는가"** 를 먼저 자문하라.
> 13. **비트마스크는 백트래킹의 `visited` 배열을 대체할 수 있다.** `used = [False]*n` 대신 `used_mask` 정수 하나를 넘기면 **상태 복사가 O(1)** 이고 메모이제이션 키로 바로 쓸 수 있다. [[day-27-backtracking/concept|백트래킹(Day 27)]]에 메모이제이션을 얹는 표준 방법이다.
> 14. **그래도 가지치기가 이길 때가 있다.** #698(K개 같은 합 부분집합)은 비트 DP가 `O(2ⁿ·n)`으로 안전하지만, **정렬 + 강한 가지치기 백트래킹이 실측으로 더 빠른 경우**도 흔하다. 지수 복잡도끼리는 **상수와 가지치기가 승부를 가른다** — 최악 복잡도만 보고 판단하지 마라.
> 15. **실무에서의 비트마스킹.** 리눅스 파일 권한(`rwxr-xr-x` = `0o755`), 네트워크 서브넷 마스크, 이벤트 리스너 플래그(`READ | WRITE`), 게임의 상태 플래그, DB의 옵션 비트필드, feature flag — **"여러 개의 참/거짓 옵션을 하나의 정수로 묶는" 패턴은 시스템 전반의 기본 관용구**다. 파이썬 표준 라이브러리의 `enum.Flag`와 `re` 플래그(`re.I | re.M`)가 바로 이것이다.
> 16. **면접 단골 비교: 비트마스킹 vs 완전 탐색 vs DP.** 정답 요지: "**비트마스킹은 집합을 정수로 인코딩하는 표현 기법**이지 알고리즘이 아니다. **완전 탐색에 쓰면 재귀 없는 부분집합 열거**가 되고, **DP에 쓰면 상태 압축**이 되어 `O(n!)` 순열 탐색을 `O(2ⁿ·n²)`로 낮춘다. 대가는 `n ≤ 20` 정도의 좁은 적용 범위와 가독성이다."

> [!example]- 예제 코드 (Examples)
> ```python
> # ---- (1) 비트 하나 다루기: 5가지 관용구 ----
> def bit_test(mask, i):   return (mask >> i) & 1          # 읽기 (0/1 로 정규화)
> def bit_set(mask, i):    return mask | (1 << i)          # 켜기
> def bit_clear(mask, i):  return mask & ~(1 << i)         # 끄기
> def bit_toggle(mask, i): return mask ^ (1 << i)          # 뒤집기
>
> def full_mask(n):        return (1 << n) - 1             # 괄호 필수! 1 << n-1 은 버그
>
>
> # ---- (2) 집합 연산 대응 ----
> a, b = 0b1100, 0b1010
> union      = a | b                   # 합집합
> inter      = a & b                   # 교집합
> diff       = a & ~b                  # 차집합 A - B
> sym        = a ^ b                   # 대칭차
> is_subset  = (a & b) == a            # A ⊆ B ?
> complement = full_mask(4) ^ a        # 여집합 (~a 는 음수이므로 XOR 사용)
>
>
> # ---- (3) popcount: 세 가지 방법 ----
> def popcount_kernighan(x):           # 켜진 비트 수만큼만 돈다
>     cnt = 0
>     while x:
>         x &= x - 1                   # 최하위 1비트 제거
>         cnt += 1
>     return cnt
>
> # 파이썬 3.10+ : x.bit_count()  <- 가장 빠름 (C 구현)
> # 그 이전      : bin(x).count('1')
>
> def popcount_table(n):               # 0..2^n-1 전부 O(2^n) 에 전처리
>     pc = [0] * (1 << n)
>     for m in range(1, 1 << n):
>         pc[m] = pc[m >> 1] + (m & 1)
>     return pc
>
>
> # ---- (4) 부분집합 전체 열거: O(2^n · n) ----
> def all_subsets(items):
>     n = len(items)
>     out = []
>     for mask in range(1 << n):                        # 0 .. 2^n - 1
>         out.append([items[i] for i in range(n) if mask >> i & 1])
>     return out
>
> # 부분집합 "합"만 필요하면 이전 마스크를 재활용해 O(2^n) 으로:
> def subset_sums(nums):
>     n = len(nums)
>     s = [0] * (1 << n)
>     for m in range(1, 1 << n):
>         low = m & -m                                  # 최하위 1비트
>         i = low.bit_length() - 1                      # 그 비트의 위치
>         s[m] = s[m ^ low] + nums[i]                   # 그 원소를 뺀 마스크 + 원소
>     return s
>
>
> # ---- (5) 서브마스크 열거: m 의 모든 부분집합, 전체 O(3^n) ----
> def submasks(m):
>     out, sub = [], m
>     while True:
>         out.append(sub)
>         if sub == 0:                                  # 공집합까지 포함해야 한다!
>             break
>         sub = (sub - 1) & m
>     return out
>
>
> # ---- (6) 비트 DP: 외판원 순회 TSP, O(2^n · n^2) ----
> def tsp(dist):
>     """0 에서 출발해 모든 도시를 한 번씩 방문하고 0 으로 복귀하는 최소 비용."""
>     n = len(dist)
>     INF = float('inf')
>     dp = [[INF] * n for _ in range(1 << n)]           # dp[방문집합][현재위치]
>     dp[1][0] = 0                                      # 0번만 방문, 0에 있음
>     for mask in range(1 << n):                        # 작은 마스크부터 = 위상 순서
>         for last in range(n):
>             cur = dp[mask][last]
>             if cur == INF or not (mask >> last & 1):  # 도달 불가 상태는 건너뛴다
>                 continue
>             for nxt in range(n):
>                 if mask >> nxt & 1:                   # 이미 방문
>                     continue
>                 nm = mask | (1 << nxt)
>                 cand = cur + dist[last][nxt]
>                 if cand < dp[nm][nxt]:
>                     dp[nm][nxt] = cand
>     end = (1 << n) - 1
>     return min(dp[end][last] + dist[last][0] for last in range(n))
>
>
> # ---- (7) 비트마스크 + BFS: 모든 노드 방문 최단 보행 (LeetCode #847 골격) ----
> from collections import deque
>
> def shortest_path_all_nodes(graph):
>     n = len(graph)
>     if n == 1:
>         return 0
>     goal = (1 << n) - 1
>     dq = deque((i, 1 << i) for i in range(n))         # 시작점이 자유롭다
>     seen = {(i, 1 << i) for i in range(n)}
>     steps = 0
>     while dq:
>         for _ in range(len(dq)):                      # 레벨 단위 BFS
>             u, mask = dq.popleft()
>             if mask == goal:
>                 return steps
>             for v in graph[u]:
>                 nm = mask | (1 << v)                  # 상태 = (노드, 방문집합)
>                 if (v, nm) not in seen:
>                     seen.add((v, nm))
>                     dq.append((v, nm))
>         steps += 1
>     return -1
>
>
> # ---- (8) 자리별 독립 계산: 모든 부분집합의 XOR 총합 (LeetCode #1863) ----
> def subset_xor_sum(nums):
>     """어떤 비트가 하나라도 켜져 있으면 부분집합의 절반에서 1 -> OR << (n-1)."""
>     acc = 0
>     for x in nums:
>         acc |= x
>     return acc << (len(nums) - 1)
>
>
> # ---- (9) 파이썬 정수의 함정 ----
> #   ~5 == -6                 (~x == -x - 1, 무한 정밀도라 음수가 된다)
> #   bin(-6) == '-0b110'      (2의 보수 표기가 아니라 부호 + 절댓값 표기)
> #   -1 & 0xFF == 255         (마스킹하면 원하는 폭만 볼 수 있다)
> #   1 << n - 1  !=  (1 << n) - 1      <- 괄호 필수
> #   mask & (1 << i) 의 값은 0 또는 2^i (0/1 아님)
> ```
>
> 전체 실행 가능한 예제(집합 연산 검증, 부분집합 열거와 `itertools` 교차 검증, 서브마스크 3ⁿ 검증, Gosper's hack, TSP 비트 DP와 순열 브루트포스 교차 검증, 비트마스크 BFS, popcount 3종 성능 비교, 파이썬 정수 함정 실증 포함): [examples.py](examples.py)
