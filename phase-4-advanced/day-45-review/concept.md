# Day 45 — Phase 4 심화 종합 복습 (Advanced Review)

> [!abstract] 한눈 요약 (TL;DR)
> **Phase 4(Day 31~44)의 마지막 정거장**이다. 지난 14일 동안 심화 무기 열넷을 벼렸다 — DP·배낭·LIS/LCS·다익스트라·벨만포드/플로이드·유니온파인드·MST·위상정렬·트라이·세그먼트트리/펜윅·비트마스킹·KMP/라빈카프·LCA·트리DP. 오늘은 **새 개념을 배우는 날이 아니라, 이 열넷을 "문제를 읽는 즉시 후보가 떠오르는" 하나의 의사결정 지도(decision map)로 묶는 날**이다. [[day-30-review/concept|Day 30]]이 개념 집중기(자료구조·기법·탐색)를 묶었다면, 오늘은 **그 위층**을 묶는다. Phase 4 전체를 한 줄로 압축하면 이렇다 — **"제약(constraint)을 먼저 읽고, 허용 복잡도를 정하고, 그 복잡도에 도달하는 도구를 고른다."** 실전에서 무기 선택은 취향이 아니라 **산술**이다. `N ≤ 20`이면 `2^N` 비트마스크가 열리고, `N ≤ 5000`이면 `O(N²)` DP가 허용되며, `N ≤ 10^5`이면 `O(N log N)` 이하만 살아남고, `V ≤ 400`이면 `O(V³)` 플로이드-워셜이 오히려 가장 짧은 코드다. **이 표를 외우는 것이 Phase 4를 외우는 것이다.** 오늘 정리하는 판단 축은 다섯 개다. **① 최적화인가 탐색인가** — "최소/최대/개수"를 묻고 **부분 문제가 겹치면 DP**, 겹치지 않고 제약이 작으면 **완전 탐색/비트마스크**. **② 그래프라면 무엇이 붙어 있나** — 간선 가중치가 **없으면 BFS**, **음이 아니면 다익스트라**, **음수가 있으면 벨만-포드**, **모든 쌍이면 플로이드-워셜**, **연결성만 물으면 유니온파인드**, **전부 잇는 최소 비용이면 MST**, **선후 관계면 위상 정렬**. **③ 트리라면 무엇을 묻나** — **경로의 조상**이면 LCA, **서브트리 집계**면 트리 DP, **모든 루트에 대한 답**이면 리루팅. **④ 문자열이라면** — **접두사 집합**이면 트라이, **패턴 위치**면 KMP/라빈-카프. **⑤ 질의가 반복되나** — 배열이 **고정이면 누적 합**, **변하면 펜윅/세그먼트 트리**. 그리고 이 다섯 축 위에 **언제나 Big-O의 심판**([[day-16-big-o/concept|Day 16]])이 얹힌다. 오늘의 13문제는 특정 기법 하나를 훈련하는 것이 아니라 **"어떤 무기를 꺼낼지 판단"** 을 훈련하도록 Day 31~44 전 범위를 섞었고, **의도적으로 지난 14일에 한 번도 나오지 않은 문제들만** 골랐다 — 답을 기억하는 것이 아니라 **판단을 재현하는지**를 확인해야 하기 때문이다. 핵심 한 줄: **"제약이 알고리즘을 고르고, Big-O가 그것을 승인한다."**

> [!note]- 1. 정의와 직관 (Definition & Intuition)
> **종합 복습의 본질은 "다시 읽기"가 아니라 "인덱스 재구축"이다.** [[day-30-review/concept|Day 30]]에서 이미 한 번 말했지만, Phase 4에서는 그 의미가 더 무겁다. 개념 집중기의 도구들(스택·큐·해시·정렬·이분 탐색·DFS·BFS)은 **문제 문장에 거의 그대로 드러난다** — "괄호가 맞는지", "가장 가까운", "정렬된 배열에서". 반면 Phase 4의 도구들은 **문제 문장에 이름이 나오지 않는다.** 아무도 "이것은 위상 정렬 문제입니다"라고 써 주지 않는다. 대신 **"선수 과목", "작업 순서", "빌드 의존성"** 이라고 쓴다. **Phase 4의 실력은 곧 "위장된 문장에서 구조를 알아보는 능력"** 이다.
>

> ### 비유 — 응급실 트리아지(triage)
>
> 응급실 의사는 환자를 보는 순간 **진단명을 먼저 떠올리지 않는다.** 먼저 **활력 징후(vital signs)** 를 본다 — 혈압, 맥박, 호흡. 그 숫자가 **어느 트랙으로 보낼지**를 결정하고, 진단은 그다음이다.
>
> **알고리즘 문제의 활력 징후는 "제약(constraints)"이다.**
> ```
>   환자를 보자마자 재는 것              문제를 읽자마자 보는 것
>   ------------------------------------------------------------
>   혈압 / 맥박 / 호흡수          <->    N 의 크기, 질의 수 Q, 값의 범위
>   "지금 당장 위험한가"           <->    "O(N^2) 이 도는가, 안 도는가"
>   트랙 배정 (중증/경증)          <->    도구 후보군 좁히기
>   정밀 진단                      <->    구체적 알고리즘 확정
> ```
> **초보자는 "무슨 알고리즘일까?"부터 생각하고, 숙련자는 "얼마나 빨라야 하나?"부터 생각한다.** 이 순서를 뒤집는 것이 오늘의 목표다. 실제로 **제약만 보고도 후보가 2~3개로 줄어드는 경우가 대부분**이며, 그다음에 문제의 구조적 신호(선후 관계? 연결성? 접두사?)로 하나를 확정한다.
>

> ### Phase 4를 관통하는 세 가지 큰 줄기
>
> 열네 개 도구는 흩어진 것이 아니라 **세 갈래 계보**를 이룬다. 이 계보를 알면 하나를 떠올릴 때 이웃이 함께 떠오른다.
> ```
>   [줄기 1] "부분 문제로 쪼개 재사용한다"  = DP 계열
>       Day 31 DP 입문 -> Day 32 배낭 -> Day 33 LIS/LCS
>                      -> Day 41 비트마스크 DP (상태를 집합으로)
>                      -> Day 44 트리 DP     (상태를 서브트리로)
>       공통 질문: "상태(state)를 무엇으로 잡을까? 전이(transition)는? 계산 순서는?"
>
>   [줄기 2] "정점과 간선의 관계를 푼다"    = 그래프 계열
>       Day 34 다익스트라 -> Day 35 벨만포드/플로이드   (거리)
>       Day 36 유니온파인드 -> Day 37 MST               (연결성)
>       Day 38 위상 정렬                                 (순서)
>       Day 43 LCA -> Day 44 트리 DP                     (트리 특화)
>       공통 질문: "가중치가 있나? 음수인가? 방향이 있나? 사이클이 있나?"
>
>   [줄기 3] "많은 질의를 빠르게 답한다"    = 자료구조 계열
>       Day 39 트라이         (문자열 집합 질의)
>       Day 40 세그먼트/펜윅  (구간 질의 + 갱신)
>       Day 42 KMP/라빈카프   (패턴 위치 질의)
>       공통 질문: "전처리에 얼마를 쓰고 질의당 얼마를 쓸까?"
> ```
> **줄기 3의 사고방식이 특히 중요하다.** 코딩테스트에서 "질의가 `Q`번 들어온다"는 문장은 **"질의당 `O(1)` 또는 `O(log N)`으로 답하라"** 는 요구다. `Q`와 `N`이 둘 다 `10^5`면 **질의당 `O(N)`은 `10^10`으로 즉사**한다. **전처리에 투자하라**는 신호다.
>

>
> ### "무엇을 묻는가"가 도구를 고른다 — 네 가지 질문 유형
>
> ```
>   [최적값을 묻는다]   "최소 비용", "최대 개수", "가장 긴"
>       -> 부분 문제가 겹치는가?  Yes -> DP
>                                 No  -> 그리디 / 완전 탐색 / 이분 탐색(정답)
>
>   [경우의 수를 묻는다] "몇 가지 방법", "가짓수"
>       -> 거의 항상 DP (또는 조합론). 완전 탐색은 개수 세기에 너무 느리다
>
>   [가능 여부를 묻는다] "가능한가", "만들 수 있는가"
>       -> DP(bool) / 유니온파인드(연결성) / 위상 정렬(사이클 존재)
>
>   [구조를 묻는다]     "순서를 출력", "경로를 복원", "어떤 노드"
>       -> 추적 배열(parent/choice)을 함께 유지해야 한다. 값만 구하면 반쪽이다
> ```
> **네 번째가 실전에서 가장 자주 무너지는 지점**이다. "최솟값"만 구하는 코드는 짜 놓고 **"그 경로를 출력하라"** 를 못 하는 경우가 많다. **DP·다익스트라·위상 정렬 모두 `parent[]`(또는 `choice[]`)를 함께 채우면 복원이 `O(길이)`** 라는 것을 습관으로 만들라.

> [!gear]- 2. 동작 원리 (How It Works) — Phase 4 마스터 의사결정 지도
> 문제를 읽을 때 **아래 표를 위에서 아래로** 훑는다. 신호가 잡히면 그 후보부터 의심하고, **마지막에 반드시 제약 표로 검산**한다.
>

>
> **(A) 0단계 — 제약을 먼저 읽어라 (가장 중요한 표)**
> ```
>   N 의 크기        허용 복잡도        열리는 도구                          Day
>   ---------------------------------------------------------------------------
>   N <= 12          O(N!)              순열 완전 탐색                       24
>   N <= 20          O(2^N * N)         비트마스크 DP, 부분집합 열거          41
>   N <= 100         O(N^3)             플로이드-워셜, 3중 루프 DP            35
>   N <= 400         O(V^3)             플로이드-워셜 (6.4e7, 경계)           35
>   N <= 2,000       O(N^2)             LCS, 편집거리, 2차원 DP               33
>   N <= 5,000       O(N^2)             LIS O(N^2), 벨만-포드(V*E)            33,35
>   N <= 100,000     O(N log N)         정렬, 다익스트라, LIS 이분, MST       17,34,33,37
>   N <= 1,000,000   O(N) / O(N log N)  KMP, 유니온파인드, 펜윅, 트라이       42,36,40,39
>   N <= 10^9        O(log N) / O(sqrt) 이분 탐색, 거듭제곱, 수학             18,05
>   ---------------------------------------------------------------------------
>   기준: 파이썬은 1초에 약 1000만~2000만 회 단순 연산 (PyPy 아님)
> ```
> ```
>   +-- 제약 읽기의 3가지 실전 규칙 ------------------------------------------+
>   |  1) "N <= 20" 을 보면 즉시 2^N 을 의심하라. 이것은 출제자의 신호다.      |
>   |  2) 질의 수 Q 가 따로 주어지면 "질의당 복잡도"를 별도로 계산하라.        |
>   |     전체 = 전처리 + Q * 질의당.  Q=1e5, 질의당 O(N)=1e5 -> 1e10 즉사    |
>   |  3) 값의 범위(1e9 등)는 "좌표 압축" 또는 "이분 탐색"의 신호다.           |
>   +-------------------------------------------------------------------------+
> ```
>

>
> **(B) 그래프 문제 분기표 — "무엇이 붙어 있고 무엇을 묻나"**
> ```
>   이런 신호가 보이면...                        ->  도구                복잡도        Day
>   -------------------------------------------------------------------------------------
>   "최소 이동 횟수", 간선 가중치 전부 1          ->  BFS                 O(V+E)        26
>   "최소 비용", 가중치 >= 0, 시작점 하나          ->  다익스트라(heapq)   O(E log V)    34
>   "최소 비용", 음수 간선 존재                    ->  벨만-포드           O(V*E)        35
>   "음수 사이클이 있는가"                         ->  벨만-포드 V번째 갱신 O(V*E)       35
>   "모든 쌍 최단 거리", V <= 400 정도             ->  플로이드-워셜       O(V^3)        35
>   "같은 그룹인가", "연결 요소 개수"              ->  유니온파인드        ~O(a(N))      36
>   "사이클이 생기는가" (무향, 간선 추가하며)      ->  유니온파인드        ~O(a(N))      36
>   "전부 연결하는 최소 비용"                      ->  MST(크루스칼/프림)  O(E log E)    37
>   "선수 과목", "작업 순서", "의존성"             ->  위상 정렬(Kahn)     O(V+E)        38
>   "사이클이 있는가" (방향 그래프)                ->  위상 정렬 결과 길이 O(V+E)        38
>   "DAG 위의 최장/최단 경로"                      ->  위상 정렬 + DP      O(V+E)        38
>   -------------------------------------------------------------------------------------
> ```
> ```
>   최단 경로 3형제 - 한눈 비교 (실전에서 가장 자주 헷갈린다)
>
>                  다익스트라       벨만-포드         플로이드-워셜
>   ------------------------------------------------------------------

> > **"전처리 + 질의" 관점으로 다시 보기 — Phase 4의 진짜 주제.**
> >
> > Phase 4 도구의 절반은 **"한 번 비싸게 준비하고, 그다음 질의를 싸게 받는"** 구조다. 이것이 개념 집중기와의 결정적 차이다.
> >
> > | 문제 | 나이브 (질의당) | 전처리 후 (질의당) | Q = 10⁵일 때 |
> > |---|---|---|---|
> > | 구간 합 (불변) | O(N) | **O(1)** 누적 합 | 10¹⁰ → 10⁵ |
> > | 구간 합 (갱신 있음) | O(N) | **O(log N)** 펜윅 | 10¹⁰ → 1.7×10⁶ |
> > | 두 노드의 LCA | O(N) | **O(log N)** 희소 배열 | 10¹⁰ → 1.7×10⁶ |
> > | 접두사 검색 | O(단어 수·길이) | **O(길이)** 트라이 | 큰 폭 감소 |
> > | 모든 쌍 최단 거리 | 다익스트라 V회 | **O(V³)** 한 번 | V 작을 때 유리 |
> >
> > **"질의가 많다"는 문장을 보면 전처리를 떠올려라.** 이 반사신경 하나가 Phase 4의 절반이다.
>
> > **파이썬 실전 상수 감각 — 같은 복잡도라도 다르다.**
> >
> > | 연산 | 상대 비용 | 비고 |
> > |---|---|---|
> > | 리스트 인덱싱 `a[i]` | 1 | 가장 싸다 |
> > | 딕셔너리 조회 `d[k]` | ~2 | 해시 계산 비용 |
> > | 함수 호출 | ~5~10 | **재귀가 느린 진짜 이유** |
> > | `heapq.heappush/pop` | ~10~20 | log N 에 상수까지 |
> > | 객체 속성 접근 `o.x` | ~3 | 트라이를 dict로 짜는 이유 |
> >
> > **결론 두 가지.** ① **재귀 → 반복 전환은 복잡도가 아니라 상수를 줄인다**(그리고 `RecursionError`를 없앤다). ② **트라이는 클래스보다 중첩 `dict`가 빠르다** — [[day-39-trie/concept|Day 39]]에서 본 그대로다.
>
> > **경계선에 걸리는 조합들 — 외워 둘 위험 구간.**
> >
> > | 조합 | 연산량 | 파이썬 판정 |
> > |---|---|---|
> > | 플로이드-워셜 `V = 500` | 1.25×10⁸ | ⚠️ 위험 (수십 초) |
> > | 플로이드-워셜 `V = 200` | 8×10⁶ | ✅ 안전 |
> > | 벨만-포드 `V=1000, E=10⁴` | 10⁷ | ⚠️ 경계 |
> > | 비트마스크 DP `N = 20` | 2×10⁷ (2^20·20) | ⚠️ 경계 (최적화 필요) |
> > | 비트마스크 DP `N = 16` | 10⁶ | ✅ 안전 |
> > | 0/1 배낭 `N=100, W=10⁵` | 10⁷ | ⚠️ 경계 |
> >
> > **경계 구간에서는 "복잡도를 낮추기"보다 "상수를 낮추기"가 실전 해법**인 경우가 많다: 내부 루프에서 속성 접근 제거, `for` 대신 슬라이스·내장 함수, 지역 변수로 캐싱.

> [!tip]- 💡 이해를 돕는 팁 (Tips)
> - **오늘의 암기 문장 셋.** **"제약을 먼저 읽어라."** / **"질의가 많으면 전처리."** / **"음수가 있으면 다익스트라를 버려라."** 이 셋이 Phase 4 판단의 90%다.
> - **문제 문장의 "위장 단어" 사전을 만들어 두라.** 출제자는 알고리즘 이름을 절대 쓰지 않는다. **"선수 과목·빌드 순서·조립 공정" = 위상 정렬**, **"같은 팀·같은 네트워크·친구의 친구" = 유니온파인드**, **"모든 도시를 잇는 최소 비용" = MST**, **"자동완성·사전·접두사" = 트라이**, **"신호가 도달하는 시간" = 다익스트라**, **"환전하며 이득이 나는 순환" = 음수 사이클(벨만-포드)**. 이 사전이 실전 속도를 결정한다.
> - **다익스트라의 3대 오답을 기억하라.** ① **음수 간선에 쓴다**(가장 흔하다), ② **`visited` 체크 없이 힙에서 꺼낸 것을 무조건 처리한다**(중복 정점 처리로 느려진다 — `if d > dist[v]: continue`가 정석), ③ **`dist` 갱신 없이 힙에만 넣는다.** [[day-34-dijkstra/concept|Day 34]]로 되돌아가 이 세 줄을 확인하라.
> - **플로이드-워셜의 루프 순서는 `k`가 반드시 가장 바깥**이다. `for k: for i: for j:` — `k`를 안쪽으로 옮기면 **조용히 틀린 답**이 나온다. 이건 "경유지 `k`를 하나씩 허용해 간다"는 DP의 정의에서 나오는 순서다. **가장 자주 나오는 3중 루프 버그**다.
> - **유니온파인드는 "간선을 추가하며 사이클을 보는" 문제 전부에 쓰인다.** `find(a) == find(b)`면 이미 연결 → 이 간선을 추가하면 사이클. **크루스칼이 정확히 이 판단으로 MST를 만든다.** 두 개념을 한 몸으로 기억하라([[day-36-union-find/concept|Day 36]] + [[day-37-mst/concept|Day 37]]).
> - **위상 정렬은 "정렬"이 아니라 "사이클 탐지기"이기도 하다.** Kahn 알고리즘 결과의 길이가 `V`보다 작으면 **사이클이 있다.** "완주 가능한가"류 문제의 표준 답이다.
> - **LIS의 `tails` 배열은 실제 부분 수열이 아니다.** 길이만 맞다. **실제 수열을 복원하려면 각 원소가 들어간 위치를 기록**해 두고 역추적해야 한다. 면접에서 자주 파고드는 지점이다([[day-33-dp-lis-lcs/concept|Day 33]]).
> - **비트마스크는 `N ≤ 20`이 사실상 상한선이다.** `2^20 ≈ 10^6`은 되지만 `2^25 ≈ 3.4×10^7`은 파이썬에서 위험하다. **제약에 20 이하가 보이면 즉시 비트마스크를 후보에 올려라**([[day-41-bitmask/concept|Day 41]]).
> - **KMP의 `pi` 배열(실패 함수)은 그 자체로 답이 되는 문제가 많다.** "접두사이면서 접미사인 최장 문자열"([#1392](https://leetcode.com/problems/longest-happy-prefix/))이 대표다. **`pi[-1]`이 곧 답**이다. **KMP를 "검색 알고리즘"으로만 기억하면 이 유형을 놓친다.**
> - **펜윅 트리는 "합"에만 쓸 수 있다.** 정확히는 **역원이 존재하는 연산**(합, XOR)만. **`min`/`max`는 뺄 수 없으므로 세그먼트 트리**가 필요하다. [[day-44-tree-dp/concept|Day 44]] 리루팅에서 본 **"뺄 수 있나?"** 질문이 여기서도 그대로 쓰인다.
> - **격자(grid) 문제를 그래프로 번역하는 습관.** `m×n` 격자는 **정점 `mn`개, 간선 `4mn`개인 그래프**다. "증가하는 경로"는 **간선 방향을 값이 커지는 쪽으로만 주면 DAG**가 되고, 그러면 [[day-38-topological-sort/concept|위상 정렬 + DP]] 또는 **메모이제이션 DFS**가 정답이다([#329](https://leetcode.com/problems/longest-increasing-path-in-a-matrix/)). **"격자 → 그래프" 번역이 되면 Phase 3·4가 하나로 이어진다.**
> - **"최소 높이 루트"는 잎을 깎는다.** [#310](https://leetcode.com/problems/minimum-height-trees/)은 트리 DP나 리루팅으로도 풀리지만, **차수 1 노드를 층층이 제거하는 BFS**가 훨씬 짧다. **답은 항상 1개 또는 2개**라는 사실도 함께 외워 두라(트리 지름의 중앙).
> - **답이 두 가지 방법으로 나오면 교차 검증하라.** 오늘 문제 중 여럿이 그렇다: 최단 경로는 **다익스트라 vs 벨만-포드 vs 플로이드**, 연결 요소는 **유니온파인드 vs DFS**, LIS는 **O(N²) vs O(N log N)**, 문자열 매칭은 **KMP vs 내장 `find`**. **무작위 입력으로 둘을 대조**하면 구현 확신이 생긴다 — 이것이 실전에서 가장 빠른 디버깅이다.
> - **복습은 "다시 읽기"가 아니라 "다시 풀기"다.** 개념 노트를 읽으면 다 아는 것 같지만, **빈 화면에서 다익스트라를 처음부터 짜 보면** 안다. 오늘 13문제는 **개념 노트를 보지 않고** 먼저 시도하고, 막히는 지점만 해당 Day로 돌아가라. **막힌 지점이 곧 당신의 진짜 약점 목록**이다.
> - **표준 라이브러리를 최대한 쓰라.** `heapq`(다익스트라·프림), `collections.deque`(BFS·Kahn), `bisect`(LIS), `functools.lru_cache`(메모이제이션), `str.find`(단순 매칭 검증용). **직접 짤 수 있어야 하지만, 실전에서는 내장이 더 빠르고 안전하다.**

> [!warning]- ⚠️ 개발자 필수 상식 (Must-Know)
> 1. **다익스트라에 음수 간선을 쓰면 안 된다.** 다익스트라는 **"한 번 확정된 최단 거리는 다시 줄지 않는다"** 는 전제(그리디 불변식) 위에 서 있고, 음수 간선은 이 전제를 깬다. **"통행료 환급", "할인", "이득"** 같은 단어가 보이면 음수를 의심하고 벨만-포드로 가라.
> 2. **다익스트라에서 `if d > dist[v]: continue`를 빼먹지 마라.** 힙에는 같은 정점이 여러 번 들어간다(`decrease-key`가 없으므로). 이 한 줄이 없으면 **불필요한 전개로 시간이 크게 늘어난다.**
> 3. **플로이드-워셜의 `k` 루프는 가장 바깥이다.** 순서를 바꾸면 **에러 없이 조용히 틀린다.** 그리고 `INF + INF` 오버플로를 피하려면 `INF`를 충분히 작게(예: `10**9`) 잡거나 갱신 전에 `INF` 체크를 넣어라.
> 4. **벨만-포드는 `V-1`번 돌고, `V`번째에 갱신되면 음수 사이클이다.** `V-1`인 이유는 **최단 경로가 최대 `V-1`개의 간선**을 갖기 때문이다.
> 5. **유니온파인드는 경로 압축과 union by rank/size를 둘 다 써야 `~O(a(N))`이다.** 하나만 쓰면 `O(log N)`이다. 그리고 **`find`를 재귀로 짜면 깊이 10⁵에서 죽는다** — **반복 버전(while + 경로 압축)** 을 손에 익혀라.
> 6. **크루스칼은 간선을 정렬하고, 프림은 정점을 힙으로 뽑는다.** `E`가 `V²`에 가까운 **밀집 그래프면 프림**, `E`가 `V`에 가까운 **희소 그래프면 크루스칼**이 유리하다. 코딩테스트에서는 **크루스칼이 짧아서 대개 이긴다**(유니온파인드만 있으면 된다).
> 7. **MST는 "간선 `V-1`개를 고르면 끝"이다.** 이 조기 종료를 넣으면 정렬 후 남은 간선을 훑지 않아도 된다. 그리고 **`V-1`개를 못 채우면 그래프가 연결되어 있지 않다**는 뜻이다 — 이 체크가 필요한 문제가 있다.
> 8. **위상 정렬 결과의 길이로 사이클을 판정하라.** `len(order) != V`면 사이클이 있다. **"불가능하면 빈 배열 반환"** 류 문제([#210](https://leetcode.com/problems/course-schedule-ii/))의 표준 처리다.
> 9. **트라이는 단어의 끝을 반드시 표시하라.** `is_end` 플래그(또는 `'#'` 키) 없이 짜면 **"app"이 사전에 없어도 "apple" 때문에 있다고 답한다.** 트라이 구현 최다 버그다.
> 10. **펜윅 트리는 1-based 인덱스가 필수다.** `i & -i` 연산이 0에서 무한 루프에 빠지기 때문이다. **입력이 0-based면 `+1`을 해서 넣어라.** 그리고 **값의 범위가 크면 좌표 압축**을 먼저 하라.
> 11. **세그먼트 트리 배열 크기는 `4N`으로 잡아라.** `2N`은 `N`이 2의 거듭제곱이 아닐 때 부족하다. `4N`은 항상 안전하다.
> 12. **비트마스크에서 연산자 우선순위를 조심하라.** `mask & 1 << i`는 `mask & (1 << i)`로 해석되어 우연히 맞지만, `mask & 1 == 0`은 **`mask & (1 == 0)`** 이 되어 틀린다. **괄호를 항상 쓰라.**
> 13. **KMP의 `pi` 배열 구축에서 `j = pi[j-1]` 되감기를 while로 돌려라.** `if`로 한 번만 되감으면 틀린다. 이 한 줄이 KMP의 심장이다.
> 14. **라빈-카프는 반드시 해시 충돌 시 실제 문자열을 비교하라.** 비교를 생략하면 **확률적으로 틀리는 코드**가 된다. 실전에서는 **모듈러를 큰 소수로** 잡고 검증을 넣는다.
> 15. **LCA 희소 배열의 `LOG`는 `N.bit_length()` 이상으로.** 부족하면 깊은 트리에서 조용히 틀린다. 그리고 **깊이를 먼저 맞추고 나서 함께 올라가는 순서**를 지켜라.
> 16. **트리 DP·LCA·DFS 전부에서 파이썬 재귀 한도 1000이 문제가 된다.** `N ≤ 10⁴`만 되어도 체인 입력이면 죽는다. **`sys.setrecursionlimit`은 임시방편**이고, **정석은 BFS 순서 + `reversed(order)`** 다([[day-44-tree-dp/concept|Day 44]]).
> 17. **0/1 배낭은 무게 축을 역순으로, 무한 배낭은 정순으로 돈다.** 방향 하나로 문제가 바뀐다. **왜 그런지 설명할 수 없다면 [[day-32-dp-knapsack/concept|Day 32]]로 돌아가라** — 면접 단골이다.
> 18. **"경로/순서를 출력하라"에 대비해 추적 배열을 습관화하라.** 다익스트라는 `parent[v]`, DP는 `choice[i]`, 위상 정렬은 결과 자체가 순서다. **값만 구하는 코드는 절반짜리**다.
> 19. **실무에서의 Phase 4.** **다익스트라** = 지도 경로 안내·네트워크 라우팅(OSPF), **MST** = 통신망·전력망 설계, **위상 정렬** = 빌드 시스템(`make`, Gradle)·패키지 의존성 해석·스프레드시트 재계산, **유니온파인드** = 이미지 연결 요소·클러스터링, **트라이** = 자동완성·IP 라우팅 테이블·사전, **세그먼트/펜윅** = 실시간 랭킹·시계열 집계, **KMP** = `grep`·시그니처 검색, **DP** = 편집 거리(`diff`, 맞춤법)·리소스 배분. **전부 지금 쓰이는 기술이다.**
> 20. **가장 중요한 것 — 못 푸는 문제보다 "잘못 고르는 문제"가 더 위험하다.** 다익스트라를 완벽히 짰는데 음수 간선이 있었다면 0점이다. **코드를 쓰기 전에 30초를 들여 제약과 전제를 확인하는 습관**이 실전 점수를 가장 크게 올린다.

> [!example]- 예제 코드 (Examples)
> Phase 4 핵심 템플릿을 **암기용 최소 형태**로 모았다. 실전에서 이 골격을 그대로 꺼내 쓸 수 있어야 한다.
>
> ```python
> import heapq
> from collections import deque
>
> # ---- Day 34. 다익스트라 (가중치 >= 0) ----
> def dijkstra(n, adj, src):
>     INF = float('inf')
>     dist = [INF] * n
>     dist[src] = 0
>     pq = [(0, src)]
>     while pq:
>         d, v = heapq.heappop(pq)
>         if d > dist[v]:          # 필수! 힙에 중복이 들어온다
>             continue
>         for w, cost in adj[v]:
>             nd = d + cost
>             if nd < dist[w]:
>                 dist[w] = nd
>                 heapq.heappush(pq, (nd, w))
>     return dist
>
>
> # ---- Day 35. 플로이드-워셜 (k 가 가장 바깥!) ----
> def floyd(n, dist):
>     for k in range(n):
>         dk = dist[k]
>         for i in range(n):
>             di = dist[i]
>             via = di[k]
>             for j in range(n):
>                 if via + dk[j] < di[j]:
>                     di[j] = via + dk[j]
>     return dist
>
>
> # ---- Day 36. 유니온파인드 (반복 버전 - 재귀 금지) ----
> class DSU:
>     def __init__(self, n):
>         self.p = list(range(n))
>         self.sz = [1] * n
>     def find(self, x):
>         while self.p[x] != x:
>             self.p[x] = self.p[self.p[x]]   # 경로 압축
>             x = self.p[x]
>         return x
>     def union(self, a, b):
>         ra, rb = self.find(a), self.find(b)
>         if ra == rb:
>             return False                    # 이미 연결 -> 사이클
>         if self.sz[ra] < self.sz[rb]:
>             ra, rb = rb, ra
>         self.p[rb] = ra
>         self.sz[ra] += self.sz[rb]
>         return True
>
>
> # ---- Day 37. 크루스칼 MST ----
> def kruskal(n, edges):                      # edges: (cost, a, b)
>     dsu = DSU(n)
>     total, used = 0, 0
>     for cost, a, b in sorted(edges):
>         if dsu.union(a, b):
>             total += cost
>             used += 1
>             if used == n - 1:               # 조기 종료
>                 break
>     return total if used == n - 1 else -1   # 연결 불가
>
>
> # ---- Day 38. 위상 정렬 (Kahn) + 사이클 판정 ----
> def topo_sort(n, graph, indeg):
>     dq = deque(v for v in range(n) if indeg[v] == 0)
>     order = []
>     while dq:
>         v = dq.popleft()
>         order.append(v)
>         for w in graph[v]:
>             indeg[w] -= 1
>             if indeg[w] == 0:
>                 dq.append(w)
>     return order if len(order) == n else []  # 짧으면 사이클
>
>
> # ---- Day 40. 펜윅 트리 (1-based 필수) ----
> class BIT:
>     def __init__(self, n):
>         self.n = n
>         self.t = [0] * (n + 1)
>     def add(self, i, v):                    # i: 1-based
>         while i <= self.n:
>             self.t[i] += v
>             i += i & -i
>     def query(self, i):                     # [1, i] 합
>         s = 0
>         while i > 0:
>             s += self.t[i]
>             i -= i & -i
>         return s
>
>
> # ---- Day 42. KMP 실패 함수 (그 자체가 답이 되는 문제가 많다) ----
> def build_pi(p):
>     pi = [0] * len(p)
>     j = 0
>     for i in range(1, len(p)):
>         while j and p[i] != p[j]:
>             j = pi[j - 1]                   # while 이어야 한다. if 는 틀림
>         if p[i] == p[j]:
>             j += 1
>             pi[i] = j
>     return pi
> ```
