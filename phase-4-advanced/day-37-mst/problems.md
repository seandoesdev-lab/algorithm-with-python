## 1. Min Cost to Connect All Points 🟡
- **출처:** [LeetCode #1584](https://leetcode.com/problems/min-cost-to-connect-all-points/)
- **유형:** **MST 기본** — 완전 그래프(complete graph)에서 Kruskal vs Prim 비교
- **문제:** 2차원 평면 위 점들 `points[i] = [xi, yi]`가 주어진다. 두 점을 잇는 비용은 **맨해튼 거리** `|xi−xj| + |yi−yj|`다. 모든 점이 서로 (직접·간접으로) 연결되도록 하는 **최소 총비용**을 구하라.
- **입력/출력:** `points: List[List[int]]` → `int`
- **제약:** `1 <= points.length <= 1000`, `-10^6 <= xi, yi <= 10^6`, 모든 점은 서로 다름
- **핵심 힌트:**
  - 점 = 정점, **모든 점 쌍**이 간선이므로 간선 수는 `n(n−1)/2` — 즉 **완전 그래프**다.
  - **접근 A (크루스칼):** 간선 약 50만 개를 만들어 정렬 → `O(n² log n)`. n=1000에서 통과는 하지만 메모리·시간이 빠듯하다.
  - **접근 B (프림 배열판, 권장):** 간선을 만들지 **않고** `dist[]` 배열만 갱신 → **`O(n²)`**. 메모리 `O(n)`. 이 문제의 정석.
  - `n == 1`이면 답은 `0` (간선 0개). 경계 처리 잊지 말 것.

## 2. 섬 연결하기 ⚫ (기출)
- **출처:** [프로그래머스 #42861](https://school.programmers.co.kr/learn/courses/30/lessons/42861) (Level 3)
- **유형:** **크루스칼 정석** — 간선 리스트가 그대로 주어지는 가장 전형적인 MST
- **문제:** `n`개의 섬 사이에 다리를 건설한다. `costs[i] = [a, b, cost]`는 섬 `a`와 `b`를 잇는 다리의 건설 비용이다. 다리를 여러 번 건너서라도 **모든 섬이 서로 통행 가능**하도록 만드는 **최소 건설 비용**을 구하라.
- **입력/출력:** `n: int, costs: List[List[int]]` → `int`
- **제약:** `1 <= n <= 100`, `costs.length <= n(n−1)/2`, 연결할 수 없는 경우는 입력으로 주어지지 않음
- **핵심 힌트:**
  - 입력이 이미 `(a, b, cost)` 간선 리스트다 → **크루스칼을 그대로 적용**하면 끝.
  - `costs.sort(key=lambda x: x[2])`로 **비용 오름차순** 정렬. `key`를 빼먹고 그냥 `sort()`하면 섬 번호로 정렬되어 오답(반드시 주의).
  - `dsu.union(a, b)`가 `True`일 때만 비용을 더한다. 채택 간선이 `n−1`개가 되면 종료.
  - 섬 번호가 `0 ~ n−1`이므로 `DSU(n)`. (다음 문제와 달리 여기는 0-based)

## 3. 전력망을 둘로 나누기 ⚫ (기출)
- **출처:** [프로그래머스 #86971](https://school.programmers.co.kr/learn/courses/30/lessons/86971) (Level 2)
- **유형:** **신장 트리 간선 제거 + 컴포넌트 크기** — 트리는 이미 신장 트리라는 성질을 이용
- **문제:** `n`개의 송전탑이 `n−1`개의 전선으로 **트리 형태**로 연결되어 있다. `wires[i] = [a, b]`. 전선 **하나를 끊어** 전력망을 두 개로 나눌 때, 두 망에 속한 송전탑 개수가 **최대한 비슷**하도록 하고 싶다. 그 **개수 차이의 최솟값**을 구하라.
- **입력/출력:** `n: int, wires: List[List[int]]` → `int`
- **제약:** `2 <= n <= 100`, `wires.length == n−1`, 송전탑 번호는 **1 이상 n 이하**(1-based)
- **핵심 힌트:**
  - 간선이 정확히 `n−1`개이고 연결되어 있으므로 이 그래프는 **이미 신장 트리**다 — MST를 구할 필요가 없다. 오늘 배운 "트리 = V−1 간선" 성질의 직접 응용.
  - 트리에서 **아무 간선이나 하나 끊으면 반드시 정확히 2개**의 컴포넌트가 된다(사이클이 없으므로).
  - `n ≤ 100`이라 **완전 탐색**으로 충분: 각 전선 `i`를 제외하고 나머지로 Union-Find를 다시 만든 뒤, 한쪽 컴포넌트 크기 `c`를 세어 `|n − 2c|`를 계산. 그 최솟값이 답.
  - **1-based 주의:** `DSU(n+1)`로 잡고 0번 인덱스는 버린다. 크기를 셀 때도 `1..n`만 순회.
  - 대안: DFS로 서브트리 크기를 한 번에 구하면 `O(n)`이지만, 제약이 작아 `O(n²α)` 완전 탐색이 더 안전하고 읽기 쉽다.

## 4. Path With Minimum Effort 🔴
- **출처:** [LeetCode #1631](https://leetcode.com/problems/path-with-minimum-effort/)
- **유형:** **최소 병목 경로(minimax path)** — MST/크루스칼의 대표 변형
- **문제:** `rows × columns` 격자 `heights`가 주어진다. 좌상단 `(0,0)`에서 우하단 `(rows−1, columns−1)`까지 상하좌우로 이동한다. 경로의 **effort**는 **연속한 두 칸 높이차의 절댓값 중 최댓값**이다. 가능한 경로들 중 **최소 effort**를 구하라.
- **입력/출력:** `heights: List[List[int]]` → `int`
- **제약:** `1 <= rows, columns <= 100`, `1 <= heights[i][j] <= 10^6`
- **핵심 힌트:**
  - "경로 길이의 **합**"이 아니라 "경로상 **최대 간선**"을 최소화 → **최단 경로가 아니라 병목 문제**다. 다익스트라를 그대로 쓰면 안 된다.
  - **접근 A (크루스칼, 권장):** 셀 `(r,c)`를 `r*C + c`로 1차원화. 인접한 두 칸마다 간선 `(|높이차|, u, v)`를 만들고 **가중치 오름차순으로 union**. `find(0) == find(R*C−1)`이 **처음 성립하는 순간의 가중치**가 답. `O(RC log(RC))`.
  - **접근 B (이분 탐색 + BFS/DFS):** 답을 `limit`으로 가정하고 "높이차 ≤ limit인 칸만 통과"해서 도달 가능한지 검사. 가능하면 범위를 줄인다. `O(RC log(maxH))`.
  - **접근 C (변형 다익스트라):** `dist[v] = min(max(dist[u], |높이차|))`로 완화(relax)한다. 더하기가 아니라 **max**를 쓰는 게 포인트.
  - 격자가 1×1이면 답은 `0`.

## 5. Checking Existence of Edge Length Limited Paths 🔴
- **출처:** [LeetCode #1697](https://leetcode.com/problems/checking-existence-of-edge-length-limited-paths/)
- **유형:** **오프라인 쿼리(offline query) + 점진적 union** — 쿼리를 정렬해 간선을 한 번만 훑는다
- **문제:** `n`개 노드와 무방향 간선 `edgeList[i] = [u, v, dis]`가 주어진다(중복 간선 가능). 각 쿼리 `queries[j] = [p, q, limit]`에 대해, **모든 간선의 길이가 `limit`보다 작은** `p`→`q` 경로가 존재하는지 `True`/`False`로 답하라.
- **입력/출력:** `n: int, edgeList: List[List[int]], queries: List[List[int]]` → `List[bool]`
- **제약:** `2 <= n <= 10^5`, `1 <= edgeList.length, queries.length <= 10^5`
- **핵심 힌트:**
  - 쿼리마다 BFS를 돌리면 `O(Q·E)`로 확실히 시간 초과. **쿼리 순서를 바꿔도 된다**는 점이 열쇠다(= 오프라인 처리).
  - **간선을 `dis` 오름차순, 쿼리를 `limit` 오름차순**으로 각각 정렬한다. 쿼리를 작은 limit부터 처리하며 **`dis < limit`인 간선을 포인터로 밀어가며 union**.
  - 이렇게 하면 **간선을 전체에서 딱 한 번만** union한다 → `O(E log E + Q log Q)`.
  - **원래 쿼리 순서로 답을 되돌려야 한다.** 쿼리 인덱스를 함께 정렬(`sorted(range(len(queries)), key=...)`)하고 `res[원래인덱스] = ...`로 채운다. 이걸 놓치면 순서가 뒤섞인 오답.
  - 부등호가 **`<` (strictly less than)** 임에 주의 — `<=`로 쓰면 틀린다.

## 6. Find Critical and Pseudo-Critical Edges in MST 🔴
- **출처:** [LeetCode #1489](https://leetcode.com/problems/find-critical-and-pseudo-critical-edges-in-minimum-spanning-tree/)
- **유형:** **간선 강제 제외/포함으로 MST 재계산** — MST 유일성 개념의 정면 응용
- **문제:** 가중치 있는 무방향 연결 그래프(`n`개 정점, `edges[i] = [a, b, w]`)가 주어진다. **critical edge**는 그 간선을 **빼면 MST 비용이 커지는**(또는 그래프가 끊기는) 간선이고, **pseudo-critical edge**는 **어떤 MST에는 포함될 수 있지만 모든 MST에 포함되지는 않는** 간선이다. 두 목록을 **원래 인덱스**로 반환하라.
- **입력/출력:** `n: int, edges: List[List[int]]` → `List[List[int]]` (`[critical, pseudo_critical]`)
- **제약:** `2 <= n <= 100`, `1 <= edges.length <= min(200, n(n−1)/2)`
- **핵심 힌트:**
  - 먼저 **기준 MST 비용 `base`** 를 크루스칼로 구한다.
  - 각 간선 `i`에 대해 두 번 판정한다:
    - **제외 테스트:** 간선 `i`를 빼고 MST를 다시 구했을 때 비용이 `base`보다 **크거나** 연결이 안 되면 → **critical**.
    - **포함 강제 테스트:** 간선 `i`를 **먼저 union하고 비용에 더한 뒤** 나머지로 크루스칼을 마저 돌린다. 결과가 `base`와 **같으면** → **pseudo-critical**.
  - critical이면 pseudo-critical에 넣지 않는다(**critical 판정이 우선**).
  - 둘 다 아니면 그 간선은 **어떤 MST에도 못 들어간다**(사이클 성질상 항상 최대 간선).
  - **원래 인덱스를 보존**해야 하므로 `(w, a, b, i)` 형태로 묶어 정렬한다. 정렬 후 `i`가 뒤섞이므로 이 필드가 없으면 답을 못 만든다.
  - 복잡도 `O(E² · α(V))`. `E ≤ 200`이라 넉넉히 통과.

### 학습 체크리스트
- [ ] "싼 간선부터, 사이클이면 패스, V−1개" — 크루스칼을 손으로 즉시 쓸 수 있다 (1·2번)
- [ ] 정렬 키를 반드시 **가중치**로 지정한다(`key=lambda e: e[2]`). 안 하면 정점 번호 정렬 오답 (2번)
- [ ] 완전 그래프에서는 간선을 만들지 않고 **프림 `O(V²)`** 를 쓴다 (1번)
- [ ] 간선 `n−1`개 + 연결 = 이미 신장 트리. 끊으면 반드시 컴포넌트 2개 (3번)
- [ ] 0-based / 1-based를 확인하고 `DSU(n)` vs `DSU(n+1)`을 고른다 (2·3번)
- [ ] "경로상 **최대** 간선 최소화"는 크루스칼로 s·t가 처음 연결되는 순간을 잡는다 (4번)
- [ ] 쿼리가 많으면 **오프라인 정렬** 후 간선을 한 번만 훑고, 답은 원래 인덱스로 되돌린다 (5번)
- [ ] 간선 강제 **포함**은 먼저 union+가산, 강제 **제외**는 순회에서 skip (6번)
- [ ] MST 비용은 유일하지만 MST 구성은 유일하지 않을 수 있다 (6번)
- [ ] 연결 불가 판정(`채택 간선 != V−1` 또는 `dsu.count != 1`)을 항상 넣는다 (전 문제)
